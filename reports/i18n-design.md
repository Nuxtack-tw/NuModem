## §1 設計理念

### 1.1 問題規模

盤點結果（`tools/i18n_extract.py`）：

| 來源 | 條數 | 怎麼抽 |
|---|---|---|
| `AT_CMD_TABS`（選單：群組名／說明／按鈕 tip／逾時／確認框／參數標籤／參數說明／下拉選項） | 500 | 瀏覽器走資料結構 |
| `AT_ANNOTATIONS`＋`AT_URCS`＋`AT_RESULT_CODES` 的純字串註解 | 191 | 同上 |
| **30 張對照表的值**（錯誤碼、狀態碼、註冊狀態、功能等級…） | 335 | 同上 |
| 插值型註解的骨架（`` tt`...` `` 的 key） | 123 | 靜態掃描原始碼 |
| **note 函式體內的裸字面值**（`x ? '甲' : '乙'`、`return '丙'`、字串串接） | 75 | 靜態掃描 `L('…')` |
| 程式碼內固定字串（送出／填入命令列／確定要送出嗎？…） | 10 | 手列 |
| **去重後合計** | **1,213** | |

1,213 條 × 17 種目標語言 = **20,621 條翻譯**。原有的 i18n 只涵蓋主 UI 的 99 個鍵，
AT 面板與註解引擎**完全在 i18n 體系之外**。

⚠ **粗體那兩類是第一輪盤點漏掉的** —— 詳見 §4.1。
第一輪只抽了「資料表的 `note` 欄位」與「`tt` 骨架」（998 條），
結果 en-US 出現「`error 563: socket 識別碼已被使用`」這種中英夾雜。
後續又靠洩漏掃描逐步補到 1,213 條，**每一輪都是掃描器找出來的，不是想出來的**。

**驗收結果：17 種語言全部通過洩漏掃描（UI 0 處、註解 0 處）。**

### 1.2 核心取捨：用「繁中原文本身」當 key

正統做法是替每條字串編一個代號（`at.tcpip.qiopen.tip`），但那要**動到 1,414 處資料定義**——
在一個 9,700 行、能正常運作的單檔應用裡，這是不可接受的風險，而且光是替 998 條字串取名
就是一天的工。

改用「原文即 key」之後：

- `AT_CMD_TABS`／`AT_ANNOTATIONS`／錯誤碼表**一個字都不用改**
- 只在**渲染點與 `annotate()` 出口**包一層查表 —— 實際改動 **13 處**
- zh-TW **完全不佔空間**：查不到就回傳原文，所以只需要維護另外 17 種語言
- 代價：原文一改，該條翻譯就變孤兒（自動退回中文顯示，**不會壞掉**）

既有的 `languageManager.t(key)` 本來就是 `translations[lang]?.[key] || key`
（查不到回傳 key 本身），與這個設計天然相容 —— 等於這套 fallback 語意早就存在。

### 1.3 為什麼不內嵌翻譯

998 條 × 17 語言 ≈ **2.7 MB**。主檔目前 544 KB，內嵌會膨脹到 3 MB 以上，
編輯器開起來會卡，而這些內容 **99% 的時候使用者一個字也用不到**（只會用自己那一種語言）。

改成**按需載入**：一種語言一個 `js/i18n/at-<lang>.js`（單檔約 160 KB），
選到哪個才載哪個。用 `<script>` 標籤而非 `fetch()` ——
**直接用 `file://` 開啟時 `fetch` 會被 CORS 擋掉，`<script>` 不會**。

載不到就靜靜退回繁體中文（只複製 HTML、沒帶 `js/` 目錄時就是這個情況），
console 留一則警告，功能完全不受影響。這是刻意的降級設計，不是 bug。

> 專案規則允許此拆分：CLAUDE.md「主程式維持在單一 HTML 檔案」與
> 「JavaScript 模組可拆分至 `js/` 目錄下的獨立檔案」並列，後者正是為這種情況預留的。

## §2 邏輯原理

### 2.1 三個原語

```js
// 整條字串查表 —— tip／label／desc／錯誤碼描述等固定文字
const L = (s) => AT_I18N[atLang()]?.[s] ?? s;

// 帶插值的字串 —— 把插值位置抽掉後的「骨架」當 key
const tt = (strings, ...vals) => {
    const key = strings.reduce((a, s, i) => a + s + (i < vals.length ? '{' + i + '}' : ''), '');
    const pat = AT_I18N[atLang()]?.[key] ?? key;
    return pat.replace(/\{(\d+)\}/g, (m, i) => (vals[i] !== undefined ? vals[i] : m));
};

// 切語言時重跑每個元素的上字閉包（面板不重建 DOM）
const txt = (el, prop, fn) => { const r = () => { el[prop] = fn(); }; r(); atI18nRefreshers.push(r); };
```

**`tt` 的用法就是在原本的反引號前面加兩個字元**，其餘完全不動：

```js
// 改造前
note: m => `連線 ${m[1]} 建立成功 —— 可以開始用 AT+QISENDEX 送資料`
// 改造後（key 自動算出來是「連線 {0} 建立成功 —— 可以開始用 AT+QISENDEX 送資料」）
note: m => tt`連線 ${m[1]} 建立成功 —— 可以開始用 AT+QISENDEX 送資料`
```

⚠ **`tt` 內部用 cooked 而非 `strings.raw`** —— key 必須等於「實際顯示出來的文字」。
用 `.raw` 的話含 `\n` 的字串會把跳脫序列原封不動寫進 key，翻譯檔對不上、也印不出換行。
（這是實作時踩到的第一個坑。）

### 2.2 註解引擎只改 4 個出口就全覆蓋

```
annotate(text, 'sent')     → return L(spec.note)                      ← 指令註解
annotate(text, 'received') → URC：typeof note === 'function' ? note(um) : L(u.note)
                           → resolve()：typeof note === 'function' ? note(m) : L(note)
describeErr()              → tt`${L(label)} ${v}：${L(zh)}`            ← 全部錯誤碼表
```

函式型的 `note` 自己用 `tt` 查表，字串型在這四個出口過 `L()` ——
**191 條純字串註解 ＋ 199 條錯誤碼描述，全部由這四行涵蓋**。

### 2.3 切語言時不重建 DOM

面板是啟動時一次建好的（200 顆按鈕／卡片）。重建 DOM 會弄丟使用者已填的參數值、
展開狀態、群組說明的收合狀態。

改為：建立時每個上字動作都登記一個閉包到 `atI18nRefreshers`，
`languageManager.updateUI()` 末端呼叫 `window.refreshAtI18n()` 全部重跑。
沿用 V26.0.57 群組說明鈕 `_renderDescToggle` 的既有模式，只是集中管理。

下拉選單另外處理：選項清單可能被「活選項機制」（`=?` 回應改寫）換過，
所以記住 `lastOptions` 並在切語言時用最新那份重畫。

### 2.4 按需載入時序

```
頁面載入 → 面板建好（繁中）
        → LanguageManager 建構 → ensureAtI18n(currentLang)
        → 注入 <script src="js/i18n/at-<lang>.js"> （async）
        → onload → refreshAtI18n() → 面板換字
使用者切語言 → setLanguage() → ensureAtI18n()（不 await，主 UI 立刻換）
             → 檔案已載過就直接 refresh；沒載過就等下載完自動補上
```

主 UI 不等 AT 面板 —— **AT 面板慢半拍補上，比整個介面卡住好**。

## §3 操作方式

### 3.1 新增／修改字串之後

翻譯是靠原文比對的，**改了原文就要重新翻譯那一條**。流程：

```bash
# 1. 重新抽出原文目錄（需先在瀏覽器匯出資料型字串，見 3.2）
python tools/i18n_extract.py          # → i18n/sources.json（只產這一個；
                                      #   舊版還會產 to-translate.json，現已不會）

# 2. 翻譯（人工或交給 agent），產出 i18n/raw/<lang>.a.json 與 .b.json

# 3. 合併並產生瀏覽器要載的檔（含品質關卡）
python tools/i18n_merge.py            # → js/i18n/at-<lang>.js
python tools/i18n_merge.py en-US      # 只重做單一語言
```

### 3.1b 改完一定要跑洩漏掃描

靜態盤點只能證明「我抽到的都翻了」，證明不了「沒有漏抽」。§4.1 就是這樣栽的。

1. 瀏覽器開啟 `NuModem_EG800.html`
2. Console 貼上 `tools/i18n_audit_snippet.js` 整份
3. `await auditI18n('en-US')` → 回傳 `{ uiLeaks, anLeaks }`，**兩者都應該是空陣列**

它掃兩件事：畫面上所有葉節點文字與 `title`／`placeholder`／`data-tip`；
以及對一份代表性 AT 回應語料跑 `annotate()` 的輸出。任何殘留中文都會被列出來。

### 3.2 資料型字串怎麼匯出

`AT_CMD_TABS` 等結構在閉包裡，Python 靜態解析不可靠。改由瀏覽器匯出：

1. 用瀏覽器開啟 `NuModem_EG800.html`
2. 開發者工具 console 執行匯出片段（走 `window.__AT_SRC`，該匯出點純唯讀）
3. 存成**專案根目錄**的 `at_i18n_sources.json`（⚠ 不是 `i18n/` 底下 ——
   `i18n_extract.py:154` 讀的是 `ROOT/at_i18n_sources.json`）。
   **一定要聯集併回、不要覆蓋**：那是瀏覽器當下畫面的快照，
   直接覆蓋會把沒開到的頁簽整批弄丟
4. 再跑 `tools/i18n_extract.py` —— 它會把這份與程式碼裡靜態抽出的 `tt` 骨架合併去重

### 3.3 品質關卡（`tools/i18n_merge.py`）

**會擋下該語言、不產生輸出檔**的問題：

- 索引缺漏／多餘（必須剛好是 `0..997`）
- 佔位符 `{0}{1}…` 的個數或編號與原文不符 —— **這會讓執行期印出錯的數值**
- 譯文為空

**只警告**的問題：

- 譯文與原文完全相同（多半是漏譯；自動略過不寫入，反正查不到就回退原文）
- AT 指令名／`<尖括號參數>` 在譯文中消失

## §4 踩過的坑

### 4.1 靜態抽取一定會漏 —— 唯一可靠的判準是「使用者看到什麼」

第一輪抽了 998 條、翻完 17 種語言、看起來完美。切到 en-US 一看：

```
Connection 0 failed to establish — error 563: socket 識別碼已被使用
裝置錯誤 10：SIM not inserted
```

漏掉的是**兩整類**，各有各的理由：

| 漏掉的類別 | 為什麼會漏 | 例子 |
|---|---|---|
| **對照表的值** | 只匯出了 4 張錯誤碼表，實際有 30 張。它們透過 `` tt`…：${TABLE[v]}` `` 被插進句子 | `socket 識別碼已被使用`、`已註冊，本地網路`、`Initial 尚未建立` |
| **note 函式體內的裸字面值** | 既不是資料表欄位（抽不到）、也不在 `` tt` ` `` 骨架裡（`${}` 內／字串串接位置） | `x ? '（緩衝已空）' : ' —— 用 AT+QIRD…'`、`return 'SIM 初始化：尚未開始'` |

兩個對應的修法：

1. **`tt` 對插值本身也過一次 `L()`** —— 一處改動就涵蓋全部 13 個
   `` tt`…${TABLE[v]}` `` 站點。對主機名／數字是安全的：目錄裡只有本專案的原文，不會誤命中
2. **把裸字面值統一包成 `L('…')`** —— 包了才會翻譯，而且包成這個固定形狀之後，
   靜態抽取就能可靠地找到它們（`tools/i18n_extract.py` 的 `l_calls()`）

**教訓寫成工具**：`tools/i18n_audit_snippet.js` 直接掃「切到某語言後畫面上與註解輸出裡
還有沒有中文」。這是唯一能證明覆蓋完整的方法 —— 靜態盤點只能證明「我抽到的都翻了」。

### 4.2 索引式翻譯稿會在目錄擴充時整批錯位

第一批翻譯稿是 `index -> 譯文`，搭配當時那份 998 條的目錄才有意義。
補上漏掉的 194 條之後索引全部位移，沿用舊稿會**無聲錯譯** —— 比缺翻危險得多
（缺翻只是顯示中文，錯譯是顯示不相干的句子）。

已改為**以原文字串為鍵**（`tools/i18n_reindex.py` 負責轉換），順序再怎麼變都不受影響。
`tools/i18n_merge.py` 刻意**不讀**舊的 `i18n/tr-delta/`，就是為了避免誤用索引式殘檔。

### 4.1b 抽取器自己也有兩個盲點（都是掃描器抓出來的）

補完 194 條之後掃描器還是有殘留，追下去發現抽取器本身有 bug：

| 症狀 | 根因 |
|---|---|
| key 變成 `SIM 狀態：{0}\s`，永遠對不上 | `tt` 骨架掃描器的**跳脫處理寫在深度判斷之前** —— 插值裡的正規式 `/\s+/g` 的 `\s` 被當成骨架文字累加進 key |
| `context {0}：{1}；APN「{2}」` 與分隔符 `；` 整個沒被抽出 | 過濾條件是「**含漢字**」，但這兩條**一個漢字都沒有**（全是 ASCII、佔位符、全形標點）。它們卻是道地的中文排版：日文不用「；」、RTL 語言還要改順序 |
| `AT_ANNOTATIONS` 之前的 helper 函式沒被標 `tt` | 機械套用腳本的範圍只設到 `AT_ANNOTATIONS` 起點之後，`atLookup`／`regReadNote`／`csqRssi` 這些先定義的 helper 全在範圍外 |

修法分別是：跳脫處理移進骨架分支並補上字串／正規式跳過；過濾條件改成「含漢字**或**全形標點」；
helper 區段補標。

### 4.1c 日文不能用「有沒有 CJK 字元」判斷洩漏

掃描器一度對 ja-JP 報 425 處 UI ＋ 97 處註解，逐條看全是**正確的日文** ——
`SIM 状態: パスワードの入力待ちなし` 用的是新字體 `状`，不是繁體 `狀`。

`tools/i18n_audit_snippet.js` 因此對 ja-JP 改判：只看**繁體專用字形**
（狀/状、說/説、讀/読、對/対、發/発、點/点、數/数… 這些日文新字體不同形的字）
與**中文才用的標點**（`，` `；` `——`）。改判後 ja-JP 也是 0 處。

### 4.3 其他

- **`tt` 一開始用 `strings.raw`** —— 含 `\n` 的字串會把跳脫序列原封不動寫進 key，
  翻譯對不上、也印不出換行。必須用 cooked
- **機械套用 `tt` 的掃描範圍太寬** —— 第一版涵蓋整個 `SerialMonitor` 類別，
  把產生 HTML 的樣板（`<div class="empty-state">`）也標了進去。
  功能上無害（查不到即原樣輸出）但會污染翻譯目錄、且萬一被翻譯就破壞標記。已撤除
- **Python 腳本把整檔 CRLF 轉成 LF** —— `io.open(..., newline='')` 寫回時，
  搭配讀取端的 universal newlines 就會轉換。功能無害但讓每次 diff 都變成全檔。
  改用 `io.open(..., encoding='utf-8', newline='')` 讀取即可保留

## §5 限制與已知問題

| 項目 | 說明 |
|---|---|
| **原文改動會產生孤兒翻譯** | 該條自動退回繁中顯示，不會壞掉；`i18n_merge.py` 的「與原文相同」警告可以抓出一部分 |
| **只複製 HTML 會失去翻譯** | 沒帶 `js/i18n/` 目錄時全部退回繁中，console 留警告。刻意的降級設計 |
| **RTL 版面尚未處理** | ar-SA／he-IL／fa-IR 的**文字**會翻譯，但整體版面沒有 `dir="rtl"` 支援 —— 這是 fork 時就存在的缺陷，見 `reports/offline-acceptance-checklist.md` §3.5，本次未一併解決 |
| **指令原文與參數值不翻譯** | `AT+QIOPEN=...`、主機名、hex 字串等一律保持原樣 —— 這是刻意的，工程師需要看到會實際送出的位元組 |
| **群組名多為英文** | `Socket`／`Connect`／`Config` 等原本就是英文，多數語言維持不譯 |
| **`{0} {1}：{2}` 這類純結構 key** | `describeErr` 產生，本身沒有可翻譯的詞，但保留它讓 RTL 語言有機會調整標點與順序 |

## §7 `i18n/` 目錄逐檔 reference（2026-09-01 清點）

> 本節是為了回答「i18n 目錄是什麼用途」而補的。
> 動手刪任何東西之前先看 7.3 —— 這個目錄**最像垃圾的那部分其實是來源**。

### 7.1 資料怎麼流


### 7.3 三個容易誤判的地方

**1. `tr*/` 看起來像過程檔，其實是來源。**
`js/i18n/at-*.js` 才是產物 —— `i18n_merge.py` 每次都從 `tr*/` 重新產生它。
刪掉 `tr*/`（7.5 MB）省下的空間，代價是 4.6 MB 的 `.js` 變成**無源孤兒**：
往後原文只要動一個字，那條就再也補不回來。
2026-09-01 發佈前整理時差點犯這個錯，讀了 `i18n_merge.py:2` 的檔頭才發現。

**2. 批次目錄是「疊加」不是「取代」。**
`tr_dirs()` 用 `re.fullmatch(r'tr(\d*)')` 掃描並依數字排序，後批覆蓋前批。
所以 18 個目錄**每一個都在生效**，不是只有最新那批。
新增補譯批只要建 `i18n/tr19/` 就會自動被吃到 —— 刻意不寫死清單，因為寫死會忘記加（踩過）。

**3. `tr-delta/` 被明確拒讀，不是漏掉。**
它是索引式的，而索引對應的原文目錄早就擴充過了。讀進來會**整批位移變成無聲錯譯** ——
比缺翻危險得多（缺翻只是回退顯示繁中）。`i18n_merge.py` 的註解特地寫了這件事。

### 7.4 所以整個目錄能瘦多少

真正的過程檔只有 `tr-delta/`、`delta-list.json`、`_delta.json`、`_need.json`、
`tr7/*.array.json` 與各 `trN-source.json`。
`raw/` ＋ `to-translate.json`（2 MB）是「重建 `tr/` 的能力」，看要不要保。
**剩下的 5.5 MB 是 `tr*/`，一個都不能動。**
