# Wi-Fi Scan 功能解說（EG800K）

> 建立：2026-08-06｜依據：Wi-Fi Scan 應用筆記 v1.1（實際內文 v1.2 參數已依實測校正）＋本機實測（2026-08-02 破案記錄）

## 緣起（user 提問）

> 我現在要來測試Wi-Fi scan，你先跟我解釋這是什麼功能？ —— 2026-08-06

## §1 這是什麼：只掃不連的 Wi-Fi「接收器」

EG800K 是 LTE 模組，**沒有 Wi-Fi 上網能力** —— 但它內建一個 Wi-Fi **掃描**功能：
被動接收周邊 2.4G 熱點（AP）廣播的 beacon 訊框，回報每個熱點的：

- **MAC 位址（BSSID）** —— 熱點的硬體識別碼，全球唯一
- **RSSI**（訊號強度，dBm，越接近 0 越強）
- **頻道**（本機實測都是 2.4G 的 1-13）

**本機韌體不回報 SSID（熱點名稱）**：2026-08-02 實測 ecn/ssid 兩欄固定回 `-`，
只給 MAC／RSSI／頻道。所以掃出來的清單看不到「家裡 Wi-Fi 叫什麼」，只看得到機器識別。

## §2 為什麼 LTE 模組要長這功能：室內定位的拼圖

（用途說明屬應用領域通識）GNSS 在室內收不到訊號 —— 你這幾天已經深刻體會 ——
而 Wi-Fi 熱點的 MAC 位置相對固定。把「掃到哪些 MAC＋各自多強」丟給定位服務資料庫
（Google、Here 這類服務累積了全球熱點位置庫），就能在**完全沒有 GNSS 的室內**估出
數十公尺級的位置。IoT 裝置（資產追蹤器、物流盒子）常用這招補 GNSS 的死角：
室外用衛星、進倉庫換 Wi-Fi 掃描。也可以做粗粒度的「場域感知」——
掃到公司的 AP 就知道裝置回廠了。

掃描是純 RF 接收，**零數據流量**（跟 GNSS 一樣不上網），所以列在離線驗收清單 E4。

## §3 本工具的四顆按鈕（WiFiScan 頁）

| 按鈕 | 指令 | 作用 |
|---|---|---|
| Support? | `AT+QWIFISCAN=?` | 支援範圍。**本機實回 `(4000-255000),(1-3),(4-10),(0-255),(0-1)`** —— round 1-3、maxbssid **4-10**（2026-08-06 實測；先前依應用文件記為 1-6／4-30 是錯的，已更正） |
| Read Cfg | `AT+QWIFISCAN?` | 目前組態（本機出廠 `12000,1,5,5,0`＝時限 12 秒、1 輪、BSSID 上限 5、RRC timeout 5s、優先權 0） |
| Scan | `AT+QWIFISCAN` | 用目前組態掃一次 |
| Scan (custom) | 參數卡片 | 自訂時限／輪數／BSSID 上限／RRC timeout／優先權後掃描 |

## §4 執行流程與判讀（實測行為）

1. 按 `Scan` → 模組先回 `OK`（表示掃描開始，**不是結果**）
2. 幾秒內（最長到掃描時限 12 秒）結果以 **URC 逐條**回報：
   `+QWIFISCAN: (-,-,-35,"C2:28:35:00:00:01",1)` —— 註解會解成
   「熱點 MAC …；RSSI -35 dBm；頻道 1（2.4G）」
3. 時限內沒掃到任何熱點 → `+QWIFISCAN:TIMEOUT`（註解標明「正常結束，不是錯誤」；
   注意這行冒號後沒空白，是文件陷阱之一，解析已處理）
4. 實測參考：2026-08-02 在本機位置掃到 5 個熱點（RSSI -35 ~ -80 多 dBm）

## §5 這功能的血淚史（為什麼現在能動）

**結果是 URC** —— 2026-08-02 之前這功能看起來「壞掉」：指令回 OK 但永遠沒有結果。
真相是模組出廠把 URC 全部送到 USB AT 埠（`urcport=usbat`），走 UART 的本工具一條都收不到，
連 TIMEOUT 都看不見。切到 `uart1`（寫 NVRAM，已完成）後立即正常。
這一案後來還連環破了 GNSS 韌體載入 URC 與 FTP/HTTP/SSL 結果不回報等件 ——
同一個根因。若未來換新模組測試，記得先跑 Hardware 頁 URC 羣的檢查。

## §6 測試建議（對應驗收清單 E4）

- 直接按 `Scan`，等幾秒看 URC 列表；每行應帶 MAC/RSSI/頻道註解
- 想看 TIMEOUT 路徑：把 Scan (custom) 的 BSSID 上限設大、時限設短，或到收不到 Wi-Fi 的地方測
- RSSI 直覺：-30 ~ -50 很近、-60 ~ -75 一般、-80 以下很弱
- 本機出廠 BSSID 上限 5 —— 環境熱點多時只回報最先掃到的 5 個，想看更多用 custom 卡把上限調高（**本機上限 10**）

## §7 掃到的資料要如何定位？（2026-08-06 user 追問）

> wifi scan出來的數據要如何定位？

**關鍵觀念：Wi-Fi 掃描本身不產生座標。** 模組只給「看到哪些 MAC、各自多強」，
要變成經緯度必須把清單送去**熱點位置資料庫**查詢，定位是在雲端算的。

**原理**（應用領域通識）：全球數十億 Wi-Fi 熱點位置多半固定，Google／Apple／Combain
等業者長年蒐集「在某座標收到某 MAC」建成資料庫。送上三個以上 MAC＋RSSI，
伺服器查出各熱點已知位置、以訊號強度加權三邊定位，回傳座標＋精度半徑。
典型精度：市區密集區 **20-50 m**，稀疏處百公尺以上。冷門或新裝熱點不在庫裡則查無。

### 四條路線

| 路線 | 做法 | 本機可行性 |
|---|---|---|
| **1. 模組內建 QuecLocator** | `AT+QLBS` 一條指令：韌體自己掃描＋查庫＋回座標 | ✅ **本機支援**（2026-08-06 實測 `AT+QLBSCFG=?` 回七個子項：asynch／timeout／server／token／timeupdate／withtime／latorder）。**需要 token**（Quectel 申請）＋PDP＋流量 |
| **2. 自己送 HTTP 查詢** | 掃描 → 組 JSON → `AT+QHTTPPOST` 給定位 API → 收座標 | ✅ 本工具 HTTP 頁現成可做。Google Geolocation API（需 key、有免費額度）。**注意 Mozilla MLS 已於 2024 年停止服務，別走那條** |
| **3. 上位機處理** | 模組只掃，MAC 清單交給電腦／伺服器查 | ✅ 最省模組流量，實務最常見 |
| **4. 自建場域小庫** | 自己記錄「哪個 AP 在哪」，掃到查自己的表 | ✅ 零查詢費、不依賴外部，但只在自家場域有效 |

### QLBS 實測發現（2026-08-06 零流量探測）

- `AT+QLBSCFG=?` → 七個子項齊全 ⇒ **QuecLocator 韌體支援**
- `AT+QLBS=?` → 只回 `OK`（無參數清單）；`AT+QLBS?` → `ERROR`（無讀取式）
  ⇒ QLBS 是**執行式**指令，直接觸發定位
- **未做的前置**：`AT+QLBSCFG="token"` 需填 Quectel 核發的 token（本機未設），
  且要 PDP 已啟用、會耗流量 —— 併入連線測試計劃 P7

### 三個現實提醒

1. 本機韌體**不回報 SSID**，只有 MAC —— 對定位剛好夠用（各家 API 用的就是 MAC）
2. 出廠 BSSID 上限 5、**本機上限 10** —— 定位品質吃熱點數量，實測前用 custom 卡調高
3. 所有雲端方案都要**數據流量**，且把周邊熱點 MAC 送給第三方，商用前需考量隱私與服務條款
