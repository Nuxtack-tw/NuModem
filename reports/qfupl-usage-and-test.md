## §1 這是什麼功能

**把電腦上的檔案傳進模組肚子裡的快閃儲存（UFS，User File Storage）。**

EG800K 內建一塊小小的檔案系統。很多功能需要「模組本地有檔案」才能運作，
最重要的就是 **TLS 憑證**：

- `seclevel 1`（驗證伺服器）→ 模組要有受信任的 CA 憑證（`cacert.pem`）
- `seclevel 2`（雙向認證）→ 還要有用戶端憑證＋私鑰（`clientcert.pem`／`clientkey.pem`）
- 這對 **SSL raw socket、MQTT over SSL、HTTPS** 三條路全部適用 —— 它們共用同一套
  SSL context 與 UFS 憑證
- 另外 FTP 也能「先傳進 UFS、再從 UFS 上傳到 FTP 伺服器」（FILE 手冊 §3.6 中轉法）

沒有這顆按鈕之前，憑證只能靠兩段式指令手動走（命令列會被 CR 污染、長度要自己算，
實務上幾乎必失敗）—— 這就是完工盤點裡六份手冊斷在同一點的原因。

**費用：零數據流量。** UFS 是模組內部儲存，上傳走 UART 線，完全不碰行動網路。

## §2 運作原理

```
你按「送出（兩段式）」
  │ 工具先在本機算好：檔案大小（bytes）與 16-bit XOR checksum
  ▼
AT+QFUPL="cacert.pem",1939,10     ← 大小是選檔時自動填的
  │
  ▼ 模組回 CONNECT（表示「開始送資料」）
  │
  ▼ 工具把檔案的「原始位元組」一次送出（不加任何行尾；二進位檔也原樣送）
  │
  ▼ 模組收滿宣告的長度，存檔
+QFUPL: 1939,4f64                 ← 實收大小,checksum
OK
  │
  ▼ 註解引擎自動比對模組回報值與本機預算值：
     ✅ 兩者吻合 = 檔案完整無誤
     ❌ 不符 = 傳壞了，提示 QFDEL 刪掉重傳
```

- **checksum 演算法**：每 2 bytes 一組做 16-bit XOR，奇數長度時最後一位元組補在高位。
  此演算法已用 P5 的實機真值驗證（1,939 bytes 的 ISRG Root X1 → `4f64`，吻合）
- **逾時保護**：模組等資料的上限預設 5 秒（本卡帶 10 秒）。若長度算錯，
  模組逾時後會拿「已收到的部分」存檔並回報 —— 這時大小比對一定不符，看 ❌ 就知道
- **等不到 CONNECT 時 payload 不會送**（實測驗證）—— 不會把檔案內容灑進指令流

## §3 按鈕群一覽（SSL 頁「UFS 檔案」）

| 按鈕 | 用途 |
|---|---|
| **Upload**（選檔卡） | 選檔 → 檔名／大小自動填 → 送出。二進位檔也可以 |
| `AT+QFLST` | 列出 UFS 全部檔案與大小 —— 上傳後的驗證手段 |
| `AT+QFLDS="UFS"` | 查剩餘／總空間 |
| `AT+QFDEL="{file}"` | 刪除指定檔（`*`＝全部）；傳壞時先刪再傳 |

錯誤碼 400–426（FILE 手冊 Table 3，如 405 找不到檔案、403 磁碟已滿、421 逾時）
已併入註解引擎，回報時自動解讀。

## §4 怎麼測試（模組上電後照做即可）

**步驟 0**：跑開機儀式（重載過頁面就要重跑）。**不需要 SIM 上網、不需要天線** —— 全程零流量。

**基本迴圈（5 分鐘）**：

1. SSL 頁 →「UFS 檔案」群 → Upload 卡「選擇檔案」挑 `reports/artifacts/badssl-root.pem`
   （1,939 bytes 的測試憑證，我們知道它的正確 checksum 是 `4f64`）
2. 確認指令列自動變成 `AT+QFUPL="badssl-root.pem",1939,10` → 按「送出（兩段式）」
3. **預期**：終端出現 `CONNECT` → `«二進位內容» ← payload 1939 bytes` →
   `+QFUPL: 1939,4f64` 帶註解「✅ 與本機檔案的大小、checksum 皆吻合」
4. 按 `AT+QFLST` → 預期看到 `+QFLST: "UFS:badssl-root.pem",1939`
5. 按 `AT+QFDEL`（檔名填 badssl-root.pem）→ OK → 再按 `AT+QFLST` 確認消失

**負向測試（驗證保護機制）**：

6. 重傳同一檔but這次**手動把大小欄改大**（例如 3000）再送出 →
   預期模組等 10 秒逾時、回報的大小不是 3000 → 註解顯示 ❌ → QFDEL 清掉
7. 對已存在的檔名再傳一次 → 預期 `+CME ERROR: 407`（檔案已存在，註解會解讀）

**端到端驗收（真正的目的 —— 憑證驗證）**：

8. 上傳 `badssl-root.pem` → `AT+QSSLCFG="cacert",1,"UFS:badssl-root.pem"` →
   `AT+QSSLCFG="seclevel",1,1` → `sni` 開 1 → 開 PDP → `AT+QSSLOPEN` 連 badssl.com:443
   —— 好憑證連得上、壞站（expired.badssl.com）連不上，兩個方向都成立才算數
   （完整成對測試法見 `p5-ssl-test-results.md`）。⚠ 這一步要流量。

| 層 | 狀態 |
|---|---|

| checksum 演算法 | ✅ 與 P5 實機真值吻合（`4f64`） |
| 註解比對 ✅／❌ 兩路、QFLST/QFLDS 解讀、錯誤 407 解讀 | ✅ 實測（合成回應） |
| 兩段式接線（等 CONNECT、逾時不誤送 payload） | ✅ 實測（模組斷電下的逾時路徑） |
| **實機上傳 → QFLST 驗證 → QFDEL** | ✅ **2026-08-31 模組接回後全數通過**（見下） |

### 實機測試結果（2026-08-31，模組接回後；SIM 未插 —— UFS 測試本來就不需要）

| 步驟 | 結果 |
|---|---|
| 上傳 badssl-root.pem | ✅ `CONNECT` → 1,939 bytes → **`+QFUPL: 1939,4f64`，與本機預算值分毫不差** |
| `AT+QFLST` 驗證 | ✅ `+QFLST: "UFS:badssl-root.pem",1939` |
| `AT+QFLDS="UFS"` | ✅ `180224,286720` —— **實機 UFS 總容量 280 KB**（規劃憑證空間時參考） |
| 負向：同名重傳 | ✅ 擋下 —— 回 `+CME ERROR: file already exist`（**注意是文字不是 407**，見下） |
| 負向：大小謊報 3000 | ✅ 模組收滿 1,939 後等到 10 秒逾時 → 回報實收 `+QFUPL: 1939,4f64` ＋ `+CME ERROR: 421`（逾時，數字碼，註解自動解讀）。**檔案有存**（手冊的部分存檔行為證實） |
| `AT+QFDEL` 清場 | ✅ 刪除成功、QFLST 轉空、空間回收 |

**實測到的三個手冊沒明說的行為：**

1. **FILE 錯誤碼的回報形式不一致**：同在 CMEE=2 下，「檔案已存在」回**文字**
   `file already exist`、「逾時」回**數字** `421` —— 寫解析邏輯不能假設固定一種形式
   （本工具兩種都能解：數字查表、文字本身可讀）
2. **大小謊報比實際大時，逾時後模組照樣存檔**（存的是實收內容）—— 這次實收剛好完整
   所以 checksum 吻合；若是真的傳一半斷掉，checksum 比對就會抓到 ❌
3. **每個檔案佔一個 4 KB 區塊**（刪 1,939 bytes 的檔，剩餘空間 +4,096）

| UI 按鈕上傳憑證 | ✅ 再次 `+QFUPL: 1939,4f64` |
| `cacert` → `UFS:badssl-root.pem`、`seclevel 1`、`sni 1` | ✅ |

| **正向：`badssl.com:443`** | ✅ **`+QSSLOPEN: 4,0` 連線成功** —— 伺服器憑證鏈以上傳的根憑證驗證通過，`QSSLSTATE` 確認連線建立 |
| **負向：`wrong.host.badssl.com:443`** | ✅ **`+QSSLOPEN: 4,566` 正確拒絕**（主機名不符） |

⚠ 負向測試用 `wrong.host` 而非 `expired`：`ignorelocaltime` 出廠是 1（不檢查有效期），
過期憑證不會被擋 —— 這是 P5 就記錄過的行為，選測項時要避開。

**成對測試兩個方向都成立 —— 「上傳憑證 → 伺服器驗證」整條路從 UI 一鍵走通。**
測後狀態：`badssl-root.pem` 留在 UFS（下次測試直接可用）；
`seclevel`／`cacert`／`sni` 不跨重開機保存（P5 記錄），下次開機自動回出廠值。
