FTP — передача файлов

Принцип работы: у FTP два канала: управляющий — для команд, канал данных — для содержимого файлов. Вход, переименование, удаление, запрос размера идут только по управляющему каналу; LIST, загрузка и скачивание открывают отдельное соединение данных — отсюда большая часть странностей этого раздела (очереди из 615 и 603). Сквозное правило Quectel на весь раздел: OK означает лишь «команда принята», настоящий результат приходит позже в URC. Все ответы и числа в этом разделе — замеры на физическом EG800K в августе 2026 года.

Прежде чем начать: два условия

  • PDP должен быть активирован: первая кнопка страницы AT+QIACT? как раз это и проверяет — продолжать можно, лишь если возвращается +QIACT: 1,1,…,"IP"; если только OK — сначала на страницу TCP/IP и Act PDP (без активированного PDP QFTPOPEN обязательно провалится).
  • URC должны идти по UART: почти все FTP-команды работают по схеме «сначала OK, результат позже в URC»; если AT+QURCCFG="urcport" не "uart1", здесь вы увидите лишь кучу OK (настройка — на странице Hardware).

Маршрут входа: настройка → открытие → ожидание URC

  1. Привязать PDP context: AT+QFTPCFG="contextid",1 (с завода уже 1; кнопка запроса позволяет прочитать и убедиться).
  2. Задать логин и пароль: AT+QFTPCFG="account","логин","пароль" — обязательно до QFTPOPEN.
  3. Режим и тип: transmode в 1 (пассивный; за NAT — всегда он, для FTPS обязателен); filetype: для чисто текстовых файлов 1, для остальных 0.
  4. Вход: AT+QFTPOPEN="хост",21 немедленно возвращает OK (лишь принято); вход удался, только когда пришёл +QFTPOPEN: 0,0 (до 125 секунд). Затем AT+QFTPSTAT должен вернуть 1 (простой; 2 = идёт передача, 3 = закрывается).
AT+QFTPCFG="account","demo","password"
AT+QFTPCFG="transmode",1
AT+QFTPOPEN="test.rebex.net",21
OK                ← означает лишь, что команда принята
+QFTPOPEN: 0,0    ← вот эта строка — успешный вход

Остальные пункты настройки: AT+QFTPCFG=? одним нажатием перечисляет все 10 настраиваемых пунктов с диапазонами (без единого байта трафика). rsptimeout (20–180, по умолчанию 90 секунд) — максимальное время ответа большинства команд и максимальный промежуток между двумя пакетами в режиме данных; ssltype / sslctxid — для FTPS (для чистого FTP держите 0; параметры SSL задаются на странице SSL); data_address / cache / restenable — тонкая подстройка для особых окружений, назначение — в подсказках кнопок и руководстве.

Маскирование пароля (замер, расходится с руководством): при запросе AT+QFTPCFG="account" пароль в ответе замаскирован в * (руководство говорит — печатается как есть). Но логин остаётся открытым текстом, и в строке записи пароль тоже открытый — на скриншотах и записях экрана опасаться нужно именно строки записи.
🔴 AT+QFTPCLOSE асинхронна — OK не значит, что закрылось. Выход завершён, лишь когда пришёл +QFTPCLOSE: 0,0; всё это время AT+QFTPSTAT возвращает 3 (закрывается), и любая FTP-команда неизменно отвечает +CME ERROR: 603 (сервер занят).

Симптом крайне обманчив: очередь из 603 выглядит как сломанный модуль или бан от сервера, а на деле закрытие просто не докончено (в день замера на этом потеряли большой круг). Предел ожидания = rsptimeout. И ещё: она лишь выходит из FTP; для полного сброса сети — Deact PDP на странице TCP/IP.

Каталоги и файлы: сервер как файловый менеджер

Полный набор операций с файлами на сервере (LIST / NLST / MLSD открывают соединение данных, остальные идут только по управляющему каналу). Успешный ответ всегда +QFTPXXX: 0,… — первое число 0 и есть успех:

Приём (вся цепочка прошла замер): используйте SIZE как проверку существования — после переименования запрос старого имени возвращает +QFTPSIZE: 627,550, нового — 0,20; после удаления запрос снова даёт 627,550 — каждый шаг проверен без скачивания и байта. 627,550 — двухслойный код ошибки: 627 = уровень модуля «FTP не выполнил запрошенное действие», 550 = уровень протокола FTP, ответ сервера «файл или каталог не существует»; пояснения инструмента переводят послойно.

Скачивание: содержимое печатается прямо в терминал (COM:)

AT+QFTPGET="имяфайла","COM:" — после CONNECT содержимое файла вываливается прямо в терминал, в конце +QFTPGET: 0,<байты> (замер readme.txt вернул 0,379). Вторая кнопка — скачивание кусками — несёт ещё параметры начала и длины и является самым рекомендуемым способом: сначала узнайте размер через SIZE, потом берите кусками — не взрывайте трафик целым файлом. AT+QFTPLEN показывает, сколько байт реально передал последний PUT / GET / LIST / NLST.

Загрузка: двухэтапная, набралась объявленная длина — завершилась сама

AT+QFTPPUT="имяфайла","COM:",0,<длина>,1 — двухэтапная команда: после CONNECT (вход в режим данных) отправьте ровно объявленное число байт; модуль, досчитав, сам выходит из режима данных — Ctrl+Z не нужен. Инструмент считает длину сам: достаточно вставить содержимое в карточку параметров.

AT+QFTPPUT="numodem-test.txt","COM:",0,20,1
CONNECT                        ← вход в режим данных
NuModem-P6-FTP-test\n          ← отправлено ровно 20 bytes
OK
+QFTPPUT: 0,20                 ← сервер получил 20 bytes

Эти 20 bytes при замере нарочно забрали с хоста питоновским ftplib и сравнили побайтно — совпадение полное. Вариант через UFS: руководство поддерживает и имя вида "UFS:xxx" — перевалку через встроенное хранилище модуля; детали в записке по FTPS. Сначала файл с компьютера кладётся в UFS кнопкой Upload группы «Файлы UFS» на странице SSL (AT+QFUPL — идёт по UART без единого байта трафика, checksum сверяется автоматически).

⚠ Для FTP +++ — это «прервать», а не «приостановить». Руководство (FTPS AN v1.5 p13) пишет, что после побега можно вернуться в режим данных через ATO и продолжить передачу — замер это опровергает (два прогона, результат одинаковый): после побега AT+QFTPSTAT возвращает 1 (простой), а не 2 (идёт передача), ATO отвечает NO CARRIER — передача прервана целиком, восстанавливать нечего. Поэтому +++ годится лишь для побега из вышедшего из-под контроля режима данных, но не для паузы в скачивании большого файла.

Правильная отправка: по 1 секунде тишины до и после, сырыми байтами, без CR (с CR не срабатывает) — кнопка +++ этой страницы уже так и шлёт; кнопка ATO оставлена в значении из руководства.
