Network — Registrasi, Operator, RF

Cara kerja: semua fungsi data hanya bisa dipakai dengan prasyarat sudah teregistrasi ke jaringan seluler dan kanal data PDP sudah siap — halaman ini adalah dasbor sekaligus sakelar masuk jaringan; semua penelusuran "tidak bisa online" dimulai dari sini. Angka pada bagian ini semuanya hasil uji nyata EG800K fisik pada Agustus 2026.

Sebelum mulai: alihkan dulu URC ke UART

Dari pabrik, EG800K mengirim pesan laporan proaktif (URC) ke usbat (port AT USB), sedangkan alat ini berjalan lewat UART — tak satu pun URC akan diterima: laporan sinyal, hasil TCP / MQTT / pemindaian Wi-Fi semuanya senyap, dengan gejala "semua perintah membalas OK, tetapi pesan tak pernah datang".

Penyebab nomor satu "semua URC lenyap" adalah ini. Buka tab Hardware, tekan AT+QURCCFG="urcport" untuk memeriksa; bila bukan "uart1", ubah dengan tombol pengalihnya — setelan ditulis ke NVRAM, sekali diubah bertahan melintasi boot ulang.

Langkah pertama: pastikan status registrasi

Setelah ritual boot menampilkan RDY, tekan dulu AT+CEREG? (untuk modul 4G, perintah inilah yang paling akurat). Tiga tombol registrasi mewakili tiga domain jaringan: CEREG = LTE/EPS, CREG = domain circuit-switched, CGREG = domain packet-switched; angka kedua (stat) dibaca dengan cara yang sama:

statArtiYang harus dilakukan
0Belum teregistrasiLazim tepat setelah boot; tunggu beberapa detik lalu cek lagi
1Teregistrasi (jaringan sendiri)Normal, lanjutkan
2Sedang mencariTunggu
3Ditolak jaringanPeriksa SIM / paket; lihat penyebabnya dengan CEER
5Teregistrasi (roaming)Kondisi normal perangkat ini, lihat di bawah
stat=5 bukan kerusakan. Hasil uji: ketiga query registrasi membalas 0,5: SIM-nya kartu IoT 1NCE (kartu roaming internasional MCC 901), di negara mana pun terhitung "roaming" — anggap 5 sebagai 1.

Bila registrasi berhasil tetapi tetap tak bisa online, lanjutkan menekan AT+CGATT? untuk memeriksa attach domain paket; bila perlu tekan AT+CGATT=1 untuk attach manual; bila gagal, gunakan AT+CEER untuk melihat penyebabnya (lapisannya berbeda dengan QIGETERROR di halaman TCP/IP). CGATT bisa memblokir maksimum 140 detik; jangan ditekan bertubi-tubi.

Sekarang menggantung di operator mana, band berapa

AT+COPS? menanyakan operator tempat login saat ini (digit terakhir 7 = LTE). Jebakan: nama operator bisa berupa string kosong — hasil uji membalas +COPS: 0,0,"",7, itu bukan kerusakan. Untuk melihat operator, tekan saja AT+QNWINFO (teknologi / operator / band / kanal):

+QNWINFO: "FDD LTE","46692","LTE BAND 8",3750

46692 = Chunghwa Telecom, Band 8; tanpa layanan, balasannya NO SERVICE. Kartu roaming ini memilih jaringan sendiri: pada tanggal berbeda pengujian pernah menggantung di Chunghwa Telecom Band 8 dan FarEasTone (466-01) Band 3; ganti operator maupun ganti band semuanya normal. AT+COPS=? memindai semua operator di sekitar: memblokir maksimum 300 detik dan memutus layanan yang sedang berjalan; tekan hanya bila benar-benar perlu.

Kekuatan dan kualitas sinyal: CSQ hanyalah nilai kasar

AT+CSQ membalas rssi dan ber: rssi 0–31 memetakan -113 hingga -51 dBm, 99 = tak terdeteksi (lazim tepat setelah boot, tunggu beberapa detik). Hasil uji rssi 18–24 (-77 hingga -65 dBm, baik); ber selalu 99, tak punya nilai rujukan. Tiga elemen kualitas LTE yang sesungguhnya RSRP (kekuatan) / RSRQ (kualitas) / SINR (rasio sinyal-derau; rendah = terganggu interferensi) hanya bisa didapat dari kelompok Signal URC (AT+QINDCFG="sqi" tanpa nilai = memeriksa sakelarnya):

TombolPerintahFungsi
LTE QualityAT+QINDCFG="sqi",1 Menyalakan laporan RSRP / RSRQ / SINR — wajib untuk uji antena dan penempatan. Hanya di-push saat sinyal "berubah"; bila tak ada gerakan, bungkus atau cabut-pasang antenanya; setelan tak bertahan melintasi boot ulang
Signal PushAT+QINDCFG="csq",1 Melapor begitu sinyal berubah, menggantikan menekan CSQ bertubi-tubi

Kanal PDP: lapisan 3GPP vs halaman TCP/IP

PDP context = "kanal data" yang dijatahkan jaringan seluler; hanya dengan itu ada IP. Kelompok ini adalah query baca-saja lapisan standar 3GPP: AT+CGDCONT? menampilkan context dan APN, AT+CGACT? menampilkan status aktivasi (memblokir maksimum 150 detik; ⚠ urutan parameter bentuk tulisnya terbalik), AT+CGPADDR menampilkan IP yang didapat. QIACT? / QICSGP di halaman TCP/IP adalah stack milik Quectel sendiri, bukan lapisan yang sama — membandingkan keduanya berdampingan bisa membedakan sisi mana yang rusak: di sini ada IP, di sana tidak = jaringan sudah memberi tetapi stack belum menyala. Perangkat ini otomatis mengaktifkan PDP dan mendapat IP begitu boot.

AT+QGDCNT? menanyakan kuota kumulatif (angka pertama terkirim, angka kedua diterima), wajib dipakai saat menguji kuota dengan kartu roaming. ⚠ Pengujian membantah petunjuk tombol "akumulasi melintasi boot": penghitung secara default tidak disimpan ke NV; begitu daya putus (termasuk memuat ulang halaman) langsung nol — catat di tempat, atau simpan ke NV dengan AT+QGDCNT=1.

Praktik penelusuran: kartu ini hanya mengizinkan satu PDP

Di halaman TCP/IP menekan AT+QIACT=1 malah dibalas ERROR (572,operation not allowed)? Skenario tetap kartu ini: setelah boot, lapisan 3GPP sudah otomatis mengaktifkan satu PDP, tetapi nomor context-nya mengambang (pengujian pernah melihat 1 dan 9); membuka yang kedua dibalas +CME ERROR: 100 ⇒ jaringan hanya mengizinkan satu PDP; sedangkan rentang contextID QIACT hanya 1–8 — bila PDP dibuka di 9, stack Quectel sama sekali tak bisa menyentuhnya. Solusinya dua langkah (lakukan sekali setiap habis boot):

AT+CGACT?             ← Lihat cid yang mana (nomornya mengambang, langkah ini tak boleh dilewati)
AT+CGACT=0,<cid itu>   ← Lapisan 3GPP melepaskan jatahnya
AT+QIACT=1            ← Halaman TCP/IP; balasan +QIACT: 1,1,1,"10.187.7.8" berarti berhasil

Menyetel APN lewat QICSGP bisa dilewati untuk kartu ini — hasil uji: modul otomatis menyinkronkan APN yang dijatahkan jaringan (iot.1nce.net); baru wajib bila berganti ke kartu APN korporat yang butuh akun-sandi.

Di tengah pengujian tiba-tiba semuanya timeout? Curigai dulu PDP hanyut. Hasil uji: saat HTTP gagal total beruntun (error 716, timeout tetap 30 detik), AT+QIACT? tetap saja membalas IP — pada saat itu ia menipu; silangkan dengan AT+CGACT? (hasil uji: 1,0 dan 9,1 = hanyut ke 9). Solusi: AT+QIDEACT=1 → AT+CGACT=0,<cid tempat hanyut> → AT+QIACT=1, lalu verifikasi dengan ping.

Tingkat fungsi CFUN dan kendali RF

Seluruh kelompok RF Control mengubah status modul; semuanya tombol berbingkai merah yang meminta konfirmasi sebelum jalan. Tekan dulu AT+CFUN? untuk melihat tingkat saat ini sebelum bertindak:

PerintahTingkatArti
AT+CFUN=1Fungsi penuh RF menyala penuh; untuk memulihkan, selalu tekan yang ini
AT+CFUN=4Mode pesawat Kirim-terima mati semua, SIM tetap ada — titik awal untuk menguji "masuk jaringan ulang"
AT+CFUN=0Minimum SIM ikut dinonaktifkan; manual hanya menulis Minimum functionality tanpa perincian
AT+CFUN=1,1Restart lunak Menyalakan ulang seluruh modul. ⚠ Port AT mati sesaat; tunggu lagi RDY

CFUN memblokir maksimum 15 detik. Bila SIM terkunci PIN, setelah kembali ke CFUN=1 PIN harus dimasukkan lagi barulah teregistrasi. AT+CGATT=0 (PS Detach) melepaskan diri dari domain paket — merobohkan semua koneksi TCP / MQTT; pakai hanya untuk menguji "attach ulang".

Lanjutan: QENG membaca info BTS (diketik di baris perintah)

Halaman ini tidak punya tombolnya — ketik AT+QENG="servingcell" di baris perintah untuk membaca parameter BTS yang melayani; kolom kunci hasil uji:

KolomNilai hasil ujiCara membaca
MCC / MNC466 / 01Taiwan / FarEasTone
Cell ID / TACABCDE02 / 1234 (hex) Desimal 180149762 / 4660; eNodeB = ECI≫8 = 703710, sektor = 2
PCID / EARFCN144 / 1550 Identitas sel fisik (tidak unik global) / Band 3
RSRP / RSRQ / RSSI / SINR-113 / -18 / -92 / -1 RSRP di bawah -100 terhitung buruk; SINR -1 dB = kualitas jelek
Cell ID dan TAC berbasis heksadesimal; sebelum mencari di basis data, wajib dikonversi ke desimal. Basis data seperti OpenCelliD semuanya menerima desimal; melempar langsung ABCDE02 hanya berbuah "tidak ditemukan". Selain itu AT+QENG="neighbourcell" hanya membalas PCID, tanpa Cell ID global (batasan standar LTE).
