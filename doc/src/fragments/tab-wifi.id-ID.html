WiFiScan — Pemindaian Wi-Fi dan Penentuan Posisi Jaringan

Cara kerja: EG800K adalah modul LTE, tanpa kemampuan internet Wi-Fi, tetapi punya penerima Wi-Fi bawaan yang "hanya memindai tanpa menyambung": secara pasif menerima frame beacon yang disiarkan hotspot 2.4GHz di sekitar, lalu melaporkan alamat MAC (BSSID), RSSI (kekuatan sinyal), dan kanal setiap hotspot. Pemindaian adalah penerimaan RF murni, nol kuota data; ia sendiri tidak menghasilkan koordinat — daftar MAC + RSSI harus dikirim ke basis data posisi hotspot di cloud untuk ditukar menjadi lintang-bujur; inilah penentuan posisi jaringan yang bisa dipakai di dalam ruangan, tanpa bergantung satelit. Semua angka dan perilaku pada bagian ini adalah nilai hasil uji nyata terhadap EG800K fisik pada Agustus 2026.

Paruh atas Wi-Fi Scan empat tombol (pemindaian murni), paruh bawah QuecLocator (QLBS) tiga belas tombol (baca dulu paragraf kebenaran di belakang sebelum menekan):

Pemindaian pertama: cara menekannya, apa yang akan terlihat

  1. Jalankan ritual boot (lihat bagian "Ritual Boot").
  2. Pastikan URC lewat UART: AT+QURCCFG="urcport" harus membalas "uart1". Nilai pabriknya "usbat" — seluruh hasil pemindaian dikirim ke port USB; di sini hanya terlihat OK, bahkan TIMEOUT pun tak kunjung datang (setelan ditulis ke NVRAM, cukup diubah sekali).
  3. Tekan Scan: modul membalas OK dulu, yang berarti "pemindaian dimulai", bukan hasil. Dalam beberapa detik (paling lama sampai batas waktu pemindaian) hasil dilaporkan baris demi baris, tiap baris beranotasi otomatis (MAC / RSSI / kanal).

Membaca hasil pemindaian

Laporan hasil uji tampak seperti ini (2026-08-29, terpindai 7 hotspot, RSSI -37 ~ -89 dBm):

+QWIFISCAN: (-,-,-37,"C2:28:35:00:00:01",1)
+QWIFISCAN: (-,-,-46,"10:71:B3:00:00:02",4)
+QWIFISCAN: (-,-,-88,"A8:A2:37:00:00:03",6)

Urutan kolomnya (ecn, ssid, rssi, mac, channel). Firmware perangkat ini selalu membalas - untuk ecn dan ssid (hasil uji 2026-08-02), sehingga dari daftar tak terlihat "ini Wi-Fi milik siapa" — untuk penentuan posisi justru pas: yang dimakan basis data memang MAC + RSSI. Intuisi RSSI: -30 ~ -50 sangat dekat, -60 ~ -75 biasa, di bawah -80 sangat lemah.

Bila dalam batas waktu tak satu pun hotspot terpindai, balasannya +QWIFISCAN:TIMEOUT — penyelesaian normal, bukan error (tanpa spasi setelah titik dua; parser alat ini sudah menanganinya). Ingin memindai lebih banyak: lewat kartu parameter naikkan hotspot maksimum dari nilai pabrik 5 (batas perangkat ini 10), dan setel putaran ke 2-3 (hasil uji: hasil lintas putaran dideduplikasi).

Tidak semua hotspot terpindai bisa dipakai untuk penentuan posisi. Hasil uji 2026-08-29: dari 7 hotspot, 4 di antaranya "alamat kelola lokal" (berawalan C2: / 62: / 9E:, bit 0x02 pada byte pertama bernilai 1 — BSSID virtual dari kloning multi-SSID); basis data penentuan posisi biasanya langsung mengabaikan alamat semacam ini, sehingga bahan yang benar-benar terpakai tinggal 3 alamat global.
Rentang parameter di dokumen aplikasi V1.2 salah untuk perangkat ini. Dokumen melonggarkan putaran ke 1-6 dan hotspot maksimum ke 4-30, tetapi rentang yang nyatanya dibalas firmware perangkat ini tetap putaran 1-3, hotspot maksimum 4-10 (hasil uji 2026-08-06). Jadikan balasan nyata Support? patokan; jangan menyalin angka dokumen.

Kelompok tombol QuecLocator (QLBS): lihat dulu kebenarannya sebelum menekan

QuecLocator adalah layanan penentuan posisi cloud milik Quectel: AT+QLBS (tombol Locate) satu perintah — firmware sendiri mengumpulkan bahan, mengirimnya ke server untuk dicari di basis data, lalu mengembalikan koordinat. Tiga kenyataan:

  1. Butuh token, dan ini layanan berbayar. Dokumen resmi menulis tegas harus menghubungi dukungan teknis Quectel untuk mengajukan (tanpa registrasi mandiri). Token perangkat ini kosong dari pabrik.
  2. Dari 16 dokumen resmi EG800K, tak satu pun menyebut QuecLocator. Dokumen aplikasi yang ada di tangan diperuntukkan EC200U / EG915U (sintaks dan kode error terbukti cocok lewat pengujian), bukan dokumen resmi perangkat ini.
  3. Proyek ini sudah memutuskan tidak memakainya (2026-08-29): logika penentuan posisi terkunci di dalam firmware; begitu layanannya tutup, seluruh perintah AT-nya langsung mati dan vendornya tak bisa ditukar (forum Quectel sudah mengonfirmasi seri BG95 berhenti didukung). Tombolnya dipertahankan hanya untuk "verifikasi sambil lalu bila mendapat token gratis".
+QLBS: 702 adalah "server timeout", bukan masalah token. Proyek ini pernah salah memvonis 702 sebagai "tak punya token" selama tiga minggu penuh — kebenarannya: saat itu lupa mengaktifkan PDP dulu, modul sama sekali tak bisa mencapai server, dan setelah timeout penuh (pabrik 60 detik) membalas 702. Eksperimen pembanding 2026-08-29 (token kosong sepanjang proses): PDP belum aktif membalas 702; setelah aktif membalas 10002 (token tidak ada) — server bisa dicapai dari Taiwan; yang kurang hanyalah token. Sebelum mengirim AT+QLBS, wajib AT+QIACT=1 dulu (memakan kuota).

Ketujuh subitem setelan punya tombol query / setel masing-masing; Cfg? (AT+QLBSCFG=?) sekali klik menampilkan semua rentangnya (nol kuota). Nilai pabrik perangkat ini dan poin hasil uji:

Bila benar-benar mendapat token: isikan lewat Set Token → konfirmasi dengan Token? (tampil *) → aktifkan PDP di halaman TCP/IP → Locate.

Jalur alternatif: penentuan posisi jaringan tanpa token (hasil uji 71 meter)

Penentuan posisi jaringan tak harus lewat QuecLocator. Jalur alternatif sudah tembus ujung-ke-ujung pada 2026-08-29: modul hanya mengeluarkan bahan (halaman ini memindai hotspot, AT+QENG="servingcell" membaca BTS), keluaran terminal disimpan lalu diserahkan ke tools/wifi_geolocate.py yang mencari basis data publik di sisi PC — modul nol kuota, bebas layanan Quectel. Hasil uji (dibandingkan nilai sejati GNSS hari yang sama): pencarian tabel BTS dengan Unwired Labs (registrasi gratis) galat 71 meter (kesimpulan penutup jalur penentuan posisi ini), dengan beaconDB (bebas kunci) 632 meter; pencarian tabel Wi-Fi tersangkut di vendor — ekosistem gratisnya sudah runtuh (beaconDB tak mencakup wilayah ini, paket gratis Unwired Labs tak menyertakan Wi-Fi, Google / HERE mewajibkan kartu kredit), ditangguhkan.

71 meter adalah "ketepatan pencarian tabel", bukan "presisi pengukuran". Penentuan posisi BTS memakai Cell ID untuk mencari koordinat terdaftar BTS itu; cell yang sama selamanya mengembalikan titik yang sama — berganti BTS, galatnya bisa berskala kilometer; ±1051 meter yang dilaporkan layanannya sendiri itulah estimasi yang jujur. Selain itu Cell ID dan TAC berbasis heksadesimal; sebelum mencari tabel wajib dikonversi ke desimal (perkakasnya sudah menangani ini).
