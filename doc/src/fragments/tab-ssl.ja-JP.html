SSL —— TLS チャネル

動作原理：SSL ページは暗号化接続の共用の底層です —— ここで設定した SSL context とアップロードした証明書は、SSL raw socket、MQTT over SSL、 HTTPS の三者から共用されます。本節の秒数と挙動はすべて 2026 年 8 月に実機 EG800K で実測した値です。

初めての TLS 接続：5 つのステップ

  1. 起動シーケンスを実行し（〈起動シーケンス〉の節を参照）、続けて AT+QIACT? でデータチャネルを確認します —— +QIACT: 1,1,…,"IP" が返ること。返らなければ先に AT+QIACT=1。
  2. context を設定する：sslversion は 4（全バージョン、 互換性最良）、ciphersuite は 0XFFFF（全スイート）、 seclevel はまず 0 —— まずチャネルが通ることを確認し、検証は後に回します。
  3. 接続を開く：AT+QSSLOPEN（末尾コード 0）を押し、パラメータカードに ホストとポートを記入します。⚠ OK は「コマンドを受け付けた」の意味でしかなく、成否は URC を待ちます： +QSSLOPEN: 4,0 ではじめて成功です（実測ハンドシェイク 2.0 秒）。
  4. データを送る：AT+QSSLSEND（2 段階）を押します —— > が出たら本文を送り、宣言した長さを数え切ると自動送出、 Ctrl+Z 不要（1 パケット上限 1460 bytes）。相手の返答は +QSSLURC: "recv",4 で現れます。
  5. 読み出しとクローズ：AT+QSSLRECV（1 回の上限 1500）で +QSSLRECV: 0 まで読めば読み切った印で、エラーではありません。 AT+QSSLCLOSE=4 でクローズ（既定は最長 10 秒待ち。 もう 1 つのボタンでは秒数を指定でき、0＝即時）。
AT+QSSLOPEN=1,1,4,"tcpbin.com",4243,0
OK
+QSSLOPEN: 4,0            ← 2.0 秒、0＝成功
AT+QSSLSEND=4,15
>
NuModem-P5-SSL            ← 15 bytes を数え切ると自動送出
SEND OK
+QSSLURC: "recv",4        ← 0.4 秒
AT+QSSLRECV=4,1500
+QSSLRECV: 15
NuModem-P5-SSL
AT+QSSLCLOSE=4

接続中は AT+QSSLSTATE ですべての接続を見られます（=4 で単一 clientID を照会、状態 2＝接続済み）。ローカルポートは常に 0 が返る点に注意 —— モジュールの挙動であり、エラーではありません。

3 つのアクセスモード（AT+QSSLOPEN の末尾コード）

末尾コード挙動
0 バッファデータ受信時は +QSSLURC: "recv",<id> を出すだけで、 自分で AT+QSSLRECV を打って読みます
1 直接プッシュURC に長さが付き、データは次の行に直接吐かれます。 ⚠ このモードで AT+QSSLRECV が ERROR を返すのは正常です
2 透過転送AT ポート全体がデータチャネルになります（本ページのボタンは 0 と 1 のみ用意）

context 設定を 1 つずつ

ファームウェアがどのサブ項目に対応しているか不確かなら、まず AT+QSSLCFG=? を押します —— 実測では 17 のサブ項目が返り、アプリケーションノートの一覧より多いのです。よく使うサブ項目には設定と照会の 2 ボタンがあり、 実測では書き込み後の読み出しは完全に一致しました。

サブ項目出荷値働きと実測の要点
sslversion—プロトコルバージョン。4＝全対応
ciphersuite—暗号スイート。0XFFFF＝全対応
seclevel00＝検証しない、1＝サーバーを検証 （先に CA 証明書のアップロードが必要）、2＝相互認証（さらにクライアント証明書＋秘密鍵が必要）
cacert—CA 証明書のパス。形式は "UFS:ファイル名" で、ファイルが UFS にあることが前提（次節参照）
sni🔴 0 バーチャルホスト／CDN への接続では必須 —— 同一 IP に複数ドメインが載っていると、SNI を送らない限り 一致しない証明書が返り、検証は必ず 566 で失敗します
ignorelocaltime🔴 1 出荷状態では seclevel 1 を有効にしても証明書の有効期限をチェックしません。 チェックするなら 0 に設定し、モジュールの時計も合っている必要があります
negotiatetime300 TLS ハンドシェイクの最長待ち秒数（10–300）
🔴 3 つの出荷時既定値を合わせると＝証明書を全く検証しない （seclevel 0、sni 0、ignorelocaltime 1）。本当に検証するなら 3 つとも正しく設定する必要があります。 しかもこの 3 設定と cacert は再起動をまたいで保存されません （実測で確認）。起動のたびに出荷値へ戻ります。UFS 内の証明書ファイルは電源断でも消えません。

UFS ファイル群：証明書はどうやってモジュールに入るか

UFS はモジュール内蔵のフラッシュストレージで、実測の総容量は 280 KB、1 ファイルが 4 KB ブロックを 1 つ占めます。証明書は先にここへアップロードしないと、cacert が指すファイルがありません。 アップロードは UART 経由でデータ通信量ゼロ、バイナリファイルも送り込めます。 Upload カード：ファイルを選ぶとファイル名とサイズが自動記入され、送出後、ツールはモジュールが CONNECT を返すのを待ってから生バイトを送ります（待てなければ送りません）。完了時には 注釈エンジンが自動照合します。モジュールの報告するサイズと checksum を比べ： ✅＝完全で誤りなし、❌＝壊れて届いたので、先に削除して再アップロードします。

AT+QFUPL="badssl-root.pem",1939,10
CONNECT                   ← 続けて 1939 bytes を送出
+QFUPL: 1939,4f64         ← 実受信サイズ,checksum。注釈が自動照合 ✅
ボタン用途
AT+QFLSTUFS の全ファイルとサイズを一覧 —— アップロード後の検証に（通信量ゼロ）
AT+QFLDS="UFS"残り／総容量 bytes を照会（通信量ゼロ）
AT+QFDEL指定ファイルを削除（*＝全部）。 同名ファイルを先に消さないと、再アップロードは拒否されます
マニュアルが明言しない実測挙動 2 つ：（1）FILE エラーコードの形式が不統一 —— 同名の再アップロードはテキストの file already exist、タイムアウトは数値の 421 が返ります。 本ツールはどちらも解読できます。（2）サイズ欄を実際より大きく書くと、モジュールはタイムアウト後 実受信分をそのまま保存します —— checksum 照合が捕まえてくれます。

証明書検証の実戦：ペアテスト法

流れ：ルート証明書をアップロード → cacert をそれに向ける → seclevel 1 → sni 1 → 相手の 443 へ接続。アップロードするのは証明書チェーン最上位のルート証明書です （badssl.com のチェーンは 4 層で、最上位の ISRG Root X1 をアップロード）。 「悪い証明書がつながらない」だけのテストでは不十分 —— 「全部つながらない」でも合格してしまいます。 ペアでテストします：良い証明書はつながり、悪い証明書はつながらない。 両方向が成立してはじめて確定です。実測 2×5 の対照：

ホストseclevel 0seclevel 1
badssl.com（正の対照）つながる つながる 4,0
expired（期限切れ）つながる拒否 566
self-signed（自己署名）つながる拒否 566
wrong.host（ホスト名不一致）つながる拒否 566
untrusted-root（ルート非信頼）つながる拒否 566

制限：4 種類の証明書エラーがすべて 566 を返し、モジュールはどれなのかを区別しません。 AT+QIGETERROR も助けになりません —— あれは TCP/IP 層の担当で、 このときは 0,operate successfully しか返しません。

負のテスト項目では expired を避けてください —— 出荷時の ignorelocaltime は 1 なので、期限切れ自体は 拒否されません（上表で拒否されたのは、同時にアップロードしたルートの配下に無いからです）。単独で試すなら wrong.host を。 また通信量に注意：ハンドシェイクのたびに完全な証明書チェーンをダウンロードし、失敗しても支払いは発生します。 実測ではハンドシェイク 30 回で約 150–200 KB でした。

🔴 罠：連続で約 20 回開閉すると、データスタック全体が退化する

症状：すべての AT+QSSLOPEN が一律 552 を返し、seclevel 0 でもつながらないのに、自己診断はどれも問題なしと言う。30 秒鑑別：純粋な TCP の AT+QIOPEN で同じ相手を叩く —— これも失敗すればデータスタックが壊れているので、 SSL 設定をこれ以上調べないこと。PDP の再起動では救えず、完全な起動シーケンスだけが復旧手段です。 退化はテストデータを汚染し、「証明書検証に拒否された」と誤判定しやすいので —— ペアテストの前に再起動してきれいにしてください。
