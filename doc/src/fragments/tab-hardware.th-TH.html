Hardware —— การเปิดเครื่องและพอร์ตซีเรียล

หลักการทำงาน: หน้านี้คือรากฐานของเครื่องมือทั้งชุด: Control คือปุ่มสองปุ่มของพิธีกรรมเปิดเครื่อง (Power / Reset), Module คือการระบุตัวตนผลิตภัณฑ์, Serial คือการตั้งค่า UART, Power คือโหมดประหยัดพลังงาน, URC จัดการพอร์ตส่งออกของข้อความที่โมดูลส่งมาเอง และยังมีแถวปุ่มไบต์ดิบ (Ctrl+Z / ESC / +++) ไว้เป็นทางหนีฉุกเฉินจากโหมดข้อมูล แท็บอื่นทุกแท็บตั้งอยู่บนเงื่อนไขเบื้องต้นสองข้อ: โมดูลถูกเปิดตามพิธีกรรมแล้ว และ URC วิ่งผ่าน uart1 —— ทั้งสองเรื่องนี้ทำให้เสร็จได้ในหน้านี้ พฤติกรรมและตัวเลขทั้งหมดในหัวข้อนี้คือค่าที่วัดจริงกับ EG800K ตัวจริงเมื่อเดือนสิงหาคม 2026

ทำไมต้องมีพิธีกรรมเปิดเครื่อง: RTS = ไฟเลี้ยง, DTR = Reset

บอร์ดควบคุมที่ใช้คู่กับเครื่องมือนี้เอาสัญญาณ handshake ของ RS-232 สองเส้นไปใช้งานอย่างอื่น นี่คือกุญแจสู่การเข้าใจทั้งหน้า:

สัญญาณต่อกับอะไรจริง ๆลอจิก
RTSสวิตช์ไฟเลี้ยงของโมดูล ลอจิกกลับขั้ว: RTS OFF = จ่ายไฟ, RTS ON = ตัดไฟ
DTRขา Reset ของโมดูล DTR ON = ดึง Reset ขึ้นสูง (บูตได้), DTR OFF = ดึง Reset ลงต่ำ

คุณสมบัติของวงจร (ยืนยันจากการทดสอบจริง): การเชื่อมต่อครั้งแรก RTS ต้องON ก่อนแล้วค่อย OFF ไฟถึงจะเปิดจริง —— ตั้ง OFF ตรง ๆ ไม่รับประกันว่ามีไฟ; DTR ก็ต้องเดิน ON→OFF→ON Reset ถึงจะถูกดึงขึ้นสูงจริง การตัดไฟ (RTS ON) เป็นการตัดแบบดิบ โมดูลจะไม่ส่งข้อความอำลาใด ๆ ทั้งสิ้น

รีเฟรชหน้าเว็บ = ตัดไฟ เมื่อเบราว์เซอร์เปิดพอร์ตซีเรียลใหม่ RTS จะถูกดึงขึ้นอีกครั้ง โมดูลไฟดับทันที —— หลังเชื่อมต่ออัตโนมัติเสร็จต้องรันพิธีกรรมเปิดเครื่องใหม่ บทเรียนจากการทดสอบจริง: ข้ามพิธีกรรมแล้วส่งคำสั่งไป 17 คำสั่ง หายเงียบทั้งหมด (มีแต่บรรทัด TX, RX เป็นศูนย์) อาการแบบ "เมื่อกี้ยังดี ๆ อยู่ ตอนนี้ไม่ตอบอะไรเลย" ให้นึกถึงเรื่องนี้ก่อนเสมอ

ปุ่ม Power กับ Reset: กดอย่างไร จะเห็นอะไร

ปุ่มสองปุ่มนี้คือร่างจำแลงของสัญญาณสองเส้นในตารางข้างบน และเชื่อมโยงสองทางกับตัวบ่งชี้ RTS / DTR บนแถบสัญญาณ (ตอนยังไม่เชื่อมต่อจะเป็นสีจางกดไม่ได้) Web Serial อ่านสถานะจริงของสัญญาณขาออกกลับมาไม่ได้ สิ่งที่แถบสัญญาณแสดงคือค่าตามการรับรู้ที่เครื่องมือนี้ส่งออกไป

  1. Power (แบบสลับ): สว่างเขียว = ไฟ ON (= RTS OFF) พิธีกรรมเปิดเครื่องต้องให้ RTS เดินผ่าน ON→OFF: ถ้าปุ่มสว่างอยู่แล้ว ให้กดปิดก่อนแล้วค่อยกดเปิด
  2. Reset (momentary): กดลง = DTR OFF, ปล่อย = DTR ON, กดหนึ่งครั้งปล่อยหนึ่งครั้งคือ Reset หนึ่งรอบ (จังหวะมาตรฐานหยุดตรงกลาง 0.3 วินาที)
  3. รอ RDY: ภายในไม่กี่วินาทีเทอร์มินัลจะแสดงประกาศบูตของโมดูล RDY
  4. ยืนยันด้วย ATI: ควรตอบ Quectel / EG800K / Revision: … / OK ถ้าตอบออกมาได้ = ทั้ง UART และโมดูลยังมีชีวิตอยู่
หลังเปิดเครื่องแนะนำให้ยืนยันก่อนว่า echo (ATE) เปิดอยู่ (ค่าจากโรงงานคือเปิด) แล้วค่อยส่ง AT+CMEE=2 —— ถ้าไม่เปิดจะเห็นแค่ ERROR แห้ง ๆ เปิดแล้วถึงจะได้ข้อความอ่านรู้เรื่องแบบ +CME ERROR: … ทั้งคู่เป็น session-only โมดูลรีบูตเมื่อไหร่ต้องส่งใหม่ทุกครั้ง

Module: ปุ่มระบุตัวตนห้าปุ่ม

ปุ่มคำสั่งจะเห็นอะไร
InfoATI ยี่ห้อ / รุ่น / เวอร์ชันเฟิร์มแวร์ สามอย่างในคำสั่งเดียว —— เปิดเครื่องแล้วคำสั่งแรกให้ส่งตัวนี้
Vendor / Model / FW Ver AT+GMI / AT+GMM / AT+GMR แยกสามบรรทัดของ ATI ออกมาถามทีละอย่าง (เทียบเท่า CGMI / CGMM / CGMR ตามลำดับ) เวอร์ชันเฟิร์มแวร์ของเครื่องนี้วัดจริงได้ EG800KCNGCR07A06M04
IMEIAT+GSN IMEI ของโมดูล (ตัวเลข 15 หลัก) ไม่กินปริมาณข้อมูล ส่งเมื่อไหร่ก็ได้

Serial: อ่านพารามิเตอร์ด้วย AT&V, เปลี่ยน baud rate ด้วย IPR

AT Params (AT&V): แสดงค่าปัจจุบันของพารามิเตอร์ AT แบบตัวอักษรเดี่ยวทั้งหมด คำสั่งตัวอักษรเดี่ยวอย่าง ATE / ATQ / ATV ไม่มีรูปแบบคำสั่งอ่านค่าของตัวเอง มีแต่คำสั่งนี้เท่านั้นที่อ่านได้ เครื่องนี้วัดจริงได้ E:1 Q:0 V:1 S3:13 S4:10 —— echo เปิด, รหัสผลลัพธ์เป็นโหมดข้อความ, ท้ายบรรทัด = CR (ASCII 13) ซึ่งคือเงื่อนไขเบื้องต้นที่เครื่องมือนี้ใช้แยกวิเคราะห์คำตอบ

Baud? (AT+IPR?): ถาม baud rate ปัจจุบันของ UART ค่าจากโรงงานคือ 115200
Baud List (AT+IPR=?): ตอบกลับมาสองรายการ —— รายการแรกคือ baud rate ที่ตรวจจับอัตโนมัติได้ รายการหลังคือค่าที่ใช้ได้เฉพาะโหมดตายตัว หลังจากรันปุ่มนี้แล้ว เมนูดรอปดาวน์ของ Set Baud จะเปลี่ยนเป็นรายการที่เครื่องนี้รายงานจริง ผลวัดจริงพบว่ารายการที่สองของเครื่องนี้ไล่ไปจนถึง 1000000 bps —— ตารางใน §3.4 ของคู่มือไม่มีค่านี้

Set Baud (AT+IPR={rate};&W, การ์ดพารามิเตอร์): กดแล้วจะมีกล่องยืนยันเด้งขึ้นมาก่อน —— นี่คือปุ่มที่ล็อกตัวเองไว้นอกประตูได้ง่ายที่สุดของทั้งหน้า

กับดักสามชั้นของการเปลี่ยน baud rate (ยืนยันจากการทดสอบจริงครบทุกข้อ):
① OK ตอบปุ๊บมีผลทันที วินาทีถัดไปเครื่องมือนี้กับโมดูลก็คุยกันคนละภาษาแล้ว;
② AT&F (รีเซ็ตค่าโรงงาน) ไม่เปลี่ยน baud rate กลับมาให้ —— อย่าหวังพึ่งมัน;
③ ไม่ใส่ &W = ไม่บันทึก —— และการเชื่อมต่อใหม่ = ตัดไฟ โมดูลจะตื่นขึ้นที่ baud rate เก่า แต่การตั้งค่าพอร์ตของคุณค้างอยู่ที่ค่าใหม่ ขาดการติดต่อซ้อนสองชั้น เครื่องมือนี้จึงบังคับใช้รูปแบบรวม ;&W
การกู้คืนสี่ขั้น (กล่องยืนยันก็จะเตือนด้วย): ตัดการเชื่อมต่อ → แก้ baud rate ในส่วนเชื่อมต่อ → เชื่อมต่อใหม่ → รันพิธีกรรมเปิดเครื่องใหม่

Power: โหมดประหยัดพลังงาน QSCLK

Sleep? (AT+QSCLK?): ถามว่าโมดูลอนุญาตให้เข้าสู่โหมดหลับหรือไม่ เครื่องนี้วัดจริงค่าจากโรงงานคือ 0 = ปิดใช้ โมดูลตื่นตลอด หน้านี้ให้แค่ปุ่มถามค่าเท่านั้น: โมดูลที่หลับแล้วจะหยุดตอบ AT วิธีปลุกตามคู่มือคือดึง DTR ลงต่ำ —— แต่ DTR ของบอร์ดนี้ถูกต่อไปทำหน้าที่ขา Reset แล้ว (ดูต้นหัวข้อนี้) ถ้าไปเปิดโหมดหลับเองในบรรทัดคำสั่งแล้วปลุกไม่ตื่น ให้รันพิธีกรรมเปิดเครื่อง (ตัดไฟแล้วเปิดใหม่) ก็หลุดพ้นได้ รายละเอียดดูใน application note โหมดประหยัดพลังงานฉบับทางการ

URC: รับข้อความไม่ได้เมื่อไหร่ ให้มาที่นี่ก่อน

URC (Unsolicited Result Code, รหัสผลลัพธ์ที่ไม่ได้ร้องขอ) คือข้อความที่โมดูล "พ่นออกมาเองโดยไม่มีใครขอ" ไม่ใช่คำตอบของคำสั่งใด ๆ —— RDY ตอนบูต, ข้อมูล TCP มาถึง, ข้อความ MQTT, ผลสแกน Wi-Fi, การแจ้งโหลดเฟิร์มแวร์ GNSS ล้วนเป็น URC ทั้งนั้น พอร์ตส่งออกของมัน ค่าจากโรงงานคือพอร์ต USB (usbat) —— เครื่องมือนี้เดิน UART จึงรับไม่ได้เลยสักข้อความเดียว อาการคลาสสิกมาก: คำสั่งตอบ OK หมด แต่รอข้อความเท่าไหร่ก็ไม่มา

ปุ่มคำสั่งใช้ทำอะไร
URC Port?AT+QURCCFG="urcport" ถามว่าตอนนี้ URC ถูกส่งไปที่ไหน —— รับ URC ไม่ได้เมื่อไหร่ให้ถามตัวนี้เป็นคำสั่งแรก; ต้องตอบ "uart1" ถึงจะรับได้
URC PortsAT+QURCCFG=? เครื่องนี้รองรับพอร์ตส่งออกอะไรบ้าง วัดจริงตอบ ("usbat","usbmodem","uart1") ไม่มี "all" ที่คู่มือพูดถึง (คู่มือมีหมายเหตุว่าบางรุ่นไม่รองรับ)
URC → UARTAT+QURCCFG="urcport","uart1" สลับมาที่ UART หลัก เขียนลง NVRAM คงอยู่ข้ามการรีบูต แก้ครั้งเดียวพอ
URC SwitchAT+QINDCFG="all" สวิตช์รวมของ URC สาเหตุใหญ่อีกข้อของ "รับ URC ไม่ได้" วัดจริงเครื่องนี้ค่าจากโรงงานเป็น 1 (เปิด) อยู่แล้ว ปัญหาแทบทั้งหมดอยู่ที่พอร์ตส่งออก

ปุ่มไบต์ดิบ: ทางหนีฉุกเฉินจากโหมดข้อมูล

คำสั่งไม่น้อยเป็นแบบสองขั้น: ส่งคำสั่งก่อน รอโมดูลตอบพรอมต์ > แล้วค่อยส่งเนื้อหา เมื่อเข้าสู่โหมดข้อมูลแบบนี้แล้ว โมดูลจะกลืนทุกตัวอักษรที่คุณพิมพ์เป็นข้อมูลหมด —— รวมถึงคำสั่ง AT ที่คุณอยากส่งด้วย เมื่อคำนวณความยาวผิด เปลี่ยนใจกลางคัน หรือคำสั่งค้าง ปุ่มกดทั่วไปช่วยไม่ได้ ต้องพึ่งแถวปุ่มที่ส่งไบต์ดิบทีละไบต์นี้:

ปุ่มส่งอะไรใช้เมื่อไหร่
Ctrl+Z0x1A ตัวจบของโหมดข้อมูล: ส่งเนื้อหาที่สะสมไว้ออกไปจริง ๆ
ESC0x1B ยกเลิกโหมดข้อมูล ทิ้งเนื้อหาที่สะสมไว้ ปุ่มหนีตัวแรกที่ควรใช้เมื่อคำสั่งสองขั้นค้างหรือพอร์ต AT ไม่ตอบอีกต่อไป (คู่มือ §2.3.8)
+++เครื่องหมาย + สามตัว (ไบต์ดิบ) หนีจากโหมดข้อมูลแบบโปร่งใส (เช่นการถ่ายโอน COM: ของ FTP) กลับสู่โหมด AT กติกาแข็งมาก: ต้องเงียบก่อนและหลังอย่างละ 1 วินาที และห้ามมี CR/LF เด็ดขาด —— ทดสอบจริงพบว่าใส่ CR แล้วไม่ทำงาน ต้องส่งด้วยปุ่มนี้ พิมพ์ในบรรทัดคำสั่งไม่ได้
การทดสอบจริงหักล้างคู่มือ: +++ คือ "ยุติ" ไม่ใช่ "หยุดชั่วคราว" application note ของ FTPS v1.5 หน้า 13 บอกว่าหลัง +++ ใช้ ATO กลับเข้าโหมดข้อมูลเพื่อส่งต่อได้ แต่บนเครื่องจริง ATO ตอบแค่ NO CARRIER การถ่ายโอนถูกยุติไปแล้ว ให้ใช้ +++ เป็นเบรกฉุกเฉิน อย่าหวังว่าเบรกเสร็จแล้วจะขับต่อได้

การแก้ปัญหา

อาการสาเหตุและวิธีแก้
ไม่ว่าคำสั่งอะไรก็ไม่ตอบ ไล่สอบผู้ต้องสงสัยสามรายตามลำดับ: ① ไม่ได้รันพิธีกรรมเปิดเครื่อง (ถ้าเพิ่งรีเฟรชหน้าเว็บมาก็ใช่ตัวนี้แน่นอน); ② ตั้งท้ายบรรทัดเป็น LF —— โมดูลรับเฉพาะ CR ส่ง LF ไปจะไม่ตอบอะไรเลย; ③ baud rate ไม่ตรงกัน (ดูการกู้คืนสี่ขั้น)
กด Reset แล้วรอ RDY เท่าไหร่ก็ไม่มา ดูก่อนว่าปุ่ม Power สว่างหรือยัง —— โมดูลไม่มีไฟ กด Reset กี่ครั้งก็ไร้ผล; การเชื่อมต่อครั้งแรกไฟเลี้ยงต้องเดินผ่าน ON→OFF
คำสั่งตอบ OK หมด แต่ URC ไม่มาสักที แปดสิบเปอร์เซ็นต์คือ urcport ยังอยู่ที่ usbat ค่าโรงงาน: กด URC Port? ถาม แล้วกด URC → UART แก้; ยังไม่ได้ผลค่อยเช็ค URC Switch สวิตช์รวม
พอร์ต AT อยู่ ๆ ก็ "กลืนคำสั่ง" พิมพ์อะไรก็ไม่ตอบ ติดอยู่ในโหมดข้อมูล ตัวอักษรที่พิมพ์ถูกเก็บเป็นข้อมูลไปหมด —— กด ESC เพื่อหนีออกมา
