FTP — Transfer Berkas

Cara kerja: FTP punya dua kanal: kanal kendali membawa perintah, kanal data membawa isi berkas. Login, ganti nama, hapus, dan cek ukuran hanya lewat kanal kendali; LIST, unggah, dan unduh harus membuka satu koneksi data terpisah — sebagian besar keanehan pada bagian ini (615, 603 bertubi-tubi) lahir dari sana. Kaidah umum Quectel yang berlaku sepanjang bagian ini: OK hanya berarti "perintah diterima"; hasil sesungguhnya datang belakangan lewat URC. Balasan dan angka pada bagian ini semuanya nilai hasil uji nyata terhadap EG800K fisik pada Agustus 2026.

Sebelum mulai: dua prasyarat

  • PDP harus aktif dulu: tombol pertama halaman ini AT+QIACT? memang untuk pemeriksaan ini — harus terbalas +QIACT: 1,1,…,"IP" baru boleh lanjut; bila hanya membalas OK, pergilah dulu ke halaman TCP/IP dan tekan Act PDP (saat PDP belum aktif, QFTPOPEN pasti gagal).
  • URC harus lewat UART: perintah FTP hampir semuanya "OK dulu, hasil menyusul lewat URC"; bila AT+QURCCFG="urcport" bukan "uart1", di sini hanya terlihat setumpuk OK (penyetelannya lihat halaman Hardware).

Alur login: setel → buka → tunggu URC

  1. Ikat PDP context: AT+QFTPCFG="contextid",1 (dari pabrik memang 1; tombol query bisa membacanya kembali untuk konfirmasi).
  2. Setel akun-sandi: AT+QFTPCFG="account","akun","sandi", wajib disetel sebelum QFTPOPEN.
  3. Mode dan tipe: transmode disetel 1 (pasif; di belakang NAT selalu pakai ini, wajib untuk FTPS); filetype berkas teks murni pakai 1, selainnya pakai 0.
  4. Login: AT+QFTPOPEN="host",21 langsung membalas OK (baru diterima); tunggu +QFTPOPEN: 0,0 barulah login berhasil (maksimum 125 detik). Lalu tekan AT+QFTPSTAT, seharusnya membalas 1 (menganggur; 2 = sedang transfer, 3 = sedang menutup).
AT+QFTPCFG="account","demo","password"
AT+QFTPCFG="transmode",1
AT+QFTPOPEN="test.rebex.net",21
OK                ← Hanya berarti perintah diterima
+QFTPOPEN: 0,0    ← Baris inilah tanda login berhasil

Butir setelan lainnya: AT+QFTPCFG=? sekali klik menampilkan seluruh 10 butir yang bisa disetel beserta rentangnya (nol kuota). rsptimeout (20–180, default 90 detik) adalah waktu balasan maksimum kebanyakan perintah, sekaligus jeda maksimum antara dua paket data dalam mode data; ssltype / sslctxid untuk FTPS (FTP murni pertahankan 0; parameter SSL disetel di halaman SSL); data_address / cache / restenable adalah penyetelan halus untuk lingkungan khusus; kegunaannya lihat keterangan tiap tombol dan manual.

Penyamaran sandi (hasil uji, tak sesuai manual): saat query AT+QFTPCFG="account" dibaca kembali, sandinya disamarkan menjadi * (manual bilang dicetak apa adanya). Tetapi akunnya tetap teks polos, dan sandi pada baris penyetelan pun teks polos; yang perlu diwaspadai saat tangkapan layar atau perekaman adalah baris penyetelannya.
🔴 AT+QFTPCLOSE bersifat asinkron — OK bukan berarti sudah tertutup. Tunggu +QFTPCLOSE: 0,0 barulah logout selesai; selama itu AT+QFTPSTAT membalas 3 (sedang menutup), dan perintah FTP apa pun selalu dibalas +CME ERROR: 603 (server sibuk).

Gejalanya sangat menyesatkan: rentetan 603 tampak seperti modul rusak atau diblokir server, padahal hanya belum selesai menutup (pada hari pengujian sempat berputar-putar jauh karena ini). Batas tunggunya = rsptimeout. Selain itu ia hanya logout dari FTP; untuk mereset jaringan sepenuhnya, tekan Deact PDP di halaman TCP/IP.

Manajemen direktori dan berkas: memakai server bak penjelajah berkas

Satu set penuh operasi berkas sisi server (LIST / NLST / MLSD perlu membuka koneksi data, sisanya hanya lewat kanal kendali). Balasan keberhasilan selalu +QFTPXXX: 0,… — angka pertama 0 berarti berhasil:

PerintahYang dilakukanBalasan berhasil (hasil uji)
AT+QFTPPWDMenanyakan direktori kerja kini+QFTPPWD: 0,"/"
AT+QFTPCWDBerpindah direktori kerja; operasi berikutnya bertumpu padanya+QFTPCWD: 0,0
AT+QFTPLISTDaftar lengkap langsung dimuntahkan di terminal (dua tombol: direktori kini / direktori tertentu)Setelah isinya +QFTPLIST: 0,1175 (angka akhir = jumlah byte)
AT+QFTPNLST / AT+QFTPMLSDHanya nama berkas (hemat kuota) / format standar MLSD (mudah diparse)Sama dengan LIST
AT+QFTPSIZEMenanyakan ukuran berkas tanpa mengunduh isinya+QFTPSIZE: 0,20
AT+QFTPMDTMMenanyakan waktu ubah berkas tanpa mengunduh isinya+QFTPMDTM: 0,"20260807141117"
AT+QFTPMKDIR / AT+QFTPRMDIRMembuat / menghapus folder…: 0,0
AT+QFTPRENAMEMengganti nama berkas atau folder+QFTPRENAME: 0,0
AT+QFTPDELMenghapus berkas+QFTPDEL: 0,0

Jurus (seluruh rangkaiannya lolos pengujian): jadikan SIZE pemeriksa keberadaan — setelah ganti nama, menanyakan nama lama membalas +QFTPSIZE: 627,550, nama baru membalas 0,20; setelah dihapus, ditanya lagi kembali 627,550 — setiap langkah terverifikasi tanpa mengunduh satu byte pun. 627,550 adalah kode error dua lapis: 627 = lapisan modul "FTP tidak menjalankan aksi yang diminta", 550 = lapisan protokol FTP, server membalas "berkas atau direktori tidak ada"; anotasi alat ini menerjemahkannya per lapis.

Mengunduh: isi langsung dicetak di terminal (COM:)

AT+QFTPGET="namafile","COM:" — setelah CONNECT, isi berkas langsung dimuntahkan di terminal, diakhiri +QFTPGET: 0,<jumlah byte> (hasil uji readme.txt membalas 0,379). Tombol satunya, unduh per blok, membawa tambahan parameter titik awal dan panjang — cara mengunduh yang paling direkomendasikan: tanyakan dulu ukurannya dengan SIZE, lalu ambil per blok, menghindari satu berkas utuh meledakkan kuota. AT+QFTPLEN menanyakan berapa byte yang benar-benar ditransfer pada PUT / GET / LIST / NLST terakhir.

Mengunggah: dua tahap; begitu panjang yang dideklarasikan terpenuhi, otomatis berakhir

AT+QFTPPUT="namafile","COM:",0,<panjang>,1 adalah perintah dua tahap: setelah CONNECT (masuk mode data), kirim byte sebanyak tepat panjang yang dideklarasikan; begitu hitungan penuh, modul otomatis keluar dari mode data tanpa perlu mengirim Ctrl+Z. Alat ini menghitung panjang otomatis; cukup tempel isinya di kartu parameter.

AT+QFTPPUT="numodem-test.txt","COM:",0,20,1
CONNECT                        ← Masuk mode data
NuModem-P6-FTP-test\n          ← Kirim tepat 20 bytes
OK
+QFTPPUT: 0,20                 ← Server menerima 20 bytes

Ke-20 byte ini saat pengujian sengaja diambil kembali dari sisi host memakai Python ftplib lalu dibandingkan byte demi byte — cocok sempurna. Bentuk transit UFS: manual juga mendukung nama berkas ditulis "UFS:xxx", bertransit lewat penyimpanan bawaan modul; detailnya lihat application note FTPS. Untuk menaruh berkas komputer ke UFS lebih dulu, pakai tombol Upload di kelompok "berkas UFS" halaman SSL (AT+QFUPL, lewat UART nol kuota, checksum dibandingkan otomatis).

⚠ Bagi FTP, +++ berarti "menghentikan", bukan "menjeda". Manual (FTPS AN v1.5 hal.13) menulis bahwa setelah meloloskan diri, ATO bisa masuk kembali ke mode data untuk melanjutkan transfer; pengujian membuktikan tidak demikian (diuji dua kali, hasilnya konsisten): setelah lolos, AT+QFTPSTAT membalas 1 (menganggur) dan bukan 2 (sedang transfer), ATO membalas NO CARRIER — transfernya sudah dihentikan seluruhnya, tak ada koneksi yang bisa dipulihkan. Maka +++ hanya bisa dipakai meloloskan diri dari mode data yang lepas kendali, bukan menjeda unduhan berkas besar.

Cara mengirim yang benar: hening 1 detik sebelum dan sesudah, dikirim sebagai byte mentah, tanpa CR (ditambah CR malah tak berlaku) — tombol +++ halaman ini sudah mengirim sesuai aturan itu; tombol ATO dipertahankan sesuai makna manual.

Pemecahan masalah

GejalaPenyebab dan solusi
+CME ERROR: 603 bertubi-tubi ① Setelah QFTPCLOSE masih dalam proses menutup (QFTPSTAT membalas 3) — tunggu +QFTPCLOSE: 0,0; ② sebelumnya pernah terjadi 615 — setelah 615, semua perintah FTP selalu 603 sampai ditutup dengan benar
+CME ERROR: 615 Gagal membuka koneksi data: kanal kendali normal, kanal data tumbang total (SIZE terbalas; PUT / GET / LIST roboh semua). Kebanyakan masalah di sisi server — dlptest gagal diuji dari dua jalur jaringan berbeda, rebex nol kegagalan sepanjang proses; untuk membaca pakai rebex, menulis barulah pakai dlptest dan selesaikan sekali jalan
627,550 Berkas atau direktori tidak ada — nama atau jalurnya salah ketik; pastikan dulu posisi Anda dengan QFTPPWD / QFTPLIST
Setelah boot ulang, PUT pertama langsung 615 Degradasi stack data: QFTPCLOSE maupun restart PDP tak menyelamatkan, hanya ritual boot lengkap yang memulihkan. Cara membedakannya: pakai AT+QIOPEN halaman TCP/IP menembak target yang sama — ikut gagal = seluruh stack rusak, jangan lagi memeriksa setelan FTP
Perintah membalas OK lalu tak terjadi apa-apa URC hasilnya lari ke port USB — periksa apakah AT+QURCCFG="urcport" sudah uart1
AT+QFTPOPEN langsung gagal PDP belum aktif — tekan dulu AT+QIACT? di halaman ini; bila tak ada IP, ke halaman TCP/IP tekan Act PDP
