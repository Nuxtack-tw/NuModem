Network — Registration, operators, RF

Working principle: every data feature works only if the module is registered on the cellular network and the PDP data channel is ready — this page is the dashboard and switchboard for getting on the network, and every "cannot get online" investigation starts here. All numbers in this section were measured on a physical EG800K in August 2026.

Before you start: switch URCs to the UART first

From the factory, the EG800K sends its unsolicited messages (URCs) to usbat (the USB AT port), while this tool uses the UART — so not a single URC gets through: signal reports, TCP / MQTT / Wi-Fi scan results all go silent, and the symptom is "every command replies OK, but no messages ever come".

This is the number-one cause of "all URCs vanished". Go to the Hardware tab, query with AT+QURCCFG="urcport", and if it is not "uart1", switch it with the toggle button — the setting is written to NVRAM; change it once and it survives reboots.

Step one: confirm the registration state

After the power-up ritual shows RDY, click AT+CEREG? first (the most accurate one on a 4G module). The three registration buttons map to three domains: CEREG = LTE/EPS, CREG = circuit-switched domain, CGREG = packet-switched domain; the second number (stat) reads the same for all:

statMeaningWhat to do
0Not registered yetCommon right after boot; wait a few seconds and query again
1Registered (home network)Normal, proceed
2SearchingWait
3Rejected by the networkCheck the SIM / plan; use CEER for the reason
5Registered (roaming)The normal state on this unit, see below
stat=5 is not a fault. Measured: all three registration queries return 0,5 — the SIM is a 1NCE IoT card (MCC 901, an international roaming card) that counts as "roaming" in any country; treat 5 as 1.

If registration succeeds but you still cannot get online, click AT+CGATT? next to check packet-domain attach; if needed, click AT+CGATT=1 to attach manually, and on failure use AT+CEER for the reason (a different layer from the TCP/IP page's QIGETERROR). CGATT can block up to 140 seconds — do not hammer it.

Which operator and which band are you on right now

AT+COPS? queries the currently registered operator (a trailing 7 = LTE). Trap: the operator name may be an empty string — measured reply +COPS: 0,0,"",7, not a fault. To see the operator, click AT+QNWINFO instead (technology / operator / band / channel):

+QNWINFO: "FDD LTE","46692","LTE BAND 8",3750

46692 = Chunghwa Telecom, Band 8; with no service it returns NO SERVICE. This roaming card picks its own network: on different days it was measured on Chunghwa Telecom Band 8 and on FarEasTone (466-01) Band 3 — switching operator and band is all normal. AT+COPS=? scans every operator in the area: it can block up to 300 seconds and interrupts ongoing services; click it only if you really need it.

Signal strength and quality: CSQ is only a rough figure

AT+CSQ returns rssi and ber: rssi 0–31 maps to -113 to -51 dBm, 99 = undetectable (common right after boot; wait a few seconds). Measured rssi 18–24 (-77 to -65 dBm, good); ber is permanently 99, no reference value. LTE's real quality trio — RSRP (strength) / RSRQ (quality) / SINR (signal-to-noise ratio; low = interference) — is available only through the Signal URC group (AT+QINDCFG="sqi" with no value = query the switch):

The PDP channel: the 3GPP layer vs the TCP/IP page

A PDP context = the "data channel" the cellular network allocates; only with it do you have an IP. This group is read-only queries at the 3GPP standard layer: AT+CGDCONT? lists contexts and APNs, AT+CGACT? lists activation states (blocks up to 150 seconds; ⚠ the write form takes its parameters in the opposite order), and AT+CGPADDR lists the obtained IPs. The TCP/IP page's QIACT? / QICSGP are Quectel's own stack — not the same layer — and comparing them side by side tells you which side is broken: an IP here but none over there = the network granted it but the stack never started. This unit auto-activates a PDP and obtains an IP at boot.

AT+QGDCNT? queries cumulative data usage (first number sent, second received) — a must when metering a roaming card. ⚠ Testing overturns the button hint's "accumulates across reboots": by default the counter is not saved to NV and resets to zero on any power cut (page reloads included) — record it on the spot, or save to NV with AT+QGDCNT=1.

Field debugging: this card allows only a single PDP

Clicked AT+QIACT=1 on the TCP/IP page and got ERROR (572,operation not allowed)? This card's fixed script: after boot the 3GPP layer has already auto-activated one PDP, but the context number drifts (both 1 and 9 seen in testing); opening a second one returns +CME ERROR: 100 ⇒ the network allows only a single PDP; and QIACT's contextID range is only 1–8, so when the PDP lands on 9 the Quectel stack cannot touch it at all. The two-step fix (do it once after every boot):

AT+CGACT?             ← see which cid it is (the number drifts; do not skip this)
AT+CGACT=0,<that cid>   ← the 3GPP layer gives up the slot
AT+QIACT=1            ← TCP/IP page; a reply of +QIACT: 1,1,1,"10.187.7.8" means success

Setting the APN with QICSGP can be skipped on this card — measured, the module auto-syncs the network-assigned APN (iot.1nce.net); it becomes necessary only with enterprise APN cards that need credentials.

Everything suddenly timing out mid-test? Suspect PDP drift first. Measured: while HTTP failed continuously (error 716, fixed 30-second timeouts), AT+QIACT? still returned an IP — at that moment it lies, so cross-check against AT+CGACT? (measured: 1,0 and 9,1 = drifted to 9). Fix: AT+QIDEACT=1 → AT+CGACT=0,<the drifted cid> → AT+QIACT=1, then verify with a ping.

CFUN functionality levels and RF control

The whole RF Control group changes the module's state; every button is a red-framed confirm-before-click one. Click AT+CFUN? first to see the current level before acting:

CommandLevelMeaning
AT+CFUN=1Full functionality RF fully on; always recover with this one
AT+CFUN=4Airplane TX/RX fully off, SIM still active — the starting point for "re-registration" tests
AT+CFUN=0Minimum SIM disabled too; the manual only says Minimum functionality without details
AT+CFUN=1,1Soft restart Restarts the whole module. ⚠ The AT port goes dead briefly; wait for RDY again

CFUN can block up to 15 seconds. If the SIM has a PIN lock, after switching back to CFUN=1 you must re-enter the PIN before it registers. AT+CGATT=0 (PS Detach) leaves the packet domain — it kills every TCP / MQTT connection; use it only to test "re-attach".

This page has no button for it — type AT+QENG="servingcell" on the command line to read the serving cell's parameters. Key fields as measured:

Cell ID and TAC are hexadecimal; convert to decimal before querying any database. Databases like OpenCelliD only take decimal — throwing ABCDE02 at them just returns no match. Also, AT+QENG="neighbourcell" returns only PCIDs, no global Cell ID (an LTE standard limitation).
