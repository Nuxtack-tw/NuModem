HTTP — peticiones web

Funcionamiento: el HTTP del módulo es en tres etapas: primero se fija la URL (paso que a su vez es en dos fases), después se lanza la petición (GET/POST) y por último se lee de vuelta la respuesta. El resultado de cada etapa no viene en el OK, sino en un URC que llega después — por eso AT+QURCCFG="urcport" debe ser "uart1" (se cambia en la página Hardware); de lo contrario no se ve ni un solo resultado. Todos los datos son mediciones reales de agosto de 2026.

Antes de empezar: primero un canal de datos

La premisa es tener el PDP activado y con IP (el AT+QIACT=1 de la página TCP/IP). El grupo Connect de esta página solo contiene comprobaciones de lectura: AT+CPIN?/AT+CGATT?/AT+CGREG?/ AT+QIACT?, AT+QIDNSCFG=1 (DNS 0.0.0.0 = no asignado), AT+QIGETERROR (⚠ solo vale para el último comando TCP/IP; tras un fallo hay que pulsarlo de inmediato).

AT+QIACT? engaña. Medido: hubo una deriva del PDP a mitad de sesión: todas las peticiones fallaban con expiración fija de 30 segundos y error 716, y AT+QIACT? seguía respondiendo con IP. Contrasta con AT+CGACT?; si no coinciden, ha derivado. Arreglo: AT+QIDEACT=1 → AT+CGACT=0,<cid derivado> → AT+QIACT=1, y sigue solo tras pasar un ping.

El primer GET: cuatro pasos

  1. Configuración previa (grupo Config, cero tráfico): en la tarjeta de parámetros contextid pon 1 (vincula el PDP context que se va a usar); los tres interruptores rspout/auto, requestheader y responseheader déjalos a 0 (razones más abajo); AT+QHTTPCFG? lee de una vez toda la configuración para cotejarla y AT+QHTTPCFG=? lista los apartados configurables.
  2. Fija la URL (dos fases): la tarjeta de AT+QHTTPURL solo tiene un botón «Enviar (dos fases)» — tú rellenas la URL y la longitud la calcula el programa. Flujo: primero se envía AT+QHTTPURL=<longitud>,80, se espera el CONNECT que entra en modo de datos, y se envían los bytes de la URL tal cual, sin añadir ningún fin de línea (el CR/LF se contaría en la longitud). http://www.example.com/ mide exactamente 23. Al terminar, pulsa AT+QHTTPURL? para leerla de vuelta: idéntica letra a letra = no se coló ningún fin de línea.
  3. Lanza la petición: AT+QHTTPGET=80 (segundos de espera de la respuesta). El OK solo significa «comando aceptado»; el resultado real es el URC posterior +QHTTPGET: 0,200; su interpretación, en el párrafo siguiente.
  4. Lee la respuesta: AT+QHTTPREAD=80. Tras el CONNECT todo son bytes crudos (medido con example.com, 559 bytes), seguidos del OK — pero la marca de final es el +QHTTPREAD: 0 en su propia línea al final.

Interpretar +QHTTPGET: el primer campo no es el código de estado HTTP

Los URC de resultado de GET/POST/POSTFILE tienen los tres campos <err>,<httprspcode>,<content_length>: err 0 = el comando se ejecutó con éxito; distinto de 0 es un error de capa de módulo (716, 711…); httprspcode es el código de estado HTTP, que solo se reporta con err=0 (lo dice el manual; la herramienta trae anotaciones para 200/403/404/409/411/500); content_length es opcional — solo aparece si la cabecera de respuesta del servidor trae CONTENT-LENGTH, y un GET normal suele traer solo dos campos. Por eso el +QHTTPGET: 0,404,0 medido no es un fallo: el comando tuvo éxito; es el servidor diciendo que no lo encuentra.

Leer la respuesta: las trampas de AT+QHTTPREAD

El parámetro es «el intervalo máximo en segundos entre dos paquetes de datos», no la duración total. El firmware de este equipo solo acepta un parámetro: la lectura por tramos =<wait>,<read_len> del documento de aplicación responde en la práctica un ERROR pelado (confirmado sondeando con =?), y el botón se ha retirado — para la recuperación por tramos usa GETEX.

Trampa de interbloqueo: con rspout/auto a 1, todos los READ fallan sin excepción (lo dice el manual). Hace que el módulo vuelque la respuesta automáticamente, al precio de aniquilar los READ, y por eso ese botón tiene diálogo de confirmación. Si los READ de repente se caen todos, consulta primero AT+QHTTPCFG?.

Recuperación por tramos: AT+QHTTPGETEX lee byte a byte

AT+QHTTPGETEX=<segundos>,<desplazamiento inicial>,<longitud> usa HTTP Range para traer solo el fragmento indicado y ahorrar tráfico. Medido (el contenido del endpoint es fijo: abcdefghijklmnop): desplazamiento 0 y longitud 8 responde +QHTTPGET: 0,206,8 y se lee abcdefgh; desplazamiento 8 y otros 8 leen ijklmnop. Interpretación: el código de estado debe ser 206; si responde 200 y el contenido es siempre el mismo = el servidor no soporta Range, no es que el módulo esté roto. ⚠ Solo se puede ejecutar con requestheader=0.

POST: dos fases y Content-Type

La tarjeta de AT+QHTTPPOST también es en dos fases: tú rellenas el body y la longitud se calcula sola; primero se envía AT+QHTTPPOST=<longitud>,<segundos de entrada>,<segundos de respuesta>, se espera el CONNECT y se envía el body. Tres cosas:

  • El CONNECT puede tardar hasta 125 segundos (lo dice el manual) — la expiración de espera del aviso debe cubrir los 125 segundos; no heredes los 5 segundos de MQTT.
  • Límite del body: 1 MB (rango medido con =?: 1–1024000).
  • El Content-Type se fija antes con la tarjeta de parámetros contenttype (código de tipo 0 = form-urlencoded).

Medido: un POST de Message=HelloQuectel (20 bytes) responde +QHTTPPOST: 0,200,440; el JSON devuelto por READ permite verificar que la clave y el valor llegaron, que la longitud se calculó bien y que el Content-Type surtió efecto; el User-Agent que el módulo declara es QUECTEL_MODULE.

Cabeceras personalizadas y cabeceras de respuesta

  • reqheader/add: añade una cabecera de petición personalizada (el manual no trae ejemplo); el botón de consulta dice cuántas hay añadidas; reqheader/remove las quita.
  • requestheader a 1 = compones tú la cabecera de petición entera, hasta el GET pasa a ser en dos fases, y GETEX deja de poder usarse. En el día a día, mantenlo a 0.
  • Con responseheader a 1, READ vuelca también las cabeceras de respuesta HTTP (medido: hasta la X-Test personalizada vuelve). Tras probar, devuélvelo a 0.
  • closed/ind: activa el URC de aviso de «session cerrada».

Versión con archivos: POSTFILE y READFILE (UFS)

AT+QHTTPPOSTFILE="nombre",<segundos> envía un POST usando como body un archivo del sistema de archivos del módulo (UFS); AT+QHTTPREADFILE="nombre",<segundos> guarda la respuesta como archivo UFS. ⚠ Esta herramienta hoy no puede subir archivos a la UFS ni leer de vuelta el contenido de un archivo UFS; estos dos comandos son para combinarlos con flujos del lado del firmware.

HTTPS: la ruta sin verificación

HTTPS = HTTP + SSL context. El grupo Connect trae preparada la ruta más corta; pulsa los cinco en orden:

AT+QHTTPCFG="sslctxid",1           ← HTTP usará el SSL context 1
AT+QSSLCFG="sslversion",1,4        ← la versión TLS se negocia con el servidor
AT+QSSLCFG="ciphersuite",1,0XFFFF  ← todas las suites de cifrado abiertas
AT+QSSLCFG="seclevel",1,0          ← sin verificar el certificado (ver abajo)
AT+QSSLCFG="sni",1,1               ← activa SNI (¡de fábrica es 0!)

Después, cambia la URL a una que empiece por https:// y haz GET/READ como siempre — medido, el HTML leído es idéntico letra a letra al de la versión en claro. seclevel=0 (sin verificar el certificado) es la única ruta que esta herramienta puede completar — para verificar certificados hay que escribir antes el certificado CA en la UFS; los detalles de SSL (AT+QSSLCFG=? lista todos los subapartados, negotiatetime ajusta los segundos de espera de la negociación) están en la sección «SSL — el túnel TLS». SNI de fábrica es 0: sin activarlo, los sitios HTTPS de IP compartida reciben un certificado que no corresponde y la verificación falla a la primera. La cadena de certificados es el grueso del tráfico: una ronda de HTTPS GET son unos 8–15 KB; en claro, apenas 1 KB.

Redirecciones y cierre

Redirecciones (el manual no lo dice; aclarado en pruebas): el módulo sigue automáticamente los 302, pero solo acepta Location con ruta absoluta — con ruta relativa responde directamente error 711, fallando en 1 milisegundo. Cierre: AT+QHTTPSTOP (grupo Close) cancela la petición en curso y corta la session; cuando el estado esté raro o aparezca el error 704 (modo de datos ocupado), pulsa este primero para dejarlo limpio.
