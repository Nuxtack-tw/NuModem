Network — регистрация, оператор, радиочасть

Принцип работы: любые функции передачи данных работают лишь при условии, что модуль зарегистрирован в сотовой сети и канал данных PDP готов — эта страница и есть приборная панель и выключатели входа в сеть; любой разбор «не выходит в сеть» начинается отсюда. Все значения в этом разделе — замеры на физическом EG800K в августе 2026 года.

Прежде чем начать: переключите URC на UART

С завода EG800K отправляет самопроизвольные сообщения (URC) на usbat (USB AT-порт), а этот инструмент работает через UART — не придёт ни один URC: отчёты о сигнале, результаты TCP / MQTT / сканирования Wi-Fi молчат все разом; симптом — «команды отвечают OK, но сообщений нет».

Причина номер один «всех пропавших URC» — именно это. На вкладке Hardware запросите AT+QURCCFG="urcport"; если ответ не "uart1" — переключите кнопкой. Настройка пишется в NVRAM: одной смены хватает на все последующие перезапуски.

Шаг первый: проверить состояние регистрации

Увидев RDY после ритуала включения, сначала нажмите AT+CEREG? (для 4G-модуля это самый показательный запрос). Три кнопки регистрации соответствуют трём доменам: CEREG = LTE/EPS, CREG = домен коммутации каналов, CGREG = пакетный домен; второе число (stat) читается одинаково:

statЗначениеЧто делать
0Ещё не зарегистрированОбычное дело сразу после включения — подождите несколько секунд и запросите снова
1Зарегистрирован (домашняя сеть)Норма, идите дальше
2Идёт поискЖдите
3Сеть отказалаПроверьте SIM / тариф; причину смотрите через CEER
5Зарегистрирован (роуминг)Нормальное состояние этой машины, см. ниже
stat=5 — не неисправность. Замер: все три запроса регистрации возвращают 0,5: SIM — IoT-карта 1NCE (MCC 901, международная роуминговая), она «в роуминге» в любой стране; видите 5 — считайте как 1.

Если регистрация есть, а сети нет, дальше нажмите AT+CGATT? — проверка привязки к пакетному домену; при необходимости привяжитесь вручную кнопкой AT+CGATT=1, а если не вышло — причину смотрите через AT+CEER (это другой уровень, нежели QIGETERROR со страницы TCP/IP). CGATT может блокировать до 140 секунд — не жмите подряд.

На каком операторе и на какой полосе мы сейчас

AT+COPS? — текущий зарегистрированный оператор (последняя цифра 7 = LTE). Ловушка: имя оператора может быть пустой строкой — замер вернул +COPS: 0,0,"",7, и это не сбой. Чтобы увидеть оператора, нажмите вместо этого AT+QNWINFO (стандарт / оператор / полоса / канал):

+QNWINFO: "FDD LTE","46692","LTE BAND 8",3750

46692 = Chunghwa Telecom, Band 8; без обслуживания возвращается NO SERVICE. Эта роуминговая карта сама выбирает сеть: в разные дни замеры показывали Chunghwa Telecom Band 8 и FarEasTone (466-01) Band 3 — смена оператора и полосы нормальна. AT+COPS=? сканирует всех операторов вокруг: блокирует до 300 секунд и обрывает текущие сервисы — нажимайте, лишь убедившись, что это нужно.

Сила и качество сигнала: CSQ — лишь грубая оценка

AT+CSQ возвращает rssi и ber: rssi 0–31 соответствует -113…-51 dBm, 99 = не определяется (обычное дело сразу после включения — подождите несколько секунд). Замер: rssi 18–24 (-77…-65 dBm, хорошо); ber всегда 99, справочной ценности не имеет. Настоящую тройку качества LTE — RSRP (сила) / RSRQ (качество) / SINR (отношение сигнал/шум; низкое = помехи) — даёт только группа Signal URC (AT+QINDCFG="sqi" без значения = запрос состояния выключателя):

КнопкаКомандаДействие
LTE QualityAT+QINDCFG="sqi",1 Включает отчёты RSRP / RSRQ / SINR — незаменимо при тестах антенны и её размещения. Пуш приходит лишь при «изменении» сигнала; если тишина — оберните антенну рукой или передёрните её; настройка перезапуск не переживает
Signal PushAT+QINDCFG="csq",1 Отчёт при каждом изменении сигнала — вместо лихорадочного нажимания CSQ
URC Off / OnAT+QINDCFG="all",0/1 Мгновенно заглушить, когда заливает сообщениями — не забудьте потом включить обратно

Канал PDP: уровень 3GPP против страницы TCP/IP

PDP context = «канал данных», выделенный сотовой сетью; только с ним появляется IP. Эта группа — запросы стандартного уровня 3GPP только на чтение: AT+CGDCONT? перечисляет контексты и APN, AT+CGACT? — состояние активации (блокирует до 150 секунд; ⚠ у записывающей формы порядок параметров обратный), AT+CGPADDR — полученные IP. QIACT? / QICSGP со страницы TCP/IP — это собственный стек Quectel, не тот же уровень; сопоставив обе стороны, можно понять, где сбой: здесь IP есть, там нет = сеть выдала, но стек не запущен. Эта машина активирует PDP и получает IP автоматически при включении.

AT+QGDCNT? — накопленный трафик (первое число — отправлено, второе — принято); для замера трафика на роуминговой карте — обязательная команда. ⚠ Замер опровергает подсказку кнопки «накапливается через перезапуски»: по умолчанию счётчик в NV не сохраняется и обнуляется при снятии питания (включая перезагрузку страницы) — записывайте показания на месте либо сохраняйте в NV командой AT+QGDCNT=1.

Разбор из практики: эта карта допускает лишь один PDP

На странице TCP/IP нажали AT+QIACT=1, а в ответ ERROR (572,operation not allowed)? Постоянный сценарий этой карты: после включения уровень 3GPP уже автоматически активировал один PDP, но номер контекста плавает (замеры видели 1 и 9); попытка открыть второй возвращает +CME ERROR: 100 ⇒ сеть допускает лишь один PDP; а диапазон contextID у QIACT — только 1–8: когда PDP открыт на девятке, стек Quectel до него попросту не дотягивается. Решение в два шага (один раз после каждого включения):

AT+CGACT?             ← посмотреть, какой это cid (номер плавает, шаг не пропускать)
AT+CGACT=0,<тот cid>   ← уровень 3GPP освобождает место
AT+QIACT=1            ← страница TCP/IP; ответ +QIACT: 1,1,1,"10.187.7.8" = успех

Настройку APN через QICSGP для этой карты можно пропустить — по замеру модуль сам подхватывает APN, выданный сетью (iot.1nce.net); она обязательна лишь для корпоративных APN-карт с логином и паролем.

Посреди тестов вдруг всё стало отваливаться по таймауту? Первым подозревайте дрейф PDP. Замер: при сплошных провалах HTTP (ошибка 716, стабильный таймаут 30 секунд) AT+QIACT? как ни в чём не бывало возвращает IP — в этот момент он обманывает; сверяйте с AT+CGACT? (замер: 1,0 и 9,1 = уплыл на 9). Решение: AT+QIDEACT=1 → AT+CGACT=0,<уплывший cid> → AT+QIACT=1, затем проверить пингом.

Уровни функциональности CFUN и управление радиочастью

Вся группа RF Control меняет состояние модуля — это сплошь кнопки в красной рамке с подтверждением перед нажатием. Сначала нажмите AT+CFUN?, посмотрите текущий уровень и только потом действуйте:

КомандаУровеньЗначение
AT+CFUN=1Полная функциональность Радиочасть полностью включена; для восстановления всегда жмите эту
AT+CFUN=4Авиарежим Приём и передача выключены, SIM остаётся — отправная точка теста «повторного входа в сеть»
AT+CFUN=0Минимальный Отключается и SIM; в руководстве лишь Minimum functionality, без подробностей
AT+CFUN=1,1Мягкий перезапуск Перезапускает весь модуль. ⚠ AT-порт ненадолго умолкает — снова ждите RDY

CFUN блокирует до 15 секунд. Если на SIM стоит PIN, после возврата в CFUN=1 регистрация начнётся только после повторного ввода PIN. AT+CGATT=0 (PS Detach) отцепляет от пакетного домена — рушит все соединения TCP / MQTT; используйте только для теста «повторной привязки».

Продвинутое: QENG читает данные базовой станции (ввод в командной строке)

Кнопки на странице нет — наберите в командной строке AT+QENG="servingcell", чтобы прочитать параметры обслуживающей базовой станции; ключевые поля по замеру:

ПолеЗамерЧтение
MCC / MNC466 / 01Тайвань / FarEasTone
Cell ID / TACABCDE02 / 1234 (hex) В десятичном виде 180149762 / 4660; eNodeB = ECI≫8 = 703710, сектор = 2
PCID / EARFCN144 / 1550 Физический идентификатор соты (не уникален глобально) / Band 3
RSRP / RSRQ / RSSI / SINR-113 / -18 / -92 / -1 RSRP ниже -100 считается плохим; SINR -1 dB = качество неважное
Cell ID и TAC — шестнадцатеричные; перед запросом к базам данных обязательно переведите в десятичные. OpenCelliD и подобные базы принимают только десятичные числа: бросьте туда ABCDE02 как есть — и получите «не найдено». Кроме того, AT+QENG="neighbourcell" возвращает только PCID, без глобального Cell ID (ограничение стандарта LTE).
