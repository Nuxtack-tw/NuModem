TCP/IP — Akar Koneksi Data

Cara kerja: halaman ini adalah fondasi semua protokol data. PDP context (kanal data yang dijatahkan jaringan seluler) hanya diaktifkan dan dinonaktifkan di halaman ini; halaman SSL / HTTP / MQTT / FTP hanya menaruh query baca-saja, agar perintah yang sama tidak saling injak di dua tempat. Jebakan dan angka detik pada bagian ini semuanya hasil uji perangkat nyata pada Agustus 2026.

Langkah pertama: aktifkan PDP (QICSGP / QIACT / QIDEACT)

Tekan Act PDP (AT+QIACT=1): memblokir maksimum 150 detik; selama itu jangan kirim perintah lain; sejak titik ini kuota mulai terpakai (kartu roaming: perhatikan biaya). Setelah berhasil, wajib tekan Query IP (AT+QIACT?) dan pastikan balasannya +QIACT: 1,1,1,"alamat IP" — sebelum aktif ia hanya membalas OK. Untuk menutup, tekan Deact PDP (AT+QIDEACT=1, maksimum 40 detik); ia memaksa menutup semua koneksi di bawahnya. Set APN (AT+QICSGP) biasanya tak perlu ditekan — modul otomatis menyinkronkan APN yang dijatahkan jaringan (hasil uji: kartu 1NCE begitu boot sudah terbaca iot.1nce.net); baru perlu untuk APN korporat yang butuh akun-sandi.

Act PDP membalas ERROR, Last Error 572? Kartu ini hanya mengizinkan satu PDP. Saat boot jaringan sudah otomatis mengaktifkan satu, dan nomornya mengambang (pengujian pernah melihat 9 dan 1), sedangkan AT+QIACT hanya bisa menyentuh 1–8. Solusi: di halaman Network jalankan AT+CGACT? untuk melihat nomornya → AT+CGACT=0,<nomor> untuk melepaskan jatah → baru tekan Act PDP.

Di tengah pengujian semuanya roboh? AT+QIACT? bisa menipu — saat PDP hanyut ia tetap membalas IP; hanya dengan silang-periksa AT+CGACT? barulah kelihatan. Pemulihan: Deact PDP → AT+CGACT=0,<nomor hanyut> → Act PDP → verifikasi dengan Ping.

Membuka koneksi: OK hanya berarti "perintah diterima"

Tekan Open TCP, isi host dan port di kartu parameter (AT+QIOPEN=1,0,"TCP","host",port,0,0; context 1, connectID 0, mode buffer sudah dipatok). OK hanya berarti perintahnya diterima; berhasil-gagalnya lihat URC +QIOPEN: 0,<err>: 0 = berhasil, maksimum 150 detik; 563 = connectID masih terbuka, tekan dulu Close Sock. All Socks (AT+QISTATE) menampilkan semua socket, state 2 = sudah tersambung.

Mengirim data: tiga cara

TombolPenjelasan
Send Text
AT+QISEND=0,<len>		 Dua tahap panjang-tetap: tunggu > baru kirim isinya, panjang dihitung otomatis, bebas Ctrl+Z. Pilihan utama untuk teks murni; batas 1460 bytes, mendukung escape \n \r \t \xHH
Tiga tombol Send Var
AT+QISEND=0		 Bentuk panjang-variabel: masuk mode data dan terus menampung, baru terkirim saat melihat Ctrl+Z (0x1A) — bisa ditulis bertahap, lihat paragraf berikut
Send Hex
AT+QISENDEX=0,"hex"		 Bentuk satu baris, tidak masuk mode data. Bisa mengirim byte apa pun (termasuk 0x00); batas hex 512 karakter = 256 bytes sesungguhnya

Kirim (tulis lanjutan): tekanan pertama masuk mode data, tekanan berikutnya menambahkan satu potongan (bila sudah di mode data, perintah tidak dikirim ulang — mengirim ulang akan berubah jadi data); Kirim lalu akhiri otomatis menambahkan potongan dan menutup dengan Ctrl+Z, tercepat bila hanya satu potongan; Akhiri (Ctrl+Z) mengirimkan seluruh isi yang terkumpul sekaligus. Saat di mode data, terminal memberi penanda; untuk menyerah tekan ESC Cancel (0x1B, kunci pelarian saat perintah dua tahap tersangkut). ⚠ Data tak boleh mengandung 0x1A (akan dianggap pengakhiran dini); untuk karakter kendali pakai Send Hex.

SEND OK bukan berarti lawan sudah menerima; ia hanya menandakan data sudah diserahkan ke modul. Tekan Check ACK (AT+QISEND=0,0) untuk melihat terkirim / ter-ACK — hanya acked yang bisa dipegang.

Menerima data: tak muncul sendiri, harus tekan Read Data

Pada mode buffer, data yang diterima tidak otomatis tampil di terminal: modul hanya mengirim notifikasi +QIURC: "recv",0; Anda harus menekan Read Data (AT+QIRD=0,1500) untuk mengambilnya, dan ulangi membaca sampai membalas +QIRD: 0 — bila tak dibaca sampai bersih, notifikasi berikutnya takkan datang. Unread Len (AT+QIRD=0,0) menanyakan total diterima / sudah dibaca / belum dibaca. Selesai kirim-terima, tekan Close Sock (AT+QICLOSE=0, maksimum 10 detik). ⚠ Notifikasi recv sama sekali tak diterima? Di halaman Hardware periksa apakah AT+QURCCFG="urcport" sudah uart1 — nilai pabrik adalah port USB; semua URC lari ke sana.

Dua tabiat lawan bawaan tcpbin.com

Lawan default Open TCP adalah server echo gratis tcpbin.com:4242; dua tabiat hasil uji:

  • Echo per baris, akhirnya harus newline (0A): mengirim Hello tanpa 0A, ditunggu 6 detik tanpa balasan; setelah ditambah 0A, 0.1 detik langsung diterima. Send Text: tambahkan \n di akhir; Send Hex: tambahkan 0A di ekor.
  • Timeout idle 15 detik: begitu menganggur, koneksi diputus dan Anda menerima +QIURC: "closed",0. Ini tak ada hubungannya dengan QIRD (ia hanya membaca buffer lokal, tak menyentuh jaringan). Untuk mempertahankan koneksi, kirim data setiap kurang dari 10 detik. Setelah closed, socket berhenti di closing; wajib tekan Close Sock dulu baru bisa dipakai lagi, kalau tidak QIOPEN membalas 563.

Terjadi error: tekan dulu Last Error, lalu lakukan pembedaan 30 detik

Begitu perintah membalas ERROR, segera tekan Last Error (AT+QIGETERROR) — hanya error terakhir yang disimpan; begitu tertimpa error berikutnya, tak bisa dicari lagi. Ia memeriksa lapisan stack Quectel; untuk lapisan jaringan pakai AT+CEER di halaman Network.

🔴 Degradasi stack data — lubang paling menyita waktu. Gejala: semua koneksi gagal tanpa kecuali, tetapi swaperiksa bilang semuanya baik (QIACT? ada IP, QIGETERROR membalas 0). Hasil uji: terpicu setelah membuka-menutup SSL sekitar 20 kali beruntun; bahkan QIOPEN TCP murni pun membalas 552; QIDEACT + QIACT tak menyelamatkan, hanya menjalankan ulang ritual boot yang memulihkan.

Metode pembedaan 30 detik: pakai Open TCP menembak target yang sama — ikut gagal = seluruh stack rusak, jalankan ulang ritual boot; berhasil = masalahnya di protokol lapisan atas, lanjutkan menelusur.

Keepalive: sanggup menahan NAT operator, tak sanggup menahan tcpbin

QICFG=? menampilkan subitem dan rentangnya, Keepalive? menanyakan nilai kini, Keepalive On / Off sakelarnya — keempat perintah ini sendirinya nol kuota; setelah aktif, selama ada socket yang menganggur, paket probe terhitung ke kuota seluler. Ia tak sanggup menahan timeout 15 detik tcpbin: hasil uji, meski dinyalakan tetap diputus pada detik 15.1 — keepalive adalah probe kosong lapisan TCP yang tak terlihat aplikasi; lagi pula interval minimumnya 25 detik, memang lebih besar dari 15. Untuk bertahan dari timeout lapisan aplikasi, satu-satunya cara adalah mengirim data sungguhan (misalnya tiap 10 detik Send Hex mengirim 0A). Kegunaan sejatinya adalah menjaga hidup NAT operator (NAT kartu IoT menganggur beberapa menit langsung didaur ulang).

Hitungan kuota (estimasi, bukan hasil uji): satu probe pulang-pergi sekitar 80 bytes; default idle = 30 detik menganggur terus-menerus → per jam sekitar 9.4 KB, sehari sekitar 225 KB, sebulan sekitar 6.8 MB; idle = 600 detik → sehari sekitar 11 KB. Kartu prabayar berkuota total seperti 1NCE harus memperbesar idle. Tanpa socket terbuka, sama sekali tak makan kuota.
