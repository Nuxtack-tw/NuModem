Hardware — включение и последовательный порт

Принцип работы: эта страница — фундамент всего инструмента: Control — две кнопки ритуала включения (Power / Reset), Module — идентификация изделия, Serial — настройки UART, Power — низкое энергопотребление, URC задаёт порт вывода самопроизвольных сообщений модуля, и есть ещё ряд кнопок сырых байт — аварийный выход из режима данных. Все остальные вкладки опираются на два условия: модуль включён по ритуалу и URC идут через uart1 — и то и другое делается на этой странице. Всё поведение и все числа в этом разделе — реальные замеры на физическом EG800K в августе 2026 года.

Зачем нужен ритуал включения: RTS = питание, DTR = Reset

Плата управления, с которой работает этот инструмент, использует два сигнала квитирования RS-232 не по назначению — это ключ к пониманию всей страницы:

СигналКуда подключён на самом делеЛогика
RTSВыключатель питания модуля Инверсная логика: RTS OFF = питание подано, RTS ON = питание снято
DTRНожка Reset модуля DTR ON = Reset поднят (можно запускать), DTR OFF = Reset прижат

Особенность схемы (подтверждена замером): при первом подключении RTS должен пройти сначала ON, потом OFF — только тогда питание действительно включится; установка сразу в OFF подачу питания не гарантирует. DTR тоже должен пройти ON→OFF→ON, иначе Reset по-настоящему не поднимется. Снятие питания (RTS ON) — жёсткий обрыв: модуль не отправляет никакого прощального сообщения.

Перезагрузка страницы = снятие питания. Когда браузер заново открывает последовательный порт, он заново поднимает RTS, и модуль тут же теряет питание — после автоматического переподключения ритуал включения нужно прогнать заново. Проверено на себе: пропустив ритуал, отправили 17 команд подряд — все ушли в никуда (только строки TX, ноль RX). Любое «только что всё работало, а теперь никакой реакции» — сначала вспомните об этом.

Кнопки Power и Reset: как нажимать и что вы увидите

Эти две кнопки — воплощение двух сигналов из таблицы выше; они двусторонне связаны с индикаторами RTS / DTR в панели сигналов (пока порт не подключён, кнопки погашены и не нажимаются). Web Serial не позволяет прочитать реальное состояние выходных сигналов: панель сигналов показывает то значение, которое отправил сам инструмент.

  1. Power (переключатель): горит зелёным = питание ON (= RTS OFF). Ритуал включения требует прогнать RTS через ON→OFF: если кнопка уже горит, сначала выключите, затем включите.
  2. Reset (momentary): нажатие = DTR OFF, отпускание = DTR ON; одно нажатие с отпусканием — это один Reset (в стандартной последовательности пауза 0.3 секунды).
  3. Дождитесь RDY: через несколько секунд в терминале появится стартовое объявление модуля RDY.
  4. Проверка ATI: должно вернуться Quectel / EG800K / Revision: … / OK. Если ответ пришёл — и UART, и модуль живы.
После включения сначала убедитесь, что эхо (ATE) включено (заводское значение — включено), затем отправьте AT+CMEE=2 — без него вы будете видеть лишь сухое ERROR, а с ним — читаемый текст +CME ERROR: …. Обе настройки действуют только в пределах сессии: после каждого перезапуска модуля их нужно задавать заново.

Serial: AT&V читает параметры, IPR меняет скорость

AT Params (AT&V): перечисляет текущие значения всех однобуквенных AT-параметров. У однобуквенных команд вроде ATE / ATQ / ATV нет собственных форм запроса — прочитать их можно только этой командой. Замер на этой машине: E:1 Q:0 V:1 S3:13 S4:10 — эхо включено, коды результата в текстовом виде, конец строки = CR (ASCII 13); именно на этих условиях инструмент разбирает ответы.

Baud? (AT+IPR?): текущая скорость UART, с завода 115200.
Baud List (AT+IPR=?): возвращает два списка — первый — скорости с автоопределением, второй — доступные только в фиксированном режиме. После этой кнопки выпадающий список Set Baud заменяется на список, реально сообщённый этой машиной. По замеру второй список на этой машине доходит до 1000000 bps — в таблице §3.4 руководства этого значения нет.

Set Baud (AT+IPR={rate};&W, карточка с параметрами): при нажатии сначала появляется окно подтверждения — это кнопка, которой проще всего запереть себя снаружи.

Тройная ловушка смены скорости (все три подтверждены замером):
① Как только пришёл OK, новая скорость действует немедленно — со следующего мгновения инструмент и модуль говорят на разных языках;
② AT&F (заводской сброс) скорость не возвращает — не надейтесь, что он вас спасёт;
③ Без &W значение не сохраняется — а переподключение = снятие питания: модуль проснётся на старой скорости, тогда как настройка вашего порта останется на новой — двойная потеря связи. Поэтому инструмент принудительно использует связку ;&W.
Восстановление в четыре шага (окно подтверждения тоже о них напомнит): отключиться → сменить скорость в блоке подключения → переподключиться → заново выполнить ритуал включения.

Power: низкое энергопотребление QSCLK

Sleep? (AT+QSCLK?): разрешён ли модулю переход в сон. Замер на этой машине: с завода 0 = запрещено, модуль всегда бодрствует. На этой странице есть только кнопка запроса: заснувший модуль перестаёт отвечать на AT, а способ пробуждения по руководству — прижать DTR, но на этой плате DTR уже занят под ножку Reset (см. начало раздела). Если вы сами включили сон через командную строку и модуль не будится, выход — заново прогнать ритуал включения (снять и подать питание); подробности в официальной записке по низкому энергопотреблению.

URC: если сообщения не приходят — сначала сюда

URC (Unsolicited Result Code, самопроизвольный код результата) — сообщение, которое модуль «выдаёт сам, без запроса»; это не ответ ни на какую команду: стартовое RDY, приход данных TCP, сообщения MQTT, результаты сканирования Wi-Fi, уведомление о загрузке прошивки GNSS — всё это URC. Порт их вывода с завода — USB-порт (usbat), и работающий через UART инструмент не получит ни одного; симптом очень характерный: все команды отвечают OK, но сообщений не дождаться.

КнопкаКомандаНазначение
URC Port?AT+QURCCFG="urcport" Куда сейчас отправляются URC — если URC не приходят, первым делом запросите это; сообщения появятся, только если возвращается "uart1"
URC PortsAT+QURCCFG=? Какие порты вывода поддерживает эта машина. Замер: ("usbat","usbmodem","uart1"), без упомянутого в руководстве "all" (в руководстве есть примечание, что часть моделей его не поддерживает)
URC → UARTAT+QURCCFG="urcport","uart1" Переключить на основной UART. Пишется в NVRAM, переживает перезапуски — достаточно сменить один раз
URC SwitchAT+QINDCFG="all" Главный выключатель URC — вторая крупная причина «URC не приходят». Замер: на этой машине с завода 1 (включено); почти всегда дело в порте вывода

Кнопки сырых байт: аварийный выход из режима данных

Немало команд — двухэтапные: сначала отправляется команда, ожидается подсказка > от модуля, затем отправляется тело. Попав в такой режим данных, модуль глотает как данные каждый введённый вами символ — включая AT-команды, которые вы хотели бы отдать. Когда длина посчитана неверно, вы передумали на полпути или команда зависла, обычные кнопки не спасают — выручает этот ряд кнопок, отправляющих одиночные сырые байты:

КнопкаОтправляетКогда использовать
Ctrl+Z0x1A Завершающий символ режима данных: реально отправить всё накопленное
ESC0x1B Отменить режим данных и выбросить накопленное. Первый выбор, когда двухэтапная команда зависла и AT-порт перестал отвечать (руководство §2.3.8)
+++Три знака + (сырые байты) Побег из прозрачного режима данных (например, передача COM: в FTP) обратно в режим AT. Правила жёсткие: по 1 секунде тишины до и после, и никаких CR/LF — по замеру с добавленным CR не срабатывает; отправлять только этой кнопкой, а не набирать в командной строке
Замер опровергает руководство: +++ — это «прервать», а не «приостановить». Записка по FTPS v1.5 на странице 13 говорит, что после +++ можно вернуться в режим данных командой ATO и продолжить передачу; на реальной машине ATO отвечает лишь NO CARRIER — передача уже прервана. Считайте +++ аварийным тормозом и не рассчитывайте после него поехать дальше.

Устранение неполадок

СимптомПричина и решение
Ни одна команда не отвечает Проверьте трёх подозреваемых по порядку: ① не выполнен ритуал включения (если страница перезагружалась — это точно он); ② конец строки выставлен в LF — модуль признаёт только CR, на LF ответа нет вовсе; ③ не совпадает скорость (см. восстановление в четыре шага)
Нажали Reset, но RDY не приходит Сначала посмотрите, горит ли кнопка Power — без питания жмите Reset сколько угодно, толку не будет; при первом подключении питание должно пройти через ON→OFF
Команды отвечают OK, а URC всё не приходят Восемь шансов из десяти, что urcport всё ещё в заводском usbat: нажмите URC Port? для запроса и URC → UART для смены; если не помогло — проверьте главный выключатель URC Switch
AT-порт внезапно «глотает команды», ни на что не отвечает Вы застряли в режиме данных, и весь ввод принимается как данные — жмите ESC и выбирайтесь
