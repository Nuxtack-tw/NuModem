Basic — SIM, diagnostics and basic status

Working principle: this page is the starting point after every connection. Once the power-up ritual is done and the terminal shows RDY, come here first to do three things: switch error messages to a readable format, confirm the SIM is ready, and identify whose card this is. Except for AT&F and PIN / PUK unlocking, the entire page is read-only queries — clicking them does not change the module's state; the commands that touch connection state live in the Network, TCP/IP and other tabs. All samples in this section are values measured in August 2026 on a physical EG800K (firmware EG800KCNGCR07A06M04).

After power-up: RDY does not mean the SIM is ready

RDY is the URC the module sends on its own when it finishes booting. It only means the AT interface is alive; the SIM card is still slowly initializing behind it. Measured: sending SIM-related commands the moment RDY appears returns +CME ERROR: 14 (SIM busy) or even +CME ERROR: 13 (SIM failure); wait about 6 seconds and everything works.

When writing automation scripts, do not treat RDY as the "clear to start" signal. Pick one of two correct approaches: leave a fixed buffer of about 6 seconds after RDY; or poll AT+QINISTAT and proceed only once bit 1 (CPIN ready) is set.

Echo (ATE): "module echo" and "terminal local echo" are two different things

Echo is the module sending back verbatim the characters you sent it (ATE1 on, ATE0 off); the terminal's local echo is the tool side printing what you type onto the screen itself. The two switches are independent: with both on, every character appears twice.

  • This page's echo toggle button switches module echo with a single click. The boot default is on (corroborated by the measured AT parameter E:1).
  • The state shown on the button is not remembered out of thin air — the tool self-corrects from the actual responses (receiving an echoed line counts as on); if you hand-type ATE0 / ATE1 / AT&F on the command line, the button's state follows along and never drifts.
  • The toggle is session-only: a module restart returns it to the default. To make it the boot default you must also send AT&W (this page has no button for it; hand-type it on the command line if needed).

Making error messages readable (CMEE)

ButtonEffect
Verbose Err
AT+CMEE=2		 Error codes become text descriptions. Example: with GNSS not yet fixed, numeric mode returns +CME ERROR: 516, text mode returns DSAT_CME_GNSS_NOT_FIXED_NOW — the latter tells you what happened without a lookup table. This tool strongly recommends clicking it right after the power-up ritual
Numeric Err
AT+CMEE=1		 Error codes as numbers — the tool automatically looks up the code and annotates it
Both settings are session-only: gone once the modem restarts (a page reload = RTS power cut = a restart, which also counts). Also found in testing: even with CMEE=2 on, a few subsystems (such as file-system FILE errors) still emit a mix of text and numbers — a parser must accept both forms.

AT&F: back to factory defaults — the scope

The Factory Reset button resets the AT settings to factory values, the first step when taking over a module someone has misconfigured. It is the only button on this page that asks for confirmation first. Scope confirmed by testing: it sets echo back to on (the echo toggle button's state follows automatically) and does not affect the baud rate; whether each remaining setting is restored, check item by item under the AT&F entry in the manual.

The SIM triple check: is it there, is it waiting for a password, how far has it initialized

ButtonThe question it asksHow to read it
Card In?
AT+QSIMSTAT?		 Is the card seated properly The reply has two fields: the first is the insert/remove URC switch, the second is the card state — do not read the wrong field. On this unit this button has a record of false reports; see the warning below
SIM PIN
AT+CPIN?		 Is the card waiting for a password +CPIN: READY = "not currently waiting for any password". ⚠ It does not mean this card needs no PIN — a PIN-protected card also returns READY once unlocked. With no card it returns +CME ERROR: 10
Init State
AT+QINISTAT		 Initialization progress A bitmask: 1 = CPIN ready, 2 = SMS, 4 = phonebook, 7 = all done. Measured on this unit once boot settles: 3 (phonebook bit never set) — to decide "can I start", bit 1 is enough; do not wait forever for 7
Card In? lies on this unit. Measured: AT+QSIMSTAT? returned 0,0 (card removed), yet at the same moment CPIN was READY, the network attached, and an IP obtained — the card was perfectly fine. Presumably the control board does not wire the SIM_DET detect pin (or AT+QSIMDET is not enabled), so the reading is permanently "not inserted". To decide whether the card is present, trust AT+CPIN? or AT+QINISTAT.

Whose card is this: IMSI and ICCID

The IMSI button (AT+CIMI) returns a string of bare digits, the card's subscriber identity on the mobile network. Measured on this unit: 901405117661468 — the first three digits (MCC) are 901 = the international roaming number range. This unit's card is a 1NCE IoT SIM, which also explains why AT+CEREG? keeps returning 0,5 (registered, roaming): not a signal anomaly, but the norm for this kind of card. Recognize a roaming card before running data tests, and mind the data pricing.

The ICCID button (AT+QCCID) queries the card's serial number; measured reply +QCCID: 89882280666176614687. ⚠ The manual has no AT+CCID command — the one common in other vendors' modem tutorials does not work here; use Quectel's own AT+QCCID.

PIN unlocking: check the remaining attempts first, then act

  1. Click PIN Left first (AT+QPINC?) to see the remaining attempts — the manual's ranges: PIN 0–3 attempts left, PUK 0–10 attempts left. Know how many shots you have before you act.
  2. When the card is waiting for a PIN, click Enter PIN: it first expands a parameter card for you to fill in the PIN before sending (command template AT+CPIN="{pin}", waits up to 5 seconds).
  3. When the PIN attempts are exhausted and the card demands a PUK, click Unlock PUK: the manual requires the PUK to be sent together with a new PIN (AT+CPIN="{puk}","{newpin}"), likewise via the parameter card, waiting up to 5 seconds.
Every wrong attempt costs one; when the PUK runs low, stop and contact the carrier — do not burn through the attempts by guessing.

The three status buttons: clock, voltage, network time

ButtonWhat it showsMeasured values and how to read them
Clock
AT+CCLK?		 The module's RTC clock +CCLK: "26/08/01,00:55:32+32". The time-zone field +32 is in quarter-hours (15 minutes): 32 × 15 min = UTC+8. Measured on this unit, the RTC had already been synced by the network; time and zone both correct
Battery
AT+CBC		 Supply voltage Some firmware does not support it and an ERROR reply is normal; this unit's firmware does — measured +CBC: 0,0,4264, where the last field is the voltage (mV), i.e. 4.264 V
Net Time
AT+QLTS=2		 Current local time derived from network sync Measured +QLTS: "2026/08/02,11:46:47+32,0". The difference from Clock is the source: CCLK reads the module's own RTC, QLTS takes the network time directly; the year format also differs (RTC two digits, QLTS four) — do not confuse them when parsing

Troubleshooting

SymptomCause and fix
Querying the SIM right after RDY returns error 14 or 13 The SIM is still initializing (14 = SIM busy; 13 = SIM failure has also appeared at this stage). Wait about 6 seconds and resend — do not rush to declare the card dead
Card In? says the card was removed, yet everything else works A SIM_DET detect-pin issue (measured case on this unit), not a card problem. Look at AT+CPIN? / AT+QINISTAT instead
Every character appears twice on screen Module echo and the terminal's local echo are both on — one click of the echo toggle button fixes it
Errors come back as cold bare numbers CMEE is not on yet. Click Verbose Err; it is session-only and must be re-clicked after every power-up ritual
Commands go out and get no response at all Reopening the port re-asserts RTS = a power cut; the module has in fact rebooted. You must rerun the full power-up ritual — skip it and nothing responds
