FTP —— 檔案傳輸

工作原理：FTP 有兩條通道：控制通道走命令， 資料通道走檔案內容。理解這件事，很多怪現象就解釋得通了。

AT+QFTPCFG="account","帳號","密碼"
AT+QFTPCFG="transmode",1      ← 1 ＝ 被動模式（NAT 後方必用）
AT+QFTPOPEN="主機",21          ← 等 +QFTPOPEN: 0,0
AT+QFTPPUT="檔名","COM:",0,<長度>,1   ← CONNECT → 送資料
AT+QFTPGET="檔名","COM:"       ← CONNECT → 資料直接印出
AT+QFTPCLOSE                  ← ⚠ 見下
🔴 AT+QFTPCLOSE 是非同步的 —— OK 不代表關好了。 必須等到 +QFTPCLOSE: 0,0 才算完成。 期間狀態是 3（關閉中），這時下任何 FTP 指令一律回 +CME ERROR: 603。

症狀極具誤導性：一連串 603 看起來像模組壞了或被伺服器擋， 實際上只是關閉還沒完成。
回應意思
+QFTPSIZE: 627,550 兩層錯誤碼：模組層 627（未執行請求的動作）＋ FTP 協定層 550（檔案不存在）
+CME ERROR: 615 開資料連線失敗。特徵是控制通道正常、資料通道全滅。 一旦發生，後續全部 603 直到正確關閉
+QFTPSTAT: 0,11 ＝ 閒置、2 ＝ 傳輸中、3 ＝ 關閉中
⚠ +++ 對 FTP 是「中止」不是「暫停」。 手冊（FTP(S) AN v1.5 p13）寫 ATO 可以重入資料模式續傳， 實測不成立：逃逸後 AT+QFTPSTAT 回 1（閒置）而不是 2（傳輸中）， ATO 回 NO CARRIER。 所以 +++ 只能用來從失控的資料模式脫身，不能拿來暫停大檔下載。

正確下法：前後各靜默 1 秒、不加 CR。
