TCP/IP — The root of every data connection

Working principle: this page is the foundation of every data protocol. The PDP context (the data channel allocated by the cellular network) is activated and deactivated only on this page; the SSL / HTTP / MQTT / FTP pages carry read-only queries only, so the same command never gets driven from two places at once. All traps and timings in this section were measured on the real device in August 2026.

Step one: activate the PDP (QICSGP / QIACT / QIDEACT)

Click Act PDP (AT+QIACT=1): it can block up to 150 seconds — send no other commands meanwhile — and from here on data charges begin (mind roaming costs). After success always click Query IP (AT+QIACT?) and confirm it returns +QIACT: 1,1,1,"IP address" — before activation it returns only OK. To hang up, click Deact PDP (AT+QIDEACT=1, up to 40 seconds), which force-closes every connection under it. Set APN (AT+QICSGP) is normally unnecessary — the module auto-syncs the network-assigned APN (measured: the 1NCE card already read back iot.1nce.net at boot); only enterprise APNs with credentials need it.

Act PDP returns ERROR, Last Error 572? This card allows only one PDP. At boot the network has already auto-activated one, and its number drifts (both 9 and 1 seen in testing), while AT+QIACT can only reach 1–8. Fix: on the Network page, AT+CGACT? to find the number → AT+CGACT=0,<number> to give up the slot → click Act PDP again.

Everything dies mid-test? AT+QIACT? lies — during PDP drift it still returns an IP; only a cross-check against AT+CGACT? reveals it. Recovery: Deact PDP → AT+CGACT=0,<drifted number> → Act PDP → verify with Ping.

Opening a connection: OK only means "command accepted"

Click Open TCP and fill host and port in the parameter card (AT+QIOPEN=1,0,"TCP","host",port,0,0; context 1, connectID 0 and buffer mode are fixed). OK only means the command was accepted; success or failure comes in the URC +QIOPEN: 0,<err>: 0 = success, up to 150 seconds; 563 = the connectID is still open — click Close Sock first. All Socks (AT+QISTATE) lists every socket; state 2 = connected.

Sending data: three ways

ButtonDescription
Send Text
AT+QISEND=0,<len>		 Fixed-length two-stage: wait for >, then send the payload; the length is computed automatically, no Ctrl+Z needed. First choice for plain text; limit 1460 bytes, supports \n \r \t \xHH escapes
The three Send Var buttons
AT+QISEND=0		 Variable-length: enters data mode and keeps receiving until Ctrl+Z (0x1A) sends it off — can be written in installments, see the next paragraph
Send Hex
AT+QISENDEX=0,"hex"		 Single-line, no data mode. Can send arbitrary bytes (0x00 included); hex limit 512 characters = 256 actual bytes

Send (append): the first click enters data mode, each later click appends another chunk (while already in data mode the command is not re-sent — re-sending it would become data); Send then auto-finish appends and adds the Ctrl+Z, fastest when sending a single chunk; Finish (Ctrl+Z) sends the accumulated content in one go. The terminal flags data mode while you are in it; to abandon, click ESC Cancel (0x1B, the escape key when a two-stage command jams). ⚠ The data must not contain 0x1A (it would be taken as an early finish); for control characters use Send Hex instead.

SEND OK does not mean the peer received it — only that the data was handed to the module. Click Check ACK (AT+QISEND=0,0) to see sent / ACKed; only acked counts.

Receiving data: it does not appear by itself — click Read Data

In buffer mode, received data does not appear in the terminal on its own: the module only issues a +QIURC: "recv",0 notice, and you must click Read Data (AT+QIRD=0,1500) to fetch it, repeating until it returns +QIRD: 0 — until the buffer is drained there will be no next notice. Unread Len (AT+QIRD=0,0) shows total received / read / unread. When done, click Close Sock (AT+QICLOSE=0, up to 10 seconds). ⚠ No recv notices at all? On the Hardware page check whether AT+QURCCFG="urcport" is uart1 — the factory value is the USB port, and all URCs go there.

The two quirks of the built-in peer tcpbin.com

Open TCP's default peer is the free echo server tcpbin.com:4242, with two measured quirks:

  • Line-by-line echo; the line must end with a newline (0A): Hello without 0A got no reply after 6 seconds; with the 0A added, the echo arrived in 0.1 seconds. Append \n with Send Text, or a trailing 0A with Send Hex.
  • 15-second idle timeout: idle connections get dropped with a +QIURC: "closed",0. This has nothing to do with QIRD (it only reads the local buffer, it never touches the network). To keep the connection, send real data at least every 10 seconds. After closed, the socket sits in closing — you must click Close Sock first before reuse, or QIOPEN returns 563.

When it goes wrong: click Last Error first, then the 30-second triage

The moment a command returns ERROR, click Last Error (AT+QIGETERROR) immediately — only the last one is kept, and once the next error overwrites it, it is gone. It queries the Quectel stack layer; for the network layer use the Network page's AT+CEER.

🔴 Data-stack degradation — the most time-consuming pit. Symptom: every connection fails, yet every self-check says all is well (QIACT? has an IP, QIGETERROR returns 0). Measured: triggered after about 20 consecutive SSL open/close cycles, after which even plain-TCP QIOPEN returned 552; QIDEACT + QIACT cannot save it — only rerunning the power-up ritual recovers.

The 30-second triage: hit the same target with Open TCP — if that fails too, the whole stack is broken, rerun the power-up ritual; if it succeeds, the problem is in the upper protocol — keep digging.

Keepalive: holds off carrier NAT, cannot hold off tcpbin

QICFG=? lists the sub-items and ranges, Keepalive? reads the current value, Keepalive On / Off toggles it — these four commands themselves cost zero data; once enabled, as long as any socket sits idle, the probe packets count against your mobile data. It cannot hold off tcpbin's 15-second timeout: measured, even enabled, the drop still came at 15.1 seconds — keepalive is a TCP-layer empty probe invisible to the application; and the minimum interval is 25 seconds, already larger than 15. To survive an application-layer timeout you must send real data (e.g. Send Hex a 0A every 10 seconds). Its real purpose is carrier NAT keep-alive (IoT-card NAT entries get reclaimed after a few idle minutes).

The data bill (estimated, not measured): one probe round trip is about 80 bytes; default idle = 30 seconds of continuous idling → about 9.4 KB per hour, about 225 KB per day, about 6.8 MB per month; idle = 600 seconds → about 11 KB per day. Prepaid total-volume cards like 1NCE should raise the idle value. With no socket open, it costs nothing at all.
