Hardware — Boot dan Port Serial

Cara kerja: halaman ini adalah fondasi seluruh alat: Control berisi dua tombol ritual boot (Power / Reset), Module untuk identifikasi produk, Serial untuk setelan UART, Power untuk mode hemat daya, URC mengatur port keluaran pesan yang dikirim modul atas inisiatifnya sendiri, plus satu deret tombol byte mentah (Ctrl+Z / ESC / +++) sebagai pintu darurat mode data. Semua tab lain berdiri di atas dua prasyarat: modul sudah di-boot sesuai ritual dan URC keluar lewat uart1 — keduanya diselesaikan di halaman ini. Perilaku dan angka pada bagian ini semuanya hasil pengujian nyata terhadap EG800K fisik pada Agustus 2026.

Mengapa perlu ritual boot: RTS = daya, DTR = Reset

Papan kendali yang menyertai alat ini mengalihfungsikan dua sinyal handshake RS-232; ini kunci untuk memahami seluruh halaman:

SinyalTerhubung keLogika
RTSSakelar daya modul Logika negatif: RTS OFF = daya menyala, RTS ON = daya putus
DTRPin Reset modul DTR ON = Reset ditarik tinggi (bisa boot), DTR OFF = Reset ditarik rendah

Karakteristik rangkaian (terkonfirmasi lewat pengujian): pada koneksi pertama, RTS harus ON dulu baru OFF agar daya benar-benar menyala — langsung menyetel OFF tidak menjamin daya masuk; DTR juga harus melewati ON→OFF→ON agar Reset benar-benar tertarik tinggi. Pemutusan daya (RTS ON) adalah pemutusan keras; modul tidak mengirim pesan perpisahan apa pun.

Me-refresh halaman = daya putus. Saat browser membuka ulang port serial, RTS ditarik naik lagi dan modul langsung kehilangan daya — setelah penyambungan ulang otomatis selesai, ritual boot wajib dijalankan ulang. Pernah dialami dalam pengujian: ritual dilewati lalu 17 perintah dikirim, semuanya pergi tanpa kembali (hanya baris TX, nol RX). Setiap kali "tadi masih normal, sekarang tak ada respons sama sekali", pikirkan hal ini lebih dulu.

Tombol Power dan Reset: cara menekannya, apa yang akan terlihat

Kedua tombol ini adalah penjelmaan dua sinyal pada tabel di atas, dan tersinkron dua arah dengan indikator RTS / DTR di baris sinyal (saat belum tersambung tombol redup dan tak bisa ditekan). Web Serial tidak bisa membaca status nyata sinyal keluaran; yang ditampilkan baris sinyal adalah nilai yang diyakini alat ini berdasarkan apa yang telah dikirimnya.

  1. Power (tipe sakelar): hijau menyala = daya ON (= RTS OFF). Ritual boot mengharuskan RTS melewati ON→OFF: bila tombol sudah menyala, klik mati dulu baru klik nyala.
  2. Reset (momentary): ditekan = DTR OFF, dilepas = DTR ON; sekali tekan-lepas adalah satu kali Reset (urutan waktu standar berhenti 0.3 detik di tengah).
  3. Tunggu RDY: dalam beberapa detik terminal akan menampilkan pengumuman boot modul RDY.
  4. Verifikasi dengan ATI: seharusnya membalas Quectel / EG800K / Revision: … / OK. Bila balasannya keluar = UART dan modul sama-sama hidup.
Setelah boot, disarankan memastikan dulu echo (ATE) menyala (default pabrik menyala), lalu kirim AT+CMEE=2 — tanpa itu Anda hanya melihat ERROR yang kering; dengan itu barulah muncul teks terbaca berupa +CME ERROR: …. Keduanya hanya berlaku per sesi; setiap kali modul dinyalakan ulang, keduanya harus dikirim lagi.

TombolPerintahApa yang akan terlihat

Serial: AT&V membaca parameter, IPR mengubah baud rate

AT Params (AT&V): menampilkan nilai terkini semua parameter AT satu huruf. Perintah satu huruf seperti ATE / ATQ / ATV tidak punya bentuk query masing-masing; hanya perintah inilah yang bisa membacanya. Hasil uji perangkat ini: E:1 Q:0 V:1 S3:13 S4:10 — echo menyala, kode hasil dalam mode teks, akhir baris = CR (ASCII 13), persis prasyarat alat ini dalam mem-parsing balasan.

Baud? (AT+IPR?): menanyakan baud rate UART saat ini, default pabrik 115200.
Baud List (AT+IPR=?): membalas dua daftar — yang pertama baud rate yang bisa dideteksi otomatis, yang kedua yang hanya tersedia pada mode tetap. Setelah tombol ini dijalankan, menu tarik-turun Set Baud akan diganti dengan daftar yang benar-benar dilaporkan perangkat. Hasil uji: daftar kedua perangkat ini mencantumkan sampai 1000000 bps — nilai ini tidak ada di tabel §3.4 manual.

Set Baud (AT+IPR={rate};&W, kartu parameter): menekannya memunculkan kotak konfirmasi dulu — inilah tombol yang paling mudah mengunci Anda di luar pintu di seluruh halaman ini.

Tiga jebakan mengubah baud rate (semuanya terkonfirmasi lewat pengujian):
① Begitu OK terbalas, perubahan langsung berlaku; sejak detik berikutnya alat ini dan modul bicara dalam bahasa berbeda;
② AT&F (reset pabrik) tidak mengembalikan baud rate — jangan berharap ia menyelamatkan Anda;
③ Tanpa &W nilainya tak disimpan — sementara menyambung ulang = daya putus: modul bangun di baud rate lama sedangkan setelan port Anda tertinggal di baud rate baru, putus komunikasi ganda. Karena itu alat ini memaksa penulisan gabungan ;&W.
Empat langkah pemulihan (kotak konfirmasi juga mengingatkannya): putus koneksi → ubah baud rate di area koneksi → sambung ulang → jalankan ulang ritual boot.

Power: QSCLK hemat daya

Sleep? (AT+QSCLK?): menanyakan apakah modul diizinkan masuk tidur. Hasil uji: default pabrik perangkat ini 0 = nonaktif, modul selalu terjaga. Halaman ini hanya menyediakan tombol query: modul yang tertidur akan berhenti merespons AT; cara membangunkan versi manual adalah menarik DTR rendah — tetapi DTR papan ini sudah dialihkan menjadi pin Reset (lihat awal bagian ini). Bila Anda mengaktifkan tidur sendiri lewat baris perintah lalu modul tak bisa dibangunkan, jalankan ulang ritual boot (putus daya lalu nyalakan lagi) untuk lolos; detailnya lihat application note resmi mode hemat daya.

URC: bila pesan tak kunjung datang, ke sinilah tempat pertama

URC (Unsolicited Result Code, kode hasil tak diminta) adalah pesan yang "dimuntahkan modul atas inisiatifnya sendiri tanpa diminta", bukan balasan atas perintah mana pun — RDY saat boot, kedatangan data TCP, pesan MQTT, hasil pemindaian Wi-Fi, notifikasi pemuatan firmware GNSS semuanya URC. Port keluarannya secara default pabrik adalah port USB (usbat) — alat ini yang berjalan lewat UART takkan menerima satu pun, dengan gejala yang sangat khas: semua perintah membalas OK, tetapi pesan tak pernah datang.

TombolPerintahKegunaan
URC Port?AT+QURCCFG="urcport" Menanyakan ke mana URC sekarang dikirim — saat URC tak diterima, inilah yang pertama harus dicek; balasannya harus "uart1" barulah URC bisa diterima
URC PortsAT+QURCCFG=? Port keluaran apa saja yang didukung perangkat ini. Hasil uji membalas ("usbat","usbmodem","uart1"), tanpa "all" yang disebut manual (manual mencatat sebagian model memang tak mendukungnya)
URC → UARTAT+QURCCFG="urcport","uart1" Beralih ke UART utama. Ditulis ke NVRAM, bertahan melintasi boot ulang, cukup diubah sekali
URC SwitchAT+QINDCFG="all" Sakelar induk URC, penyebab besar lain dari "URC tak diterima". Hasil uji: default pabrik perangkat ini sudah 1 (menyala); masalahnya hampir selalu ada di port keluaran

Tombol byte mentah: pintu darurat mode data

Cukup banyak perintah bersifat dua tahap: kirim perintahnya dulu, tunggu modul membalas prompt >, baru kirim isinya. Setelah masuk mode data semacam ini, modul menelan setiap karakter yang Anda ketik sebagai data — termasuk AT command yang ingin Anda kirim. Saat panjang salah dihitung, berubah pikiran di tengah jalan, atau perintah tersangkut, tombol biasa tak bisa menolong; andalkan deretan tombol pengirim byte mentah tunggal ini:

TombolYang dikirimKapan dipakai
Ctrl+Z0x1A Penanda akhir mode data: benar-benar mengirimkan isi yang sudah terkumpul
ESC0x1B Membatalkan mode data dan membuang isi yang sudah terkumpul. Kunci pelarian pilihan utama saat perintah dua tahap tersangkut dan port AT berhenti merespons (manual §2.3.8)
+++Tiga tanda + (byte mentah) Melarikan diri dari mode data transparan (seperti transfer COM: pada FTP) kembali ke mode AT. Aturannya keras: hening 1 detik sebelum dan sesudah, sama sekali tak boleh membawa CR/LF — hasil uji: begitu ditambah CR, ia tak berlaku; wajib dikirim lewat tombol ini, tak bisa diketik di baris perintah
Pengujian membantah manual: +++ adalah "menghentikan", bukan "menjeda". Application note FTPS v1.5 halaman 13 menyebut setelah +++ Anda bisa memakai ATO untuk kembali ke mode data dan melanjutkan transfer; pada perangkat nyata ATO hanya membalas NO CARRIER — transfernya sudah dihentikan. Perlakukan +++ sebagai rem darurat; jangan berharap masih bisa jalan terus setelah mengerem.

Pemecahan masalah

GejalaPenyebab dan solusi
Tak ada respons untuk perintah apa pun Periksa tiga tersangka berurutan: ① ritual boot belum dijalankan (kalau halaman baru di-refresh, pasti ini); ② akhir baris disetel ke LF — modul hanya mengenal CR, dengan LF sama sekali tak ada respons; ③ baud rate tak cocok (lihat empat langkah pemulihan)
Reset sudah ditekan tetapi RDY tak kunjung muncul Lihat dulu apakah tombol Power menyala — modul tanpa daya, sebanyak apa pun Reset ditekan tetap percuma; pada koneksi pertama daya harus melewati ON→OFF
Semua perintah membalas OK, tetapi URC tak pernah datang Kemungkinan besar urcport masih di usbat bawaan pabrik: tekan URC Port? untuk memeriksa, lalu URC → UART untuk mengubah; bila masih gagal, periksa sakelar induk URC Switch
Port AT tiba-tiba "menelan perintah", diketik apa pun tak ada respons Tersangkut di mode data; semua yang Anda ketik ditelan sebagai data — tekan ESC untuk meloloskan diri
