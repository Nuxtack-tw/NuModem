SSL —— TLS 通道

工作原理：SSL 頁是 HTTPS 與 FTPS 的共用底層。 先用 AT+QSSLCFG 設好一個 SSL context（版本、加密套件、驗證模式）， 再用 AT+QSSLOPEN 建立 TLS 連線。

AT+QSSLCFG="sslversion",1,4    ← 4 ＝ 全部支援，相容性最好
AT+QSSLCFG="seclevel",1,0      ← 0 ＝ 不驗證憑證
AT+QSSLOPEN=1,1,4,"主機",埠,0   ← 末碼 0 ＝ 緩衝模式
AT+QSSLSEND=4,<長度>           ← 兩段式，免 Ctrl+Z
AT+QSSLRECV=4,1500             ← 讀到 0 代表空了
AT+QSSLCLOSE=4

三種存取模式（AT+QSSLOPEN 的末碼）：

末碼行為
0 緩衝收到資料只發 +QSSLURC: "recv",<id>， 要自己下 AT+QSSLRECV 讀
1 直推URC 多帶長度、資料直接吐在下一行，不必再讀。 ⚠ 這個模式下 AT+QSSLRECV 會回 ERROR，那是正常的
2 透傳AT 口整個變成資料通道
🔴 兩個出廠預設會讓憑證驗證形同虛設：
  • sni 預設 0 —— 同一個 IP 掛多個網域的伺服器（絕大多數 CDN 與測試站都是） 不送 SNI 就會拿到不匹配的憑證，驗證必敗 566
  • ignorelocaltime 預設 1 —— 出廠狀態下即使開了 seclevel 1 也不檢查憑證有效期
要真的驗憑證，這兩個都要自己設對。

怎麼測憑證驗證有沒有真的生效：只測「壞憑證連不上」是不夠的 —— 「全部都連不上」也會通過。要做成對測試： 同一組設定下，好憑證必須連得上、壞憑證必須連不上，兩個方向都成立才算數。 實測用的是 badssl.com 家族（expired / self-signed / wrong.host / untrusted-root） 加上正常的 badssl.com 當對照組。

憑證怎麼進模組？AT+QFUPL。PEM 是純 ASCII，送得進去 （本工具送得出任何位元組）。上傳後用 AT+QSSLCFG="cacert" 掛上去。
