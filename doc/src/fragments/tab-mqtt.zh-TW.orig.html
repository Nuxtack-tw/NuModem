MQTT —— 物聯網訊息

工作原理：MQTT 是兩層的：先 QMTOPEN 開「網路連線」， 再 QMTCONN 做「MQTT 登入」。兩層都通了才能訂閱與發布。

AT+QMTOPEN=0,"broker位址",1883    ← 開網路（等 +QMTOPEN URC）
AT+QMTCONN=0,"client ID"          ← 登入（等 +QMTCONN URC）
AT+QMTSUB=0,1,"主題",0             ← 訂閱
AT+QMTPUBEX=0,0,0,0,"主題",<長度>  ← 發布（兩段式）
AT+QMTDISC=0                      ← 離線
每個指令的結果碼值域都不一樣，不要互相套用。 +QMTOPEN 的 3 是「PDP 啟用失敗」， +QMTPUBEX 根本沒有 3 這個值。

最容易誤讀的是 +QMTCONN: 0,1 —— 它可能是查詢回應的「狀態 1＝初始化中」，也可能是寫入結果的「封包重傳中」。 單看一行分不出來，所以本工具會把兩種讀法並陳，不硬猜。

怎麼測：內建四個免費公開 broker 的下拉選單（mqttgo.io / HiveMQ / Mosquitto / EMQX），都允許匿名、不必註冊。 client ID 與預設主題都自動帶隨機尾碼 —— 公開 broker 上撞名會被踢線，固定主題還會收到別人的訊息， 那會讓「發給自己再收回來」的驗證失去意義。
