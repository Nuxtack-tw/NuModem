FTP —— ファイル転送

動作原理：FTP には2 本のチャネルがあります：制御チャネルはコマンドを、 データチャネルはファイル内容を運びます。ログイン、リネーム、削除、サイズ照会は制御チャネルだけで済みますが、 LIST、アップロード、ダウンロードは別にデータ接続を 1 本開く必要があります —— 本節の怪現象の大半（615、603 の連発）はここから来ます。 節全体を貫く Quectel の通則：OK は「コマンドを受け付けた」の意味でしかなく、 本当の結果は後から URC で届きます。本節の応答と数値はすべて 2026 年 8 月に実機 EG800K で実測した値です。

始める前に：2 つの前提

  • PDP を先に有効化すること：本ページ最初の AT+QIACT? がまさにこのチェックです —— +QIACT: 1,1,…,"IP" が返ってはじめて先へ進めます。OK しか返らなければ、先に TCP/IP ページで Act PDP を押してください（PDP 未有効のままでは QFTPOPEN は必ず失敗します）。
  • URC が UART を通っていること：FTP コマンドはほぼすべて「まず OK、結果は URC で届く」型です。 AT+QURCCFG="urcport" が "uart1" でなければ、 ここには OK の山しか見えません（設定は Hardware ページを参照）。

ログインの動線：設定 → オープン → URC を待つ

  1. PDP context に紐付け：AT+QFTPCFG="contextid",1 （出荷時から 1。照会ボタンで読み戻して確認できます）。
  2. アカウントを設定：AT+QFTPCFG="account","ユーザー名","パスワード"。 必ず QFTPOPEN より前に設定しておきます。
  3. モードと型：transmode は 1 （パッシブ。NAT の内側では常にこれ、FTPS では必須）。 filetype はプレーンテキストなら 1、それ以外は 0。
  4. ログイン：AT+QFTPOPEN="ホスト",21 は即 OK を返しますが（受け付けただけ）、 +QFTPOPEN: 0,0 を待ってはじめてログイン成功です（最長 125 秒）。 続けて AT+QFTPSTAT を押すと 1 が返るはずです（アイドル。2＝転送中、3＝クローズ中）。
AT+QFTPCFG="account","demo","password"
AT+QFTPCFG="transmode",1
AT+QFTPOPEN="test.rebex.net",21
OK                ← コマンドを受け付けただけ
+QFTPOPEN: 0,0    ← この行こそログイン成功

残りの設定項目：AT+QFTPCFG=? はワンキーで全 10 の設定可能項目と範囲を一覧します（通信量ゼロ）。 rsptimeout（20–180、既定 90 秒）は多くのコマンドの最大応答時間であり、 データモード中の 2 パケット間の最大間隔でもあります。ssltype／sslctxid は FTPS 用（純粋な FTP では 0 のまま。SSL パラメータは SSL ページで設定）。 data_address／cache／restenable は特殊環境向けの微調整で、用途は各ボタンの説明とマニュアルを参照してください。

パスワードのマスク（実測、マニュアルと不一致）：AT+QFTPCFG="account" の照会での読み戻しではパスワードが * にマスクされます（マニュアルはそのまま印字と記載）。ただしユーザー名は平文のままで、 設定した行のパスワードも平文です。スクリーンショットや録画で気を付けるべきは設定行の方です。
🔴 AT+QFTPCLOSE は非同期です —— OK は閉じ終えた意味ではありません。 +QFTPCLOSE: 0,0 を待ってはじめてログアウト完了です。その間 AT+QFTPSTAT は 3（クローズ中）を返し、どの FTP コマンドを打っても一律 +CME ERROR: 603（サーバービジー）です。

症状は極めて紛らわしいものです：603 の連発はモジュールの故障やサーバーからの遮断に見えますが、 実はまだ閉じ終えていないだけです（実測当日、これで大回りしました）。待ちの上限＝rsptimeout。 またこれは FTP からログアウトするだけです。ネットワークを徹底的にリセットするには、TCP/IP ページで Deact PDP を押します。

ディレクトリとファイル管理：サーバーをファイルマネージャとして使う

サーバー側ファイル操作の一式です（LIST／NLST／MLSD はデータ接続を開き、それ以外は制御チャネルのみ）。 成功応答は一律 +QFTPXXX: 0,… —— 最初の数字が 0 なら成功です：

コマンド何をするか成功応答（実測）
AT+QFTPPWD現在の作業ディレクトリを照会+QFTPPWD: 0,"/"
AT+QFTPCWD作業ディレクトリを切り替え。以後の操作はこれが基準+QFTPCWD: 0,0
AT+QFTPLIST完全な一覧をターミナルに直接吐く（2 ボタン：現在のディレクトリ／指定ディレクトリ）内容の後に +QFTPLIST: 0,1175（末尾の数＝バイト数）
AT+QFTPNLST／AT+QFTPMLSDファイル名のみ列挙（通信量節約）／MLSD 標準形式（解析しやすい）LIST と同じ
AT+QFTPSIZEファイルサイズを照会、内容はダウンロードしない+QFTPSIZE: 0,20
AT+QFTPMDTMファイル更新時刻を照会、内容はダウンロードしない+QFTPMDTM: 0,"20260807141117"
AT+QFTPMKDIR／AT+QFTPRMDIRフォルダの作成／削除…: 0,0
AT+QFTPRENAMEファイルまたはフォルダのリネーム+QFTPRENAME: 0,0
AT+QFTPDELファイルの削除+QFTPDEL: 0,0

技（実測で一連すべて合格）：SIZE を存在チェックとして使う —— リネーム後に旧名を照会すると +QFTPSIZE: 627,550、新名は 0,20。 削除後にもう一度照会するとまた 627,550。1 byte もダウンロードせずに各ステップを検証できました。 627,550 は2 層のエラーコードです：627＝モジュール層「FTP は要求された動作を実行しなかった」、 550＝FTP プロトコル層のサーバー回答「ファイルまたはディレクトリが存在しない」。本ツールの注釈は層ごとに翻訳します。

ダウンロード：内容をターミナルに直接印字（COM:）

AT+QFTPGET="ファイル名","COM:" —— CONNECT の後、ファイル内容がターミナルに直接吐かれ、 末尾に +QFTPGET: 0,<バイト数>（実測では readme.txt が 0,379 を返しました）。 もう 1 つの分割ダウンロードボタンは開始位置と長さのパラメータが付き、最も推奨するダウンロード方法です： 先に SIZE でサイズを照会し、分割で取れば、ファイル丸ごとで通信量が爆発するのを避けられます。 AT+QFTPLEN は直前の PUT／GET／LIST／NLST が実際に何 byte 転送したかを照会します。

アップロード：2 段階、宣言した長さを送り切ると自動終了

AT+QFTPPUT="ファイル名","COM:",0,<長さ>,1 は 2 段階コマンドです： CONNECT（データモード入り）を待って、宣言した長さちょうどのバイト数を送出すると、 モジュールは数え切った時点で自動的にデータモードを抜けます。Ctrl+Z を送る必要はありません。本ツールは長さを自動計算するので、 パラメータカードに内容を貼るだけです。

AT+QFTPPUT="numodem-test.txt","COM:",0,20,1
CONNECT                        ← データモードに入る
NuModem-P6-FTP-test\n          ← ちょうど 20 bytes を送出
OK
+QFTPPUT: 0,20                 ← サーバーが 20 bytes を受信

この 20 bytes は実測時、わざわざホスト側から Python の ftplib で取り戻してバイト単位で比較しました —— 完全一致。 UFS 中継形式：マニュアルはファイル名を "UFS:xxx" と書き、 モジュール内蔵ストレージで中継する形式にも対応しています。詳細は FTPS アプリケーションノートを参照。先に PC のファイルを UFS へ入れるには、 SSL ページ「UFS ファイル」グループの Upload ボタン（AT+QFUPL、UART 経由で通信量ゼロ、 checksum を自動照合）を使います。

⚠ +++ は FTP にとって「中断」であって「一時停止」ではありません。 マニュアル（FTPS AN v1.5 p13）はエスケープ後 ATO でデータモードに戻って転送を続けられると書いていますが、 実測では成立しません（2 回試して結果は一致）：エスケープ後 AT+QFTPSTAT は 2（転送中）ではなく 1（アイドル）を返し、ATO は NO CARRIER を返します —— 転送はまるごと中断済みで、復帰できる接続はありません。したがって +++ は制御不能になった データモードから脱出するためだけに使い、大きいファイルのダウンロードの一時停止には使えません。

正しい打ち方：前後にそれぞれ 1 秒の無音、生バイトで送り、CR を付けない（付けると効きません）—— 本ページの +++ ボタンはこの規則どおりに送ります。ATO ボタンはマニュアルの語義どおり残してあります。
