Network —— การลงทะเบียน, ผู้ให้บริการ, RF

หลักการทำงาน: ฟังก์ชันข้อมูลทุกอย่างจะใช้ได้ก็ต่อเมื่อลงทะเบียนกับเครือข่ายมือถือแล้ว และช่องทางข้อมูล PDP พร้อมแล้ว —— หน้านี้คือแดชบอร์ดและสวิตช์ของการเข้าเครือข่าย การไล่ปัญหา "ต่อเน็ตไม่ได้" เริ่มจากที่นี่ทั้งหมด ตัวเลขในหัวข้อนี้ล้วนวัดจริงกับ EG800K ตัวจริงเมื่อเดือนสิงหาคม 2026

ก่อนเริ่ม: สลับ URC มาที่ UART ก่อน

EG800K จากโรงงานส่งข้อความรายงานอัตโนมัติ (URC) ไปที่ usbat (พอร์ต USB AT) แต่เครื่องมือนี้เดิน UART —— URC ทุกข้อความจะรับไม่ได้เลย: การรายงานสัญญาณ, ผล TCP / MQTT / การสแกน Wi-Fi เงียบหมด อาการคือ "คำสั่งตอบ OK หมด แต่ไม่มีข้อความ"

สาเหตุอันดับหนึ่งของ "URC หายทั้งหมด" คือตัวนี้ ไปที่แท็บ Hardware กด AT+QURCCFG="urcport" เพื่อถาม ถ้าไม่ใช่ "uart1" ให้ใช้ปุ่มสลับแก้ —— การตั้งค่าเขียนลง NVRAM แก้ครั้งเดียวมีผลข้ามการรีบูต

ขั้นแรก: ยืนยันสถานะการลงทะเบียน

เมื่อพิธีกรรมเปิดเครื่องเห็น RDY แล้ว ให้กด AT+CEREG? ก่อน (โมดูล 4G ดูคำสั่งนี้แม่นสุด) ปุ่มลงทะเบียนสามปุ่มตรงกับสามโดเมน: CEREG = LTE/EPS, CREG = โดเมน circuit-switched, CGREG = โดเมน packet-switched ตัวเลขตัวที่สอง (stat) ตีความเหมือนกันหมด:

statความหมายทำอย่างไร
0ยังไม่ได้ลงทะเบียนพบบ่อยตอนเพิ่งเปิดเครื่อง รอสักครู่แล้วถามใหม่
1ลงทะเบียนแล้ว (เครือข่ายบ้าน)ปกติ ไปต่อได้
2กำลังค้นหารอ
3ถูกเครือข่ายปฏิเสธเช็ค SIM / แพ็กเกจ, ใช้ CEER ดูสาเหตุ
5ลงทะเบียนแล้ว (โรมมิ่ง)สถานะปกติของเครื่องนี้ ดูด้านล่าง
stat=5 ไม่ใช่ความเสียหาย ทดสอบจริงคำสั่งถามการลงทะเบียนทั้งสามตอบ 0,5: SIM เป็นซิม IoT ของ 1NCE (MCC 901 ซิมโรมมิ่งระหว่างประเทศ) อยู่ประเทศไหนก็นับเป็น "โรมมิ่ง" ทั้งนั้น เห็น 5 ให้ถือเสมือน 1

ลงทะเบียนสำเร็จแต่ออกเน็ตไม่ได้ ให้กด AT+CGATT? ต่อเพื่อเช็คการ attach โดเมนแพ็กเก็ต; จำเป็นก็กด AT+CGATT=1 เพื่อ attach เอง ล้มเหลวค่อยใช้ AT+CEER ดูสาเหตุ (คนละชั้นกับ QIGETERROR ของหน้า TCP/IP) CGATT บล็อกได้นานสุด 140 วินาที อย่ากดรัว

ตอนนี้เกาะผู้ให้บริการเจ้าไหน แบนด์ไหน

AT+COPS? ถามผู้ให้บริการที่ลงทะเบียนอยู่ (ตัวท้าย 7 = LTE) กับดัก: ชื่อผู้ให้บริการอาจเป็นสตริงว่าง —— ทดสอบจริงตอบ +COPS: 0,0,"",7 ไม่ใช่ความเสียหาย จะดูผู้ให้บริการให้กด AT+QNWINFO แทน (ระบบ / ผู้ให้บริการ / แบนด์ / แชนเนล):

+QNWINFO: "FDD LTE","46692","LTE BAND 8",3750

46692 = Chunghwa Telecom, Band 8; ไม่มีบริการตอบ NO SERVICE ซิมโรมมิ่งใบนี้เลือกเครือข่ายเอง: ทดสอบจริงคนละวันเคยเกาะทั้ง Chunghwa Telecom Band 8 และ FarEasTone (466-01) Band 3 เปลี่ยนผู้ให้บริการเปลี่ยนแบนด์ก็ปกติดี AT+COPS=? สแกนผู้ให้บริการรอบตัวทั้งหมด: บล็อกได้นานสุด 300 วินาทีและจะขัดจังหวะงานที่ทำอยู่ แน่ใจว่าจำเป็นค่อยกด

ความแรงและคุณภาพสัญญาณ: CSQ เป็นแค่ค่าหยาบ

AT+CSQ ตอบ rssi กับ ber: rssi 0–31 เทียบเท่า -113 ถึง -51 dBm, 99 = ตรวจไม่พบ (พบบ่อยตอนเพิ่งเปิดเครื่อง รอสักครู่) ทดสอบจริง rssi 18–24 (-77 ถึง -65 dBm, ระดับดี); ber เป็น 99 ตลอด ไม่มีค่าอ้างอิง สามปัจจัยคุณภาพตัวจริงของ LTE RSRP (ความแรง) / RSRQ (คุณภาพ) / SINR (อัตราส่วนสัญญาณต่อสัญญาณรบกวน ต่ำ = ถูกรบกวน) มีแต่กลุ่มปุ่ม Signal URC เท่านั้นที่ดึงได้ (AT+QINDCFG="sqi" ไม่ใส่ค่า = ถามสถานะสวิตช์):

ปุ่มคำสั่งหน้าที่
LTE QualityAT+QINDCFG="sqi",1 เปิดการรายงาน RSRP / RSRQ / SINR —— จำเป็นสำหรับการทดสอบเสาอากาศและตำแหน่งวาง จะแจ้งเฉพาะตอนสัญญาณ "มีการเปลี่ยนแปลง" ถ้าเงียบให้เอามือหุ้มหรือถอดเสียบเสาอากาศ; การตั้งค่าไม่คงอยู่ข้ามการรีบูต
Signal PushAT+QINDCFG="csq",1 สัญญาณเปลี่ยนเมื่อไหร่รายงานทันที แทนการกด CSQ รัว ๆ
URC Off / OnAT+QINDCFG="all",0 / 1 โดนข้อความท่วมจอเมื่อไหร่กดปิดเสียงได้ในปุ่มเดียว —— อย่าลืมเปิดกลับทีหลัง

ช่องทาง PDP: ชั้น 3GPP vs หน้า TCP/IP

PDP context = "ช่องทางข้อมูล" ที่เครือข่ายมือถือจัดสรรให้ มีมันถึงจะมี IP กลุ่มนี้เป็นการถามค่าอย่างเดียวของชั้นมาตรฐาน 3GPP: AT+CGDCONT? แสดง context กับ APN, AT+CGACT? แสดงสถานะเปิดใช้ (บล็อกได้นานสุด 150 วินาที; ⚠ รูปแบบเขียนค่าลำดับพารามิเตอร์กลับกัน), AT+CGPADDR แสดง IP ที่ได้มา ส่วน QIACT? / QICSGP ของหน้า TCP/IP คือ สแต็กของ Quectel เอง ไม่ใช่ชั้นเดียวกัน —— เทียบคู่กันจะแยกได้ว่าฝั่งไหนเสีย: ฝั่งนี้มี IP ฝั่งโน้นไม่มี = เครือข่ายให้แล้วแต่สแต็กยังไม่เริ่ม เครื่องนี้บูตแล้วเปิดใช้ PDP รับ IP อัตโนมัติ

AT+QGDCNT? ถามปริมาณข้อมูลสะสม (ตัวเลขแรกคือส่งออก ตัวที่สองคือรับเข้า) ซิมโรมมิ่งทดสอบปริมาณข้อมูลต้องใช้ตัวนี้ ⚠ การทดสอบจริงหักล้างคำใบ้บนปุ่มที่ว่า "สะสมข้ามการรีบูต": ตัวนับค่าเริ่มต้นไม่บันทึกลง NV ตัดไฟเมื่อไหร่ (รวมโหลดหน้าเว็บใหม่) ก็กลับเป็นศูนย์ —— ต้องจดทันที หรือใช้ AT+QGDCNT=1 บันทึกลง NV

สนามรบไล่ปัญหา: ซิมใบนี้อนุญาต PDP เดียวเท่านั้น

หน้า TCP/IP กด AT+QIACT=1 แล้วตอบ ERROR (572,operation not allowed)? บทหนังตายตัวของซิมใบนี้: หลังบูตชั้น 3GPP เปิดใช้ PDP ไปแล้วหนึ่งช่องโดยอัตโนมัติ แต่หมายเลข context จะลอยไปมา (ทดสอบจริงเคยเจอทั้ง 1 และ 9); เปิดช่องที่สองจะตอบ +CME ERROR: 100 ⇒ เครือข่ายอนุญาตแค่ PDP เดียว; ขณะที่ contextID ของ QIACT มีช่วงแค่ 1–8 ถ้า PDP ถูกเปิดไว้ที่ 9 สแต็กของ Quectel ก็แตะไม่ถึงเลย วิธีแก้สองขั้น (ทำหนึ่งรอบหลังบูตทุกครั้ง):

AT+CGACT?             ← ดูว่าเป็น cid ไหน (หมายเลขลอยไปมา ขั้นนี้ข้ามไม่ได้)
AT+CGACT=0,<cid นั้น>   ← ให้ชั้น 3GPP สละโควตา
AT+QIACT=1            ← หน้า TCP/IP; ตอบ +QIACT: 1,1,1,"10.187.7.8" คือสำเร็จ

QICSGP ตั้ง APN ซิมใบนี้ข้ามได้ —— ทดสอบจริงโมดูลจะซิงก์ APN ที่เครือข่ายจัดให้เองอัตโนมัติ (iot.1nce.net); จำเป็นเฉพาะซิม APN องค์กรที่ต้องใช้บัญชีรหัสผ่าน

ทดสอบอยู่ดี ๆ ทุกอย่างหมดเวลาพร้อมกัน? ให้สงสัย PDP ลอยก่อน ทดสอบจริงตอน HTTP ล้มเหลวติดต่อกันทั้งหมด (ข้อผิดพลาด 716, หมดเวลาคงที่ 30 วินาที) AT+QIACT? ก็ยังตอบ IP ตามปกติ —— ตอนนั้นมันหลอกคุณได้ ต้องเทียบไขว้กับ AT+CGACT? (ทดสอบจริง: 1,0 กับ 9,1 = ลอยไปที่ 9) วิธีแก้: AT+QIDEACT=1 → AT+CGACT=0,<cid ที่ลอยไป> → AT+QIACT=1 แล้ว ping ยืนยัน

ระดับฟังก์ชัน CFUN กับการควบคุม RF

กลุ่ม RF Control ทั้งชุดเปลี่ยนสถานะโมดูล เป็นปุ่มกรอบแดงที่ต้องยืนยันก่อนกดทั้งหมด กด AT+CFUN? ดูระดับปัจจุบันก่อนแล้วค่อยลงมือ:

คำสั่งระดับความหมาย
AT+CFUN=1เต็มฟังก์ชัน RF เปิดหมด; จะกู้คืนให้กดปุ่มนี้เสมอ
AT+CFUN=4โหมดเครื่องบิน ปิดรับส่งทั้งหมด SIM ยังอยู่ —— จุดเริ่มต้นของการทดสอบ "เข้าเครือข่ายใหม่"
AT+CFUN=0ต่ำสุด SIM ก็ถูกปิดด้วย; คู่มือเขียนแค่ Minimum functionality ไม่ได้ระบุรายละเอียด
AT+CFUN=1,1รีสตาร์ตแบบซอฟต์ รีสตาร์ตโมดูลทั้งตัว ⚠ พอร์ต AT ใช้ไม่ได้ชั่วครู่ ต้องรอ RDY ใหม่

CFUN บล็อกได้นานสุด 15 วินาที ถ้า SIM ล็อก PIN ไว้ สลับกลับ CFUN=1 แล้วต้องป้อน PIN ใหม่ ถึงจะลงทะเบียน AT+CGATT=0 (PS Detach) ถอนตัวจากโดเมนแพ็กเก็ต —— จะทุบการเชื่อมต่อ TCP / MQTT ทั้งหมดทิ้ง ใช้เฉพาะตอนทดสอบ "attach ใหม่"

ขั้นสูง: QENG อ่านข้อมูลสถานีฐาน (พิมพ์ในบรรทัดคำสั่ง)

หน้านี้ไม่มีปุ่ม —— พิมพ์ AT+QENG="servingcell" ในบรรทัดคำสั่ง เพื่ออ่านพารามิเตอร์ของสถานีฐานที่ให้บริการ ช่องสำคัญจากการทดสอบจริง:

ช่องค่าวัดจริงวิธีตีความ
MCC / MNC466 / 01ไต้หวัน / FarEasTone
Cell ID / TACABCDE02 / 1234 (hex) ฐานสิบคือ 180149762 / 4660; eNodeB = ECI≫8 = 703710, เซกเตอร์ = 2
PCID / EARFCN144 / 1550 รหัสเซลล์กายภาพ (ไม่ได้ไม่ซ้ำกันทั่วโลก) / Band 3
RSRP / RSRQ / RSSI / SINR-113 / -18 / -92 / -1 RSRP ต่ำกว่า -100 ถือว่าแย่; SINR -1 dB = คุณภาพไม่ดี
Cell ID กับ TAC เป็นเลขฐานสิบหก ก่อนค้นฐานข้อมูลต้องแปลงเป็นฐานสิบ ฐานข้อมูลอย่าง OpenCelliD รับแต่ฐานสิบ โยน ABCDE02 เข้าไปตรง ๆ จะค้นไม่เจออะไรเลย อีกอย่าง AT+QENG="neighbourcell" ตอบแค่ PCID ไม่มี Cell ID สากล (ข้อจำกัดของมาตรฐาน LTE)
