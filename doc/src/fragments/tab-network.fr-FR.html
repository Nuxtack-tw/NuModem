Network — enregistrement, opérateur, radio

Principe de fonctionnement : pour que toute fonction de données marche, il faut être enregistré sur le réseau mobile et disposer d'un canal de données PDP prêt — cette page est le tableau de bord et les interrupteurs de l'accès réseau, et tout diagnostic « pas de connexion » commence ici. Toutes les valeurs de cette section sont des mesures d'août 2026 sur un EG800K réel.

Avant de commencer : basculez d'abord les URC vers l'UART

En sortie d'usine, l'EG800K envoie ses messages spontanés (URC) vers usbat (port AT USB) ; cet outil passe par l'UART — aucun URC n'arrive alors : rapports de signal, résultats TCP / MQTT / scan Wi-Fi, tout reste muet ; le symptôme est « toutes les commandes répondent OK, mais aucun message ».

C'est la cause numéro un de « tous les URC ont disparu ». Allez dans l'onglet Hardware, interrogez avec AT+QURCCFG="urcport" ; si la réponse n'est pas "uart1", corrigez avec le bouton de bascule — le réglage s'écrit en NVRAM, une seule fois suffit, il survit aux redémarrages.

Première étape : vérifier l'état d'enregistrement

Après le RDY du rituel de démarrage, appuyez d'abord sur AT+CEREG? (la plus fiable pour un module 4G). Les trois boutons d'enregistrement correspondent à trois domaines : CEREG = LTE/EPS, CREG = domaine circuit, CGREG = domaine paquet ; le second chiffre (stat) se lit de la même façon partout :

statSignificationQue faire
0Pas encore enregistréCourant juste après le démarrage : attendez quelques secondes et réinterrogez
1Enregistré (réseau domestique)Normal, continuez
2Recherche en coursAttendez
3Refusé par le réseauVérifiez SIM / forfait, cherchez la cause avec CEER
5Enregistré (itinérance)L'état normal de cet exemplaire, voir ci-dessous
stat=5 n'est pas une panne. Mesuré : les trois interrogations d'enregistrement répondent 0,5 — la SIM est une carte IoT 1NCE (plage MCC 901, itinérance internationale), « en itinérance » dans tous les pays : traitez le 5 comme un 1.

Enregistré mais toujours pas d'accès aux données ? Interrogez ensuite l'attachement au domaine paquet avec AT+CGATT? ; au besoin, attachez manuellement avec AT+CGATT=1 ; en cas d'échec, cherchez la cause avec AT+CEER (pas la même couche que le QIGETERROR de la page TCP/IP). CGATT peut bloquer jusqu'à 140 secondes : ne martelez pas le bouton.

Sur quel opérateur, sur quelle bande

AT+COPS? interroge l'opérateur actuellement retenu (le 7 final = LTE). Piège : le nom d'opérateur peut être une chaîne vide — mesuré +COPS: 0,0,"",7, ce n'est pas une panne. Pour voir l'opérateur, appuyez plutôt sur AT+QNWINFO (technologie / opérateur / bande / canal) :

+QNWINFO: "FDD LTE","46692","LTE BAND 8",3750

46692 = Chunghwa Telecom, Band 8 ; sans service, la réponse est NO SERVICE. Cette carte en itinérance choisit son réseau toute seule : mesuré à des dates différentes sur Chunghwa Telecom Band 8 puis FarEasTone (466-01) Band 3 — changer d'opérateur et de bande est normal. AT+COPS=? scanne tous les opérateurs environnants : blocage jusqu'à 300 secondes et interruption des services en cours — n'appuyez qu'en cas de vrai besoin.

Force et qualité du signal : CSQ n'est qu'une valeur grossière

AT+CSQ renvoie rssi et ber : rssi 0–31 correspond à -113 à -51 dBm, 99 = indétectable (courant juste après le démarrage, attendez quelques secondes). Mesuré : rssi 18–24 (-77 à -65 dBm, bon) ; ber toujours à 99, sans valeur de référence. Le vrai trio de qualité LTE, RSRP (force) / RSRQ (qualité) / SINR (rapport signal/bruit, bas = brouillé), ne s'obtient que par le groupe Signal URC (AT+QINDCFG="sqi" sans valeur = interrogation de l'interrupteur) :

BoutonCommandeRôle
LTE QualityAT+QINDCFG="sqi",1 Active le rapport RSRP / RSRQ / SINR — indispensable pour tester antennes et emplacements. N'est poussé que quand le signal « change » : s'il ne se passe rien, enveloppez l'antenne ou débranchez-la ; le réglage ne survit pas au redémarrage
Signal PushAT+QINDCFG="csq",1 Rapport à chaque variation du signal, au lieu de marteler CSQ
URC Off / OnAT+QINDCFG="all",0／1 Coupure générale d'un seul geste quand l'écran est inondé — pensez à réactiver ensuite

Canal PDP : couche 3GPP vs page TCP/IP

Le contexte PDP est le « canal de données » attribué par le réseau mobile : sans lui, pas d'IP. Ce groupe interroge en lecture seule la couche standard 3GPP : AT+CGDCONT? liste les contextes et APN, AT+CGACT? liste les états d'activation (blocage jusqu'à 150 secondes ; ⚠ la forme d'écriture prend les paramètres dans l'ordre inverse), AT+CGPADDR liste les IP obtenues. Les QIACT? / QICSGP de la page TCP/IP appartiennent à la pile propre à Quectel, pas à la même couche — comparer les deux côte à côte permet de localiser la panne : une IP ici mais pas là-bas = le réseau a donné le canal, mais la pile ne l'a pas activé. Cet exemplaire active automatiquement le PDP et obtient une IP dès le démarrage.

AT+QGDCNT? interroge le trafic cumulé (premier nombre = émis, second = reçu), incontournable pour mesurer la consommation d'une carte en itinérance. ⚠ La mesure contredit l'infobulle du bouton (« cumul à travers les redémarrages ») : par défaut, le compteur n'est pas stocké en NV et retombe à zéro à la moindre coupure (rechargement de page compris) — notez la valeur sur-le-champ, ou stockez en NV avec AT+QGDCNT=1.

Dépannage vécu : cette carte n'autorise qu'un seul PDP

Sur la page TCP/IP, AT+QIACT=1 répond ERROR (572,operation not allowed) ? Scénario systématique avec cette carte : après le démarrage, la couche 3GPP a déjà activé automatiquement un PDP, mais le numéro de contexte flotte (mesuré : 1 et 9 selon les fois) ; en ouvrir un second renvoie +CME ERROR: 100 ⇒ le réseau n'autorise qu'un seul PDP ; or la plage de contextID de QIACT s'arrête à 1–8 : quand le PDP est ouvert sur le 9, la pile Quectel ne peut tout simplement pas l'atteindre. Solution en deux étapes (une fois après chaque démarrage) :

AT+CGACT?             ← voir quel est le cid (le numéro flotte, étape non facultative)
AT+CGACT=0,<ce cid>   ← la couche 3GPP libère la place
AT+QIACT=1            ← page TCP/IP ; +QIACT: 1,1,1,"10.187.7.8" = succès

Régler l'APN avec QICSGP est superflu avec cette carte — mesuré : le module synchronise tout seul l'APN attribué par le réseau (iot.1nce.net) ; ce n'est nécessaire qu'avec les cartes à APN d'entreprise exigeant identifiant et mot de passe.

Tout part soudain en timeout en plein test ? Suspectez d'abord une dérive du PDP. Mesuré : pendant une série d'échecs HTTP complets (erreur 716, timeout fixe de 30 secondes), AT+QIACT? continuait de renvoyer une IP — à ce moment-là il ment, il faut croiser avec AT+CGACT? (mesuré : 1,0 et 9,1 = dérive vers le 9). Solution : AT+QIDEACT=1 → AT+CGACT=0,<le cid de dérive> → AT+QIACT=1, puis validez par un ping.

Niveaux de fonctionnalité CFUN et contrôle radio

Tout le groupe RF Control modifie l'état du module : ce sont tous des boutons à cadre rouge avec confirmation. Appuyez d'abord sur AT+CFUN? pour connaître le niveau actuel avant d'agir :

CommandeNiveauSignification
AT+CFUN=1Fonctionnalité complète Radio entièrement active ; pour récupérer, appuyez toujours sur celui-ci
AT+CFUN=4Mode avion Émission/réception coupées, SIM toujours là — point de départ pour tester le « retour au réseau »
AT+CFUN=0Minimal SIM désactivée aussi ; le manuel se borne à « Minimum functionality » sans détail
AT+CFUN=1,1Redémarrage logiciel Redémarre tout le module. ⚠ Le port AT décroche brièvement, il faut attendre RDY à nouveau

CFUN bloque au maximum 15 secondes. Si la SIM est verrouillée par PIN, après le retour à CFUN=1 il faut ressaisir le PIN pour que l'enregistrement se fasse. AT+CGATT=0 (PS Detach) quitte le domaine paquet — et fait tomber toutes les connexions TCP / MQTT ; réservé au test de « ré-attachement ».

Avancé : lire la cellule avec QENG (saisie en ligne de commande)

Pas de bouton pour cela — tapez AT+QENG="servingcell" dans la ligne de commande pour lire les paramètres de la cellule serveuse ; champs clés mesurés :

ChampValeur mesuréeLecture
MCC / MNC466 / 01Taïwan / FarEasTone
Cell ID / TACABCDE02 / 1234 (hex) En décimal 180149762 / 4660 ; eNodeB = ECI≫8 = 703710, secteur = 2
PCID / EARFCN144 / 1550 Identifiant physique de cellule (non unique mondialement) / Band 3
RSRP / RSRQ / RSSI / SINR-113 / -18 / -92 / -1 RSRP sous -100 est considéré mauvais ; SINR -1 dB = qualité médiocre
Cell ID et TAC sont en hexadécimal : convertissez en décimal avant toute recherche en base. Les bases comme OpenCelliD n'acceptent que le décimal ; envoyer ABCDE02 tel quel ne donnera aucun résultat. Par ailleurs, AT+QENG="neighbourcell" ne renvoie que le PCID, jamais de Cell ID global (limite du standard LTE).
