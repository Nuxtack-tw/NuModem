SSL —— TLS 通道

工作原理：SSL 頁是加密連線的共用底層 —— 這裡設好的 SSL context 與上傳的憑證，同時供 SSL raw socket、MQTT over SSL 與 HTTPS 使用。本節的秒數與行為都是 2026 年 8 月對實體 EG800K 的實測值。

第一次 TLS 連線：五個步驟

  1. 跑開機儀式（見〈開機儀式〉一節），再按 AT+QIACT? 確認資料通道 —— 要回得出 +QIACT: 1,1,…,"IP"，沒有就先 AT+QIACT=1。
  2. 設 context：sslversion 填 4（全部版本， 相容性最好）、ciphersuite 填 0XFFFF（全部套件）、 seclevel 先填 0 —— 先確認通道會通，驗證留到後面。
  3. 開連線：按 AT+QSSLOPEN（末碼 0），參數卡填 主機與埠。⚠ OK 只代表「指令收下」，成敗要等 URC： +QSSLOPEN: 4,0 才是成功（實測交握 2.0 秒）。
  4. 送資料：按 AT+QSSLSEND（兩段式）—— 出現 > 後送本文，數滿宣告長度自動送出， 免 Ctrl+Z（單包上限 1460 bytes）。對方回話會出 +QSSLURC: "recv",4。
  5. 讀回與關閉：AT+QSSLRECV（單次上限 1500） 讀到 +QSSLRECV: 0 代表收乾淨了，不是錯誤。 AT+QSSLCLOSE=4 關閉（預設最長等 10 秒； 另一顆可指定秒數，0＝立即）。
AT+QSSLOPEN=1,1,4,"tcpbin.com",4243,0
OK
+QSSLOPEN: 4,0            ← 2.0 秒，0＝成功
AT+QSSLSEND=4,15
>
NuModem-P5-SSL            ← 數滿 15 bytes 自動送出
SEND OK
+QSSLURC: "recv",4        ← 0.4 秒
AT+QSSLRECV=4,1500
+QSSLRECV: 15
NuModem-P5-SSL
AT+QSSLCLOSE=4

連線期間可按 AT+QSSLSTATE 看所有連線（=4 查單一 clientID，狀態 2＝已連線）。注意本地埠永遠回 0 —— 模組行為，不是錯誤。

三種存取模式（AT+QSSLOPEN 末碼）

末碼行為
0 緩衝收到資料只發 +QSSLURC: "recv",<id>， 自己下 AT+QSSLRECV 讀
1 直推URC 多帶長度、資料直接吐在下一行； ⚠ 此模式下 AT+QSSLRECV 回 ERROR 是正常的
2 透傳AT 口整個變成資料通道（本頁按鈕只備 0 與 1）

context 設定逐項

不確定韌體支援哪些子項就先按 AT+QSSLCFG=? —— 實測回 17 個子項，比應用手冊列的多。常用子項都有設定與查詢兩顆按鈕， 實測寫入後讀回完全一致。

子項出廠作用與實測要點
sslversion—協定版本；4＝全部支援
ciphersuite—加密套件；0XFFFF＝全部支援
seclevel00＝不驗證、1＝驗證伺服器 （要先上傳 CA 憑證）、2＝雙向認證（還要用戶端憑證＋私鑰）
cacert—CA 憑證路徑，格式 "UFS:檔名"，檔案須已在 UFS（見下節）
sni🔴 0 連虛擬主機／CDN 必開 —— 同一 IP 掛多網域時不送 SNI 就拿到不匹配的憑證，驗證必敗 566
ignorelocaltime🔴 1 出廠即使開了 seclevel 1 也不檢查憑證有效期。 要檢查就設 0，且模組時鐘要對
negotiatetime300 TLS 交握最長等待秒數（10–300）
🔴 三個出廠預設加起來＝完全不驗證憑證 （seclevel 0、sni 0、ignorelocaltime 1），要真的驗就三個都要設對。 且這三個設定與 cacert 不跨重開機保存 （實測確認），每次開機都回出廠值；UFS 裡的憑證檔則斷電不丟。

UFS 檔案群：憑證怎麼進模組

UFS 是模組內建快閃儲存，實測總容量 280 KB、每檔佔一個 4 KB 區塊。憑證要先上傳到這裡，cacert 才有檔案可指。 上傳走 UART、零數據流量，二進位檔也送得進去。 Upload 卡：選檔後檔名與大小自動填入，送出後工具等模組回 CONNECT 才送原始位元組（等不到就不送）。完成時 註解引擎自動比對模組回報的大小與 checksum： ✅＝完整無誤、❌＝傳壞了，先刪再重傳。

AT+QFUPL="badssl-root.pem",1939,10
CONNECT                   ← 接著送出 1939 bytes
+QFUPL: 1939,4f64         ← 實收大小,checksum，註解自動比對 ✅
按鈕用途
AT+QFLST列出 UFS 全部檔案與大小 —— 上傳後用它驗證（零流量）
AT+QFLDS="UFS"查剩餘／總空間 bytes（零流量）
AT+QFDEL刪除指定檔（*＝全部）； 同名檔不先刪、重傳會被擋
兩個手冊沒明說的實測行為：（1）FILE 錯誤碼形式不一致 —— 同名重傳回文字 file already exist、逾時回數字 421， 本工具兩種都能解讀；（2）大小欄填得比實際大，模組逾時後 照樣把實收內容存檔 —— checksum 比對會抓出來。

憑證驗證實戰：成對測試法

流程：上傳根憑證 → cacert 指到它 → seclevel 1 → sni 1 → 連目標的 443。要上傳的是憑證鏈最上層的根憑證 （badssl.com 的鏈有四層，上傳最頂端的 ISRG Root X1）。 只測「壞憑證連不上」不夠 —— 「全部連不上」也會通過。 要成對測試：好憑證連得上、壞憑證連不上， 兩個方向都成立才算數。實測 2×5 對照：

主機seclevel 0seclevel 1
badssl.com（正對照）連得上 連得上 4,0
expired（過期）連得上拒絕 566
self-signed（自簽）連得上拒絕 566
wrong.host（主機名不符）連得上拒絕 566
untrusted-root（根不受信）連得上拒絕 566

限制：四種憑證錯誤全回 566，模組不區分是哪一種。 AT+QIGETERROR 也幫不上忙 —— 它管 TCP/IP 層， 這時只回 0,operate successfully。

負向測項避開 expired —— 出廠 ignorelocaltime 是 1，過期本身 不會被擋（上表它被擋是因為同時不在上傳的根之下），單測就用 wrong.host。 另外留意流量：每次交握都下載完整憑證鏈、失敗照付， 實測 30 次交握約 150–200 KB。

🔴 陷阱：連續開關約 20 次後，資料堆疊整個退化

症狀：所有 AT+QSSLOPEN 一律回 552，連 seclevel 0 都連不上，而每項自我檢查都說沒事。30 秒鑑別：用純 TCP 的 AT+QIOPEN 打同一目標 —— 也失敗就是資料堆疊壞了，別再查 SSL 設定。PDP 重啟救不回來，只有完整開機儀式能復原。 退化會污染測試資料、易誤判成「被憑證驗證擋掉」—— 做成對測試前先重開機清乾淨。
