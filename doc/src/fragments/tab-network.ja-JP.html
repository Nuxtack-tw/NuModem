Network —— 登録、オペレータ、RF

動作原理：すべてのデータ機能が使えるための前提は、通信ネットワークへ登録済みであること、 そして PDP データチャネルが準備できていること —— このページは入網のダッシュボードとスイッチであり、 「ネットにつながらない」の切り分けはすべてここから始まります。本節の数値はすべて 2026 年 8 月に実機 EG800K で実測したものです。

始める前に：まず URC を UART へ切り替える

EG800K は出荷時、自発報告メッセージ（URC）を usbat（USB AT ポート）へ送ります。 本ツールは UART を使うため —— URC は 1 本も受信できません：信号報告、 TCP／MQTT／Wi-Fi スキャン結果がすべて無音になり、症状は「コマンドはすべて OK が返るのに、メッセージだけが無い」です。

「URC が全部消えた」の筆頭原因がこれです。 Hardware タブで AT+QURCCFG="urcport" を照会し、 "uart1" でなければ切替ボタンで変更してください —— 設定は NVRAM に書かれ、1 回の変更で再起動をまたいで有効です。

第一歩：登録状態を確認する

起動シーケンスで RDY を見たら、まず AT+CEREG? を押します（4G モジュールではこれが最も確か）。 3 つの登録ボタンは 3 つのドメインに対応します：CEREG＝LTE/EPS、CREG＝回線交換ドメイン、 CGREG＝パケット交換ドメイン。2 番目の数字（stat）の読み方は共通です：

stat意味どうするか
0まだ登録されていない起動直後によくあります。数秒待って再照会
1登録済み（ホーム網）正常。先へ進む
2検索中待つ
3ネットワークに拒否されたSIM／料金プランを確認し、CEER で原因を見る
5登録済み（ローミング）本機の常態。下記参照
stat=5 は故障ではありません。実測では 3 つの登録照会がすべて 0,5 を返しました： SIM は 1NCE の IoT カード（MCC 901 の国際ローミングカード）で、どの国にいても「ローミング」扱いです。 5 を見たら 1 と同じに扱ってください。

登録は成功したのにネットに出られないときは、続けて AT+CGATT? でパケットドメインへのアタッチを照会します。 必要なら AT+CGATT=1 で手動アタッチし、失敗したら AT+CEER で原因を調べます（TCP/IP ページの QIGETERROR とは別レイヤ）。 CGATT は最長 140 秒ブロックするので、連打しないでください。

今どのオペレータのどのバンドにいるか

AT+COPS? は現在登録中のオペレータを照会します（末尾の 7＝LTE）。 罠：オペレータ名が空文字列のことがあります —— 実測では +COPS: 0,0,"",7 が返りましたが、 故障ではありません。オペレータを見たいときは代わりに AT+QNWINFO（方式／オペレータ／バンド／チャネル）を押します：

+QNWINFO: "FDD LTE","46692","LTE BAND 8",3750

46692＝中華電信（台湾）、Band 8。圏外のときは NO SERVICE が返ります。 本ローミングカードは自分で網を選びます：日付の異なる実測で中華電信 Band 8 と Far EasTone（466-01）Band 3 に載ったことがあり、 オペレータやバンドが変わっても正常です。AT+COPS=? は周辺の全オペレータをスキャンします： 最長 300 秒ブロックし、既存の業務を中断します。必要と確信してから押してください。

信号強度と品質：CSQ は粗い値にすぎない

AT+CSQ は rssi と ber を返します：rssi 0–31 は -113～-51 dBm に対応し、 99＝検出不能（起動直後によくあります。数秒待つ）。実測では rssi 18–24（-77～-65 dBm、良好）。 ber は常に 99 で参考になりません。LTE の本当の品質 3 要素 RSRP（強度）／RSRQ（品質）／SINR（信号対雑音比、低い＝干渉されている） は Signal URC グループでしか得られません（AT+QINDCFG="sqi" を値なしで＝スイッチの照会）：

PDP チャネル：3GPP レイヤ vs TCP/IP ページ

PDP context＝通信ネットワークが割り当てる「データチャネル」で、これがあってはじめて IP があります。このグループは 3GPP 標準レイヤの読み取り専用照会です： AT+CGDCONT? は context と APN を、AT+CGACT? は有効化状態を一覧し （最長 150 秒ブロック。⚠ 書き込み形式はパラメータの順序が逆）、AT+CGPADDR は取得した IP を一覧します。TCP/IP ページの QIACT?／QICSGP は Quectel 自社スタックで、同じレイヤではありません —— 並べて比較すると故障側を切り分けられます： こちらに IP があってあちらに無い＝ネットワークは与えたのにスタックが起動していない。本機は起動と同時に自動で PDP を有効化し IP を取得します。

AT+QGDCNT? は累計通信量を照会します（最初の数字が送信、2 番目が受信）。 ローミングカードの通信量テストには必須です。⚠ 実測がボタンのヒント「再起動をまたいで累計」を覆しました： カウンタは既定では NV に保存されず、電源断（ページの再読み込みを含む）で即ゼロに戻ります —— その場で記録するか、 AT+QGDCNT=1 で NV に保存してください。

障害切り分けの実戦：このカードは単一 PDP しか許可しない

TCP/IP ページで AT+QIACT=1 を押したのに ERROR（572,operation not allowed）？ 本カードの決まった筋書き：起動後、3GPP レイヤがすでにPDP を 1 本自動有効化していますが、 context 番号は浮動します（実測で 1 と 9 を確認）。2 本目を開こうとすると +CME ERROR: 100 ⇒ ネットワークは単一 PDP しか許可していません。しかも QIACT の contextID 範囲は 1–8 しかなく、PDP が 9 に開かれていると Quectel スタックからはまったく触れません。 対処は 2 ステップ（起動のたびに 1 回）：

AT+CGACT?             ← どの cid かを見る（番号は浮動するので省略不可）
AT+CGACT=0,<その cid>   ← 3GPP レイヤに枠を譲らせる
AT+QIACT=1            ← TCP/IP ページ。+QIACT: 1,1,1,"10.187.7.8" が返れば成功

QICSGP の APN 設定は本カードでは省略できます —— 実測ではモジュールがネットワークの割り当てた APN （iot.1nce.net）を自動同期しました。ユーザー名とパスワードが必要な企業向け APN カードに替えたときだけ必要です。

テストの途中で突然すべてタイムアウトし始めた？ まず PDP の漂流を疑ってください。 実測では HTTP が連続全敗（エラー 716、固定 30 秒タイムアウト）のときも AT+QIACT? は平然と IP を返しました —— このとき、これは嘘をつくので、AT+CGACT? と突き合わせてください （実測：1,0 と 9,1＝9 へ漂流）。 対処：AT+QIDEACT=1 → AT+CGACT=0,<漂流先の cid> → AT+QIACT=1、その後 ping で検証。

CFUN 機能レベルと RF 制御

RF Control のグループはすべてモジュールの状態を変えるもので、全部が押す前に再確認する赤枠ボタンです。 まず AT+CFUN? で現在のレベルを見てから動いてください：

コマンドレベル意味
AT+CFUN=1全機能 RF 全開。復旧は必ずこれを押す
AT+CFUN=4機内モード 送受信全停止、SIM は生きたまま —— 「再入網」テストの起点
AT+CFUN=0最小 SIM も無効化。マニュアルには Minimum functionality としか書かれておらず、詳細はありません
AT+CFUN=1,1ソフト再起動 モジュール全体を再起動。⚠ AT ポートが短時間無効になり、あらためて RDY を待つ必要があります

CFUN は最長 15 秒ブロックします。SIM に PIN ロックがある場合、CFUN=1 に戻した後 PIN を入力し直さないと 登録されません。AT+CGATT=0（PS Detach）はパケットドメインから離脱します —— すべての TCP／MQTT 接続を叩き落とします。「再アタッチ」のテストのときだけ使ってください。
