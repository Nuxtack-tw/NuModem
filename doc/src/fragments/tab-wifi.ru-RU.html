WiFiScan — сканирование Wi-Fi и сетевое позиционирование

Принцип работы: EG800K — модуль LTE, выхода в интернет по Wi-Fi у него нет, но встроен приёмник Wi-Fi «только сканирует, не подключается»: он пассивно принимает beacon-кадры, которые вещают окрестные точки доступа 2.4GHz, и сообщает MAC-адрес (BSSID), RSSI (силу сигнала) и канал каждой точки. Сканирование — чистый радиоприём, без единого байта трафика; само по себе оно координат не даёт — чтобы получить широту и долготу, список MAC + RSSI нужно отправить на запрос в облачную базу расположения точек доступа; это и есть сетевое позиционирование, работающее и в помещении, без спутников. Все числа и всё поведение в этом разделе — замеры на физическом EG800K в августе 2026 года.

Верхняя половина — Wi-Fi Scan, четыре кнопки (чистое сканирование), нижняя — QuecLocator (QLBS), тринадцать кнопок (прежде чем нажимать, прочитайте абзац правды ниже):

Первое сканирование: как нажимать и что вы увидите

  1. Прогоните ритуал включения (см. раздел «Ритуал включения»).
  2. Убедитесь, что URC идут по UART: AT+QURCCFG="urcport" должна вернуть "uart1". Заводское значение — "usbat": все результаты сканирования уйдут на USB-порт, здесь вы увидите только OK — не дождётесь даже TIMEOUT (настройка пишется в NVRAM, достаточно сменить один раз).
  3. Нажмите Scan: модуль сначала ответит OK — это значит «сканирование началось», это не результат. В течение нескольких секунд (максимум до лимита времени) результаты приходят строка за строкой, каждая с автоматическим пояснением (MAC / RSSI / канал).

Чтение результатов сканирования

Реальный отчёт выглядит так (2026-08-29, найдено 7 точек, RSSI -37 ~ -89 dBm):

+QWIFISCAN: (-,-,-37,"C2:28:35:00:00:01",1)
+QWIFISCAN: (-,-,-46,"10:71:B3:00:00:02",4)
+QWIFISCAN: (-,-,-88,"A8:A2:37:00:00:03",6)

Порядок полей — (ecn, ssid, rssi, mac, channel). Прошивка этой машины в ecn и ssid всегда возвращает - (замер 2026-08-02): в списке не видно, «чей это Wi-Fi» — для позиционирования этого как раз достаточно: базы и так едят MAC + RSSI. Интуиция по RSSI: -30 ~ -50 — совсем рядом, -60 ~ -75 — средне, ниже -80 — очень слабо.

Если за лимит времени не найдено ни одной точки, возвращается +QWIFISCAN:TIMEOUT — нормальное завершение, а не ошибка (после двоеточия нет пробела; парсер инструмента это учитывает). Хотите насканировать больше: карточкой параметров поднимите максимум точек с заводских 5 (предел этой машины — 10) и число раундов до 2-3 (по замеру результаты между раундами дедуплицируются).

Не каждая найденная точка годится для позиционирования. Замер 2026-08-29: из 7 точек 4 оказались «локально администрируемыми адресами» (начинаются с C2: / 62: / 9E:, у первого байта установлен бит 0x02 — виртуальные BSSID мульти-SSID-клонов); базы позиционирования такие адреса обычно просто игнорируют, и реально пригодного материала осталось всего 3 глобальных адреса.
Диапазоны параметров из прикладного документа V1.2 для этой машины неверны. Документ расширяет раунды до 1-6 и максимум точек до 4-30, но прошивка этой машины реально возвращает раунды 1-3, максимум точек 4-10 (замер 2026-08-06). Верьте реальному ответу Support?, не переписывайте числа из документа.

Группа кнопок QuecLocator (QLBS): сначала правда, потом нажатия

QuecLocator — облачный сервис позиционирования Quectel: одна команда AT+QLBS (кнопка Locate) — прошивка сама собирает материал, отправляет на сервер, запрашивает базу и возвращает координаты. Три обстоятельства реальности:

  1. Нужен token, и сервис платный. Официальный документ прямо пишет: обращаться в техподдержку Quectel (самостоятельной регистрации нет). Token этой машины с завода пуст.
  2. Ни один из 16 официальных документов EG800K не упоминает QuecLocator. Имеющийся прикладной документ — для EC200U / EG915U (синтаксис и коды ошибок по замеру совпадают), официальным документом этой машины он не является.
  3. Проект решил его не использовать (2026-08-29): логика позиционирования заперта в прошивке; свернётся сервис — вся AT-команда перестанет работать, а поставщика не заменить (форум Quectel уже подтвердил прекращение поддержки для серии BG95). Кнопки оставлены лишь на случай «достался бесплатный token — заодно проверить».
+QLBS: 702 — это «таймаут сервера», а не проблема token. Проект целых три недели ошибочно считал 702 «отсутствием token» — правда в том, что тогда забыли сначала активировать PDP: модуль вообще не мог достучаться до сервера и, отсидев таймаут (заводские 60 секунд), возвращал 702. Контрольный эксперимент 2026-08-29 (token всё время пуст): PDP не активирован — 702; активирован — 10002 (token не существует) — сервер из Тайваня достижим, не хватает только token. Перед AT+QLBS обязательно AT+QIACT=1 (расходуется трафик).

Для всех семи подпунктов настройки есть кнопки запроса и записи; Cfg? (AT+QLBSCFG=?) одним нажатием перечисляет все диапазоны (без единого байта трафика). Заводские значения этой машины и главное из замеров:

Альтернативный маршрут: сетевое позиционирование без token (замер — 71 метр)

Сетевое позиционирование не обязано опираться на QuecLocator. Альтернативный маршрут 2026-08-29 пройден насквозь: модуль лишь выдаёт материал (эта страница сканирует точки, AT+QENG="servingcell" читает базовую станцию), вывод терминала сохраняется в файл и передаётся tools/wifi_geolocate.py, который запрашивает публичные базы на стороне PC — ни байта трафика с модуля, без сервисов Quectel. Замер (сверка с истинным значением GNSS того же дня): запрос по базовой станции через Unwired Labs (бесплатная регистрация) — погрешность 71 метр (итоговый вывод этой линии позиционирования), через beaconDB (без ключа) — 632 метра; запрос по Wi-Fi упёрся в поставщиков — бесплатная экосистема рухнула (beaconDB не покрывает этот район, бесплатный план Unwired Labs не включает Wi-Fi, Google / HERE требуют привязки карты) — отложено.

71 метр — это «попадание в базе», а не «точность измерения». Позиционирование по базовой станции — это поиск зарегистрированных координат станции по Cell ID: одна и та же сота всегда возвращает одну и ту же точку — смените станцию, и погрешность может стать километровой; честная оценка — ±1051 метр, которые сообщает сам сервис. Кроме того, Cell ID и TAC — шестнадцатеричные: перед запросом их нужно перевести в десятичные (инструмент делает это сам).

Устранение неполадок

СимптомПричина и решение
После Scan только OK, результаты не приходят никогда URC уходят на USB-порт — запросите AT+QURCCFG="urcport"; если не "uart1" — смените (пишется в NVRAM)
+QWIFISCAN:TIMEOUT За лимит времени точек не найдено — нормальное завершение, не ошибка. Смените место или удлините лимит
+QLBS: 702 Таймаут сервера — почти всегда забыт AT+QIACT=1, а не проблема token
+QLBS: 10002 Token не существует — оформляется платно у Quectel; проект решил не использовать и идёт альтернативным маршрутом выше
Хочется AT+QCELLLOC Эта машина не поддерживает (возвращает ERROR) — это команда серии EC2x
