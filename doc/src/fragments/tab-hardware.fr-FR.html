Hardware — démarrage et port série

Principe de fonctionnement : cette page est la fondation de tout l'outil : Control regroupe les deux boutons du rituel de démarrage (Power / Reset), Module l'identification du produit, Serial les réglages UART, Power la basse consommation, URC le port de sortie des messages spontanés du module, plus une rangée de boutons d'octets bruts qui servent d'issue de secours en mode données. Tous les autres onglets reposent sur deux prérequis : le module a été démarré selon le rituel et les URC passent par uart1 — ces deux choses se règlent ici. Tous les comportements et chiffres de cette section sont des mesures d'août 2026 sur un EG800K réel.

Pourquoi un rituel de démarrage : RTS = alimentation, DTR = Reset

La carte de contrôle associée à cet outil détourne deux signaux de contrôle RS-232 de leur rôle habituel — c'est la clé de toute cette page :

SignalRéellement câblé surLogique
RTSInterrupteur d'alimentation du module Logique inversée : RTS OFF = sous tension, RTS ON = hors tension
DTRBroche Reset du module DTR ON = Reset au niveau haut (démarrage possible), DTR OFF = Reset au niveau bas

Particularité du circuit (confirmée par mesure) : à la première connexion, RTS doit passer par ON puis OFF pour que l'alimentation s'enclenche réellement — mettre OFF directement ne garantit pas la mise sous tension ; DTR doit lui aussi suivre ON→OFF→ON pour que Reset monte vraiment. La coupure (RTS ON) est brutale : le module n'envoie aucun message d'adieu.

Recharger la page = couper le courant. Quand le navigateur rouvre le port série, il relève RTS et le module perd instantanément l'alimentation — après la reconnexion automatique, il faut refaire le rituel de démarrage. Vécu en test : 17 commandes envoyées en sautant le rituel, toutes parties sans retour (que des lignes TX, zéro RX). Devant tout « ça marchait il y a une seconde, plus rien ne répond », pensez d'abord à cela.

Boutons Power et Reset : comment appuyer, ce que vous verrez

Ces deux boutons incarnent les deux signaux du tableau ci-dessus et sont couplés dans les deux sens avec les indicateurs RTS / DTR de la barre de signaux (grisés et inactifs hors connexion). Web Serial ne peut pas relire l'état réel des signaux de sortie : la barre affiche la valeur que cet outil croit avoir envoyée.

  1. Power (à bascule) : vert allumé = alimentation ON (= RTS OFF). Le rituel exige que RTS passe par ON→OFF : si le bouton est déjà allumé, éteignez-le puis rallumez-le.
  2. Reset (momentary) : appui = DTR OFF, relâchement = DTR ON, un appui-relâchement = un Reset (la séquence standard marque une pause de 0.3 seconde au milieu).
  3. Attendre RDY : en quelques secondes, le terminal affiche l'annonce de démarrage du module RDY.
  4. Vérifier avec ATI : la réponse doit être Quectel / EG800K / Revision: … / OK. Si elle arrive, l'UART et le module sont tous deux vivants.
Après le démarrage, vérifiez d'abord que l'écho (ATE) est actif (il l'est en sortie d'usine), puis envoyez AT+CMEE=2 — sans lui, vous ne verrez qu'un aride ERROR ; avec lui, vous obtenez le texte lisible +CME ERROR: …. Les deux réglages ne valent que pour la session : à refaire à chaque redémarrage du module.

Serial : AT&V pour lire les paramètres, IPR pour changer le débit

AT Params (AT&V) : liste la valeur actuelle de tous les paramètres AT à lettre unique. Les commandes à lettre unique comme ATE / ATQ / ATV n'ont pas de forme d'interrogation propre : seule cette commande permet de les lire. Mesuré ici : E:1 Q:0 V:1 S3:13 S4:10 — écho actif, codes de résultat en mode texte, fin de ligne = CR (ASCII 13), exactement les prémisses sur lesquelles cet outil analyse les réponses.

Baud? (AT+IPR?) : interroge le débit actuel de l'UART, 115200 en sortie d'usine.
Baud List (AT+IPR=?) : renvoie deux listes — la première donne les débits auto-détectables, la seconde ceux réservés au mode fixe. Une fois ce bouton exécuté, le menu déroulant de Set Baud est remplacé par la liste réellement annoncée par l'exemplaire. Mesure locale : la seconde liste monte jusqu'à 1000000 bps — valeur absente du tableau du §3.4 du manuel.

Set Baud (AT+IPR={rate};&W, carte de paramètres) : l'appui ouvre d'abord une boîte de confirmation — c'est le bouton de la page avec lequel il est le plus facile de s'enfermer dehors.

Le triple piège du changement de débit (intégralement confirmé par mesure) :
① Dès que OK revient, le changement est immédiat : l'instant d'après, cet outil et le module ne parlent plus la même langue ;
② AT&F (réinitialisation d'usine) ne remet pas le débit d'origine — n'espérez pas qu'il vous sauve ;
③ Sans &W, rien n'est enregistré — or reconnexion = coupure de courant : le module se réveillerait à l'ancien débit alors que votre port resterait réglé sur le nouveau, double perte de contact. C'est pourquoi cet outil impose la forme combinée ;&W.
Récupération en quatre étapes (rappelées aussi dans la boîte de confirmation) : déconnecter → changer le débit dans la zone de connexion → reconnecter → refaire le rituel de démarrage.

Power : basse consommation QSCLK

Sleep? (AT+QSCLK?) : interroge si le module a le droit de s'endormir. Mesuré ici : 0 en sortie d'usine = désactivé, module toujours éveillé. Cette page ne propose que le bouton d'interrogation : un module endormi cesse de répondre aux commandes AT, et la méthode de réveil du manuel est d'abaisser DTR — or sur cette carte, DTR est déjà câblé sur la broche Reset (voir le début de cette section). Si vous avez activé le sommeil depuis la ligne de commande et que le module ne se réveille plus, refaites le rituel de démarrage (coupure puis remise sous tension) pour vous en sortir ; détails dans la note d'application officielle sur la basse consommation.

URC : quand aucun message n'arrive, venez ici en premier

Un URC (Unsolicited Result Code, code de résultat non sollicité) est un message que le module « émet spontanément, sans qu'on le lui demande », et non la réponse à une commande — le RDY du démarrage, l'arrivée de données TCP, les messages MQTT, les résultats de scan Wi-Fi, la notification de chargement du firmware GNSS en sont tous. Son port de sortie est par défaut le port USB (usbat) — cet outil, qui passe par l'UART, n'en reçoit alors aucun ; le symptôme est très typique : toutes les commandes répondent OK, mais les messages ne viennent jamais.

BoutonCommandeUsage

Boutons d'octets bruts : l'issue de secours du mode données

Beaucoup de commandes sont en deux temps : on envoie la commande, on attend l'invite > du module, puis on envoie le corps. Une fois entré dans ce mode données, le module avale comme données chaque caractère que vous tapez — y compris les commandes AT que vous voudriez lancer. Longueur mal calculée, changement d'avis en cours de route, commande bloquée : les touches ordinaires ne peuvent plus rien, il faut cette rangée de boutons qui envoient chacun un octet brut :

BoutonEnvoieQuand l'utiliser
Ctrl+Z0x1A Terminateur du mode données : expédie réellement le contenu accumulé
ESC0x1B Annule le mode données et jette le contenu accumulé. Touche d'évasion de premier choix quand une commande en deux temps est bloquée et que le port AT ne répond plus (§2.3.8 du manuel)
+++Trois signes + (octets bruts) Pour s'échapper du mode données transparent (par ex. un transfert FTP en COM:) et revenir en mode AT. La règle est stricte : 1 seconde de silence avant et après, jamais de CR/LF — mesuré : avec un CR ajouté, la séquence est sans effet ; il faut passer par ce bouton, pas par la ligne de commande
La mesure contredit le manuel : +++ est un « abandon », pas une « pause ». La note d'application FTPS v1.5, page 13, affirme qu'après +++ on peut reprendre le transfert en mode données avec ATO ; sur le matériel réel, ATO ne renvoie que NO CARRIER : le transfert a déjà été abandonné. Considérez +++ comme un frein d'urgence, sans espérer repartir une fois arrêté.

Dépannage

SymptômeCause et solution
Aucune commande ne répond Examinez les trois suspects dans l'ordre : ① le rituel de démarrage n'a pas été fait (après un rechargement de page, c'est forcément lui) ; ② la fin de ligne est réglée sur LF — le module n'accepte que CR, avec LF il ne répond strictement rien ; ③ le débit ne correspond pas (voir la récupération en quatre étapes)
Reset pressé mais RDY n'arrive jamais Regardez d'abord si le bouton Power est allumé — module hors tension, Reset peut être pressé cent fois sans effet ; à la première connexion, l'alimentation doit passer par ON→OFF
Toutes les commandes répondent OK, mais les URC ne viennent jamais Neuf fois sur dix, urcport est resté sur l'usbat d'usine : interrogez avec URC Port?, corrigez avec URC → UART ; sinon, vérifiez l'interrupteur général URC Switch
Le port AT « avale » soudain les commandes, plus rien ne répond Vous êtes coincé en mode données : tout ce que vous tapez est absorbé comme données — appuyez sur ESC pour vous en sortir
